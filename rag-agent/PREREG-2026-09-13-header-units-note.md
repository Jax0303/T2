# 사전등록 — 헤더 행 추정 규칙 v2 (2026-09-13)

**결과를 보고 방법을 고치는 개입이다.** 그래서 규칙·검증 지표·예측을 측정 전에 박고,
수정 전(v1)과 수정 후(v2) 수치를 **둘 다** 싣는다. v1 은 기본값으로 남아 이전 결과가
전부 그대로 재현된다(`--header-rule v1`).

## 무엇이 드러났나 (MultiHiertt 첫 답변 레그에서)

`guess_n_header_rows` 의 blank-corner 경로는 왼쪽 칸에 글자가 있는 첫 행을 데이터로
본다. 예외는 **괄호로 완전히 감싼** 단위 표기(`(in millions)`)뿐이다. 그래서

    |                     | Amount |      |      |
    | Dollars in millions | 2010   | 2009 | 2008 |   ← 헤더인데 데이터로 읽힘

에서 연도 행이 데이터가 되고, 셀 문장에서 연도가 사라진다
(`Franchised revenues: > Total > Amount: $7,842` 와 `… $7,286` 이 같은 경로).

실측(train 11,793표, v1): 같은 표 안에서 경로가 같고 값이 다른 셀 **21.9%**
(데이터셋 MT2Net 문장은 6.8%), 데이터셋 헤더에 연도가 있는 셀 중 우리 경로에서
그 연도가 빠진 셀 **10.0%**. 첫 '데이터' 행이 연도 행인 표 513개(4.4%), 그 행의 왼쪽
칸 상위: `$ in millions` 66, `in millions of dollars` 43, `in millions` 28, `pnc pension plan` 21,
`years ended december ##,` 18 …

## 규칙 v2 (blank-corner 경로에만, 둘 다 적용)

- **R1 — 괄호 없는 단위 표기도 단위 표기다.** 왼쪽 칸 글이 60자 이하이고
  `in (thousands|millions|billions)` 를 단어로 담으면 헤더 블록 안의 표기로 본다.
  기존 괄호 규칙의 일관성 수정이다.
- **R2 — 연도 행은 헤더 행이다.** 왼쪽 칸을 뺀 비어 있지 않은 칸이 **전부** 네 자리
  연도(`looks_numeric` 가 이미 "연도는 데이터가 아니라 열 라벨"로 제외하는 그 패턴)면
  왼쪽 칸 글과 무관하게 헤더 블록을 잇는다. 숫자 비율 경로는 이미 연도를 데이터로 안
  세므로 손대지 않는다.

## 검증 지표 (검색 실행 전, 데이터셋 문장을 기준으로)

- **M1 경로 충돌률** (같은 표·같은 경로·다른 값인 셀 비율) — 낮을수록 좋다.
- **M2 연도 보존률** (데이터셋 헤더에 연도가 있는 셀 중 우리 경로에 그 연도가 있는 비율).
- **M3 데이터 셀 보존률** (데이터셋이 문장을 준 셀 중 우리가 데이터 영역으로 보는 비율).
  헤더를 **너무 길게** 잡는 과잉을 잡는 지표다.
- 질의 모집단(2,871건, 제외 사유별 개수)이 바뀌면 그대로 보고한다.

## 예측

1. M1 이 내려가고 M2 가 오른다.
2. M3 는 0.5pt 넘게 떨어지지 않는다. 떨어지면 v2 는 과잉이고 **채택하지 않는다.**
3. 검색 정확도(doc, ALL): v1 .8394 보다 오르지만, 데이터셋 헤더를 쓴 변형
   `mt2net_header_s3c` .8596 을 **넘지 않는다** — 고치는 것은 실패 유형의 일부다.
4. 답변 EM 은 조회 층에서 오른다. 산술 층은 리더 한계라 거의 안 움직인다.

## 범위

MultiHiertt(`scripts/mh_arms.py`, `scripts/answer_accuracy_mh.py`)에만 켠다. HiTab 수치는
데이터셋 헤더 트리를 쓰므로 이 함수와 무관하다. RealHiTBench·AIT-QA 의 과거 결과는
v1 로 재현되며 v2 로 다시 돌리지 않는다.

## 실행 규칙 (검색 실행 전에 정한다)

1. **같은 조건 원칙.** v2 표 파서는 본 방법만의 것이 아니다. 청킹·Huawei·RowCol·TableRAG
   단위도 같은 파서의 헤더 행 수·열 경로로 만들어지므로(`raw_lines` 의 헤더 블록,
   부분표 열 라벨, 열 이름), **표 파서를 쓰는 arm 전부를 v2 로 다시 잰다.**
   `mt2net_desc`·`mt2net_header_s3c` 는 데이터셋 문장을 쓰므로 텍스트가 바뀌지 않는다
   (좌표만 같이 옮겨지고 판정은 같다) — 재실행하지 않는다.
2. **짝지음.** 검색 표는 v1·v2 공통 질의(교집합)에서 비교한다. 답변은 v1 레그가 받은
   **같은 1,047개 질의 id** 로 고정한다(`--same-queries-as`). v2 레코드에 없는 id 는
   세어서 적는다.
3. 순서: 본 방법 검색 → 본 방법 답변 → gold(v2) → 나머지 arm 검색 → 나머지 arm 답변.

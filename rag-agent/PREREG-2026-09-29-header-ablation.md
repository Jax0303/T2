# 사전등록: 헤더 경로 제거 ablation (MultiHiertt) — 2026-09-29, 실행 전

## 배경 (사용자 결정 2026-09-29)
주장을 "캡션 + 헤더 경로를 붙인 셀 문장"으로 바꾸고, 논문을 기(문제) → 승(기존 방법의 한계) → 전(제안) → 결(증명) 순으로 짠다.
문제 정의("표를 펴면 셀 값이 무엇의 값인지 사라진다")를 직접 검증하는 실험이 MultiHiertt 최종 규칙으로는 없었다.
MultiHiertt 에는 데이터셋 캡션이 없으므로 이 실험은 **헤더 경로**의 기여만 잰다.

## 조건
- 본 방법(기존): 셀 문장 = 행 경로 + 열 경로 + 값(s3c, 머리글 최종 규칙 v3.3u). 검색 `retrieval_r100/mh_train_s3c`, 답변 `cap300_20260924/cell_uniq`(882 중 408).
- 헤더 제거(새): **색인 텍스트(dense·BM25 둘 다)만 셀 값**으로 바꾼다(`mh_arms.py --cell-text value`).
  답변 생성 모델에 주는 입력은 검색된 셀의 본 방법 문장 그대로다 → 검색 차이만 답변에 반영된다.
- 나머지 전부 동일: train 2,885 문항(답변은 같은 882), 문서 안 검색, bge-base-en-v1.5, hybrid α=0.7, 상위 20셀,
  순위 100 저장, Qwen3-8B 4bit 비생각·cot·384토큰·greedy·seed 42·batch 128, 공식 EM(주)·DocMath(보조).

## 지표와 판정
- 검색: 상위 20셀에 정답 셀 전부가 든 문항 비율(2,885·882), Recall@k·Precision@k(k=1,5,10,20)·MRR(rpm.py 정의).
- 답변: 882 공식 EM. 본 방법 대 헤더 제거 McNemar 정확(같은 문항).
- 예측(결과 전):
  1. 882 에서 상위 20셀 검색 성공이 본 방법(790/882)보다 20%p 이상 낮다.
  2. 882 답변 EM 이 본 방법(408)보다 낮고 McNemar p < .05.
  3. Recall@1 이 본 방법보다 낮다.

## 이미 본 것 (공개)
- "기" 단계 측정(사후, 기술 통계): LangChain 1,000자 청크에서 정답 셀이 든 청크에 그 표의 머리글 줄이 없는 비율 —
  2,885 문항 중 339(11.8%), 882 중 116(13.2%). 116 문항 답변: 청크 39, 본 방법 61. 나머지 766: 청크 259, 본 방법 347.
  판정 기준: 정답 셀을 담은 청크 중 어느 것도 그 표의 첫 데이터 행 셀을 담지 않으면 "머리글 없음"(행 머리글 분리는 세지 않음, 하한).
- 헤더 제거 조건의 결과는 아무것도 보지 않았다.

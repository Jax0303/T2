# 사전등록: 생성된 값을 문맥 셀 값으로 스냅한다 (2026-09-10)

## 동기

`results/cell_id_v2/GOLD_FAILURE_SOURCE.md` — 노이즈를 전부 없앤 gold 조건에서도
남는 오답 43건 중 **순수 환각은 16건뿐**이고, 나머지는 값의 출처가 문맥이다:

    A 표기만 다름 (모델이 맞음)                  4
    B 문맥 안의 다른 숫자를 집음 (제목·헤더)       2
    C 셀 값을 변환함 (100-x 8, x100 7, x1000 1,
                     ÷1000 1, 부호 1)          18
    D 숫자를 안 냄 (문자열 부분만)                3
    E 문맥에 없는 숫자 — 생성                    16

B·C·D 는 **정답 값이 문맥에 멀쩡히 있는데 그대로 옮기지 않은 것**이다.

실험 1(셀 ID 선택, `results/cell_id_v2/VERDICT.md`)은 같은 채널을 노려 값 생성 오류를
58 → 11 로 줄이는 데 성공했으나, 모델에게 "20개 중 골라"를 시켜 **셀 선택 오류를
139 → 255 로 늘려** 기각됐다(주지표 −.0838).

이 개입은 **모델의 일을 바꾸지 않는다.** 생성은 그대로 두고 파이프라인 뒤에 후처리를
한 단계 붙인다. 모델이 이미 낸 숫자가 후보를 좁히므로 선택 부담이 생기지 않는다.

## 개입이 들어가는 자리

    ① 색인 → ② 검색(셀 20개) → ③ 프롬프트 → ④ 생성 → **⑤ 스냅** → ⑥ 채점

⑤ 는 **시스템 안**이지 채점기 안이 아니다. gold 를 보지 않고 ④의 출력과 ②의 20줄만
본다. 그러므로 배포 가능하며 공식 EM 과 비교 가능성이 유지된다.
④까지의 산출물이 이미 파일에 있으므로 **GPU 재실행이 없다.**

## 규칙 (실행 전 고정)

문맥 20줄 각각의 저장값 `V = [v1..v20]` 은 실험 1에서 검증한 사전으로 얻는다
(`rag_agent/serialization/cell_id.py`, 권위/문법 두 경로 대조, test 31,492줄 ·
dev 33,380줄 전부 일치, 불일치 0). 제목·헤더 속 숫자는 값으로 뽑히지 않는다.

    0. 예측 문자열이 어떤 셀 값과 정규화 후 같으면 **그대로 둔다.** (항등 우선)
    1. 예측에서 숫자를 순서대로 뽑는다. 하나도 없으면 문자열 규칙(4)으로 간다.
    2. 각 숫자 p 마다, 아래 관계 중 하나로 p 를 만드는 셀 값 v 를 찾는다.
       허용 관계 — 이 일곱 개뿐이고 실행 전에 못 박는다:
           x100   ÷100   x1000   ÷1000   100-x   1-x   부호(-x)
    3. **후보가 정확히 하나일 때만** p 를 v 로 바꾼다. 0개거나 2개 이상이면
       그 숫자는 건드리지 않는다.
    4. 숫자가 없는 예측: 어떤 셀 값이 예측을 부분문자열로 포함하거나 그 역이고,
       **그런 셀이 정확히 하나**면 그 셀 값으로 바꾼다. 아니면 그대로 둔다.
    5. 예측 안의 숫자 중 **하나라도 바뀌면** 바뀐 것들로 예측을 재구성한다.
       원래 구분자(쉼표)를 유지한다. 숫자가 여럿이면 각각 위 규칙을 독립 적용한다.
    6. 스냅은 **한 번만** 적용한다. 연쇄하지 않는다.

값을 반올림하거나 단위를 붙이거나 비율을 바꾸지 않는다. 셀에 저장된 문자열 그대로 쓴다.

## 보고

  McNemar p, 95% paired bootstrap CI (B=10,000, seed=42).
- **스냅이 적용된 문항 수**와 그중 정답으로 바뀐 비율 / 오답으로 바뀐 비율.
- 데이터셀 1,245 · 헤더답 336 · 전체 1,581 별도.

# 사전등록: MultiHiertt 새 문항 600(882·dev 밖, 산술 셀 2개 이상 층)에서 채운 부분 표(D) 대 LangChain 청크(A), 3회 실행 (2026-10-19, 실행 전)

## 왜
- 882 에서 D 의 이득은 셀 2개 이상 문항에 몰렸다(다수결 산술 셀2+ 182 대 167, 조회 셀2+ 245 대 231; 셀 1개는 같음). 이것은 사후 관찰이다. HiTab 에서는 같은 성격의 가설(깊은 구조)을 새 문항 691 로 사전등록 확인했다(PREREG-2026-10-19-hitab-confirm.md, 충족). MultiHiertt 에서도 **새 문항**으로 "셀 2개 이상 문항에서 D > A"를 확인한다.
- 882·dev 밖에 검색 기록(상위 100)과 LangChain 청크 기록이 모두 있는 문항은 1,940건이고 그중 1,935건이 산술 셀2+ 층이다(조회 층·셀 1개 층은 전부 882·dev 에 들어가 새 문항이 없음). 따라서 확인은 **산술 셀2+ 층 한 층**에서만 하고, 셀 1개 층과의 상호작용은 새 문항으로 확인할 수 없음을 적는다.
- 표본: 산술 셀2+ 1,935 중 시드 42 로 600(선택 없음, `ids600.json`).

## 고정 조건
- 882 와 같은 입력 규칙: A = LangChain 4청크 원문(기존 `baselines/langchain_chunk` 기록, 1,000자/겹침 200/bge 상위 4), T = A 토큰 수; C = 셀 문장 순위대로 T 까지; D = 채운 부분 표 T 까지(`format_render.py`, 882 와 같은 코드). 입력 생성 `build_fresh.py`(실행 전 생성·커밋).
- Qwen3.5-4B bf16, vLLM greedy 비생각, P*(R1X1F1B2D1C1E0), 최대 4,096(`--max-model-len 8192`), 3회(동시 32/24/16). 채점 `score_formats2.py` 마지막 줄 + `score_rep.py` 다수결 McNemar. 스크립트 `run.sh`. 실행은 882 4,096 확인(run_882_cap4096.sh)이 끝난 뒤 GPU 가 비면 시작.

## 판정 규칙(결과 전 고정)
- 다수결 McNemar D 대 A p < .05 이고 세 실행 모두 D > A → "MultiHiertt 셀 2개 이상 산술 문항에서 D > A"를 쓴다(882 의 사후 관찰이 새 문항에서 재현). 아니면 우연 범위로 쓰고 882 의 층별 수치는 사후 관찰로만 남긴다.
- 보조: D 대 C, C 대 A. 선택 없음.

## 예측(확률; 실행 전 고정)
- 다수결 D − A ∈ [+10, +50]: 70%; D > A: 80%; **판정 충족: 55%**(882 산술 셀2+ 에서 +15/300 ≈ 5%p 였으므로 600 이면 +30 안팎, 불일치 비율이 같으면 p < .05 에 닿는다).
- 절대 수준: A 50~62%, D 54~66% 각 70%(산술 셀2+ 는 가장 어려운 층; 882 에서 A 55.7%, D 60.7%).
- C 대 A: C ≤ A 60%. D 대 C p < .05: 80%. 잘림 팔당 4~8%: 60%.
- 빗나가면 그대로 적는다.

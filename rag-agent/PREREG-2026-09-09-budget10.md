# 사전등록 — 예산 축소 k=20 → k=10 (조회 답변 레그)

작성 시각: 2026-09-09, **리더 실행 전**. 검색 레그(`t_s3c_k10_records.jsonl`)는
2026-09-08 에 이미 돌아 있고 이 문서는 그 위에 리더를 올리기 전에 쓴다.
사용자 결정: 규율은 **사전등록 1회 실행**(dev 반복 아님), 레버는 예산 축소.

## 1. 가설

`HANDOFF-2026-09-09-2.md` §3.1 과 `TABLES.md` 표 2d 가 같은 곳을 가리킨다:
조회 m=1 의 손실은 거의 전부 distractor 몫(−0.181)이고 리더 천장 몫은 −0.040 이다.
프롬프트 층 개입은 네 번 기각됐고(형식·근거셀·`rr10_3`·크로스인코더), 순위 개입도
기각됐다(§22.5). **문맥을 줄이는 일을 검색 층에서 하는 것**이 남은 하나다.

> H1. 배달 셀을 20 → 10 으로 줄이면 조회 m=1 주지표 EM 이 오른다.

## 2. 모집단과 조작 변인

- 주지표: **조회 m=1, n=991** (`analysis/accuracy_tables.py: primary_ids`).
- 조작 변인은 `budget_cells` 하나. 인코더 `BAAI/bge-base-en-v1.5`, α=0.7, 쿼리 접두어,
  색인 단위(셀+헤더경로), 리더 `Qwen2.5-7B-Instruct` 4bit, 프롬프트 `base`,
  `temperature=0.0`, `seed=42`, `max_tokens=64` 전부 k=20 실행과 동일.
- 짝지은 비교다 — 두 레그가 같은 991 건을 채점한다.

## 3. 실행 전에 이미 고정된 값 (리더와 무관)

| | k=20 (현행) | k=10 |
|---|---:|---:|
| 검색 정확도 (991) | 0.9142 | **0.8698** |
| 주지표 EM | 0.7164 | ? |
| Cond. EM (검색 성공분) | 0.7792 | ? |
| 검색 실패 질의 EM | 0.0471 | (0.0471 로 가정) |
| 리더 천장 = `gold`\|검색성공 | 0.9603 | 0.9603 |

**손익분기**: k=10 이 현행과 동률이 되는 Cond. EM = **0.8166**.
= (0.7164 − 0.1302 × 0.0471) / 0.8698. 즉 distractor 손실(0.9603 − 0.7792 = 0.1811)의
**21%** 를 벌면 이긴다.

## 4. 예측 (숫자를 먼저 박는다)

- Cond. EM = **0.82** [0.79, 0.85]
- 주지표 EM = **0.720** [0.694, 0.746]

근거: distractor 손실 181 건 중 141 건이 "문맥의 다른 셀 값을 그대로 읽은" 것이고,
그중 107 건이 gold 의 행·열 형제다. 경쟁 셀이 절반이 되면 그 몫의 일부가 회복된다고
본다. 다만 §22.5 가 "자리는 손잡이가 아니다"를 보였으므로 회복률을 절반 이상으로
잡지 않는다.

**점추정이 손익분기(0.8166)에 붙어 있다 — 예측대로면 아래 규칙에서 기각된다.**
그래도 돌리는 이유는 예측 구간이 손익분기를 가로지르기 때문이고, 검색이 이미
돌아 있어 판정 비용이 리더 한 번(≈20분)이기 때문이다.

## 5. 판정 규칙 (실행 후 바꾸지 않는다)

**채택** = 주지표 EM 의 Δ(k10 − k20) ≥ **+0.02** **그리고** 짝지은 정확 McNemar
p < 0.05. 둘 중 하나라도 못 채우면 **기각**한다 (§22.5 와 같은 연언 규칙).

- 부수 보고이지 판정 기준이 아닌 것: 데이터셀 전체(1,245), 산술(216), 조회 m≥2(38),
  Cond. EM, 평균 입력 토큰.
- **산술은 내려갈 것으로 예측한다** — 검색 정확도가 이미 0.7308 → 0.5641 로
  떨어져 있다(표 2d). 이 실험은 조회 전용 ablation 이며, 채택되더라도
  **표 1·표 2b 의 운영점(k=20)은 바꾸지 않는다.** k=10 은 표 2c 에 싣는다.

## 6. 기각되면 무엇을 배우나

문맥 층 개입이 전부 닫힌다 — 프롬프트 4회 + 순위 1회 + 예산 1회. 그러면 남는 것은
**어떤 셀이 배달되는가**(기성품 인코더 교체, §0.3 이 허용) 와 **리더 교체** 둘뿐이고,
조회 m=1 의 천장은 `oracle` 0.8819 로 못 박힌다. 0.9 는 검색 회수 개선 없이는
정의상 닿을 수 없다.

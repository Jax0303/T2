# 사전등록 2026-10-22 — self-consistency(표본 5개 다수결) dev 395, 세 입력, 1회

## 왜
- 검색·전달 축은 소진(상한·고르기·쪼개기 닫힘), 생각 모드는 사용자 거절. 남은 답변 단계 수단 중 같은 모델·같은 지시문에서 쓸 수 있는 표준 기법이 self-consistency(Wang 외 ICLR 2023: temperature 표본 여러 개의 최종 답 다수결)다. 세 입력에 똑같이 적용되므로 공정 비교 원칙 안이다. 비용은 출력 토큰 약 5배(입력 토큰 상한 T 는 불변).
- 정답 셀만 줘도 틀리는 882 문항 218 중 LLM 계산·해석 오류 94 — 이 부분을 겨냥한다. 사용자(10-22): "반드시 성과". 단 채택은 사용자 결정(답변 단계 조건 변경).
- 3회 실행 다수결을 정확도로 보고하는 것(10-20 금지)과 다르다: 여기서는 다수결이 **방법**이고, 그 방법의 정확도를 1회로 재며 greedy 1회 실행들과 비교한다.

## 고정 조건
- dev 395, 입력 A·D·Cp(sentence_dev 와 같은 레코드), 지시문 P*, 출력 4,096. 표본 5개, temperature 0.7, top_p 0.8, top_k 20(Qwen3 비생각 모드 공식 권장값), seed 42. 마지막 'Final answer' 줄 값(숫자 4 유효숫자·%·글자) 다수결, 동률은 먼저 나온 표본. 이긴 표본의 본문을 raw 로 두어 채점기는 그대로(`prompt_sweep.py --n-samples 5`).
- 기준 = greedy sentence_dev run1·run2(같은 입력·지시문). 비교 `results/sc_dev_20261022/compare.py`: 입력별 다수결 대 greedy 각 실행 McNemar, 5표본 전원 일치율, 출력 토큰.

## 판정 규칙
- **600 확인으로 진행**: 잘라낸 표에서 다수결 − greedy 2회 평균 ≥ +12(3%p) 이고 greedy 두 실행 모두에 대해 p<.05, 그리고 어느 입력도 −12 이하가 아님. 그러면 600·882 에 세 입력 모두 적용하는 사전등록을 따로 쓴다(채택 여부는 사용자).
- **효과 없음**: ±12 안 → 닫음. **해침**: −12 이하 → 닫음.

## 예측
- 잘라낸 표 +12 이상·유의: 40%. ±12 안: 40%. 해침: 20%. 세 입력 모두 같은 방향: 70%. 5표본 전원 일치 55~70%: 60%. 출력 토큰 4.5~5.5배: 80%.

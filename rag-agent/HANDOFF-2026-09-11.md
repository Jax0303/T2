## 다음 실행 순서

1. GPU 실행 환경을 준비하고 torch, sentence-transformers, FAISS, datasets를 설치한다.
   모델·tokenizer revision과 패키지 버전을 고정한다. `python -m pytest tests -q -ra`로
   환경 때문에 생략했던 테스트도 확인한다. MultiHiertt 데이터는 해당 테스트에 필요하다.
2. `EVALUATION-INTEGRITY-2026-09-11.md`의 명령으로 v2 검색 결과를 새 디렉터리에 생성한다.
   우선 S3c, RowCol 기본 Markdown/leaf, Huawei 문자 1000/200 조건을 실행한다.
   동일 corpus·encoder·query prefix·reader·prompt 조건을 유지한다.
   BGE 입력 초과는 기본 오류로 처리한다. 과거 절단 조건을 측정할 때만
   `--embed-overflow truncate`를 명시하고 절단 통계를 함께 보고한다.
   문자 1000과 토큰 1000은 별도 실험이며 결과를 혼합하지 않는다.
3. **수정된 RowCol을 포함해 각 arm의 답변을 새로 생성한다.**
   `scripts/answer_accuracy.py --records <새 records.jsonl> --prompt neutral --out <새 answers.jsonl>`.
   S3c gold 조건도 새로 생성한다. 기존 EM 파일을 새 문맥 결과로 재사용하지 않는다.
4. 실제 생성한 경로로 `analysis/comparison_manifest.v2.example.json`을 복사·작성한다.
   `python analysis/accuracy_tables.py --manifest <manifest.json> --out <report.md>`로 집계한다.
   전체 1,584 / 채점 1,581 / 주지표 991 / 제외 3을 확인한다.
   주지표는 mode=all, m=1, aggregation=none인 단일 셀 조회이다.
5. 검색 성공·답변 실패, 검색 실패·답변 성공의 교차표와 오류 표본을 검토한다.
   열 헤더 수정 전후의 EM 변화는 동일 질문·모델·생성 조건으로 별도 측정한다.
   셀 예산은 단위 전체 추가 후 중단하므로 실제 전달 셀 수와 초과 횟수도 보고한다.
6. 논문 표에서는 현재 arm을 ‘동일 검색기·reader 아래 표현 비교’로 명명한다.
   Huawei TableRAG, Google TableRAG, MT2Net 전체 재현이라고 표기하지 않는다.
   전체 시스템 비교를 추가할 경우 아래 별도 재현 단계로 진행한다.

## 전체 시스템 비교를 위한 별도 구현

- Huawei: 공개 commit 고정 후 Excel 숫자 렌더링·SQL 응답 처리 경로를 검증하고,
  BGE-M3·reranker·DB/SQL·질의 분해·반복 추론을 구현/연결한다.
  corpus 검색 시 알려진 정답 table_id를 질의에 넣는 원본 경로가 평가 조건에 적합한지 확인한다.
  원본 논문 설정과 공개 코드 설정의 차이는 별도 기록한다.
- Google: schema 이름 인덱스와 metadata, 별도 cell 검색, 질의 확장,
  전체 표를 읽는 PyReAct를 재현한다. HiTab 헤더 평탄화 방식과 접근 가능한 표 범위를 명시한다.
- MT2Net: 공식 table_description, 학습한 fact 검색기와 program/span reasoner가 필요하다.
  논문의 BERT-base와 공개 설정의 roberta-base 중 어느 조건인지 명시한다.
- MixRAG: H-RCL, 검색 결합, LLM reranker, RECAP이 없는 현재 상태는 미구현이다.

전체 시스템 비교는 데이터 접근 범위, 평가 방식, 모델 및 계산 예산을 명시해야 한다.
이번 검증에서는 GPU 답변 EM이나 원본 전체 파이프라인을 실행하지 않았다.
따라서 성능 향상 또는 원본 시스템 대비 우월성을 아직 주장할 수 없다.

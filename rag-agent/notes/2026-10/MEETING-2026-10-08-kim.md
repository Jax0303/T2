# 2026-10-08 세션 결론 + 김명호 교수 질문 대비 답변

## A. 이 세션(10-07~08)에서 얻은 결론

1. **문제 정의는 하나.** "표를 청크로 자르면 셀 값과 머리글이 같은 검색 단위에 있다는 보장이 없고, 머리글 없는 단위는 검색되지 않는다." 머리글 경로를 빼고 색인하면 정답 셀 포함 8.9%, 마지막 머리글만 78.2%, 경로 전체 86.3%(2,885문항, 우연 아님). 둘째 정의("불필요한 셀이 답을 떨어뜨린다")는 삭제.
2. **주장은 셋.** ① 셀 문장은 계층형 표에서 셀 단위 검색을 성립시킨다(확정). ② 머리글을 셀마다 붙인 표현은 짧은 답 지시문에서만 LLM 읽기에 유리하다(조건부). ③ 원방법끼리의 답변 수치는 보고만 하고 원인은 지시문이라고 밝힌다. "셀 문장이라서 답을 더 맞힌다"는 쓰지 않는다.
3. **지시문 × 검색 단위(882문항).** 같은 지시문(풀이 허용)이면 셀 문장 55.3% 대 청크 56.2%로 같다. LangChain 튜토리얼 지시문(세 문장 이내)에서만 46.1% 대 40.8%로 셀 문장이 높다(우연 아님). 표 4-7의 57.5 대 39.5 격차는 지시문 몫이다.
4. **답변 정확도를 정하는 것은 정답 셀이 입력에 있느냐 + LLM이 식을 세우느냐.** 정답 셀에 틀린 셀을 0·5·10·20·50개 섞어도 66.5% → 60~65%(우연 범위). 정답 셀을 담은 문항 62.4% 대 놓친 문항 18.2%. 정답 셀만 넣은 상한 66.5%.
5. **검색은 이 데이터셋 크기에서 답변을 올리지 않는다.** 문서의 셀 문장 전부(4,112토큰) 58.5% 대 20셀 57.5%. 1.7B 모델에서도 26.5% 대 26.0%. DocMath-Eval도 이 길이(표 4개, 2,216단어)는 문서 전체를 입력하고 검색은 25k 단어·표 46개에서만 쓴다. 검색의 가치는 입력 크기(700 대 1,400~4,100토큰).
6. **양자화·계산식 실행.** 1.7B bf16 대 4비트: 본 방법 26.0 → 22.5, LangChain 14.5 → 12.5(둘 다 우연 범위, 같은 방향). 답변 단계 계산식 실행은 산술 42 → 44로 효과 없고 조회를 떨어뜨림.
7. **큰 문서(표를 이어 붙임, 같은 지시문).** 표 4/20/101/162개에서 본 방법 57.5/52.0/47.5/46.5% 대 청크 55.5/44.5/37.5/41.5%. 표 101개에서 +10%p(우연 아님), 162개에서 +5%p(우연 범위). 정답 포함률은 청크 98.5 → 71%, 본 방법 89 → 77%로 101개부터 역전. 다른 보고서의 표를 붙인 합성 문서라 보조 결과. 외부 검증은 DocMath-Eval CompLong(결정 대기).
8. **8B 모델의 답변 수준은 낮지 않다.** DocMath-Eval MultiHiertt 파생 부분집합(문서 전체 입력): GPT-4o 64~66%, GPT-4-Turbo 53~61%, Qwen2-72B 45~49%, Llama-3-8B 25~29%, 사람 87%. 본 방법 산술 51.2%(문서 전체 입력), 전체 57.5%.
9. **결정(10-08).** 비교군 답변 지시문을 본 방법 지시문으로 통일한다(LangChain 55.5%, RAPTOR는 재실행 필요, Chen·Yu는 자기 파이프라인 그대로). 튜토리얼 지시문 결과는 원방법 보조 행. 2×2 결과를 본 뒤의 사후 결정임을 원고에 적는다. 비용 주장은 안 하되 "같은 정확도를 입력 1/2~1/6로"를 쓸지는 결정 대기.
10. **남은 일.** GPU: 1.7B Yu·RAPTOR, bge-m3 5방법, Yu 882(403/882), Chen 셋, RAPTOR 본 방법 지시문. 원고: 문제 정의(1.1·1.3·3.1), 같은 셀 수 표 복원, 3.3.4 k, 표기 53곳, 양자화 문단, 예시, 적용 조건, 2×2 표와 지시문 문장, 큰 문서 보조 절, 한계 2개, 단위당 셀 수 각주, 11.9 → 11.8%.

## B. 김명호 교수 질문 대비

### ① "이전 점수와 발표자료 점수(100.0 등)가 왜 다른가"
**답.** 지표 정의가 바뀌었습니다. 옛 표는 모든 방법을 셀 20개로 잘라 "그 안에 정답 셀이 다 있는 비율"을 쟀고, 새 표는 지시대로 표준 재현율@k, k = 검색 단위 수입니다. 청크 하나가 셀 37~46개라 청크 5개면 문서 전체가 되어 100%가 됩니다. 표본(2,908 → 2,885/200)과 머리글 규칙·비교군 구현(공식 코드)도 최종판으로 바뀌었습니다.

| | 옛 표 | 새 표 |
|---|---|---|
| 재는 것 | 셀 20개 안 정답 전부 포함 | 재현율@k, k = 검색 단위 수 |
| 청크 | 83.9%(단일조회) | R@1 76.8%, R@5 100% |
| 본 방법 | 94.8%(단일조회) | R@5 73.4%, R@20 93.9% |

**잇는 숫자.** 셀 수를 다시 같게 하면 46셀에서 본 방법 98.6% 대 청크 76.8%, 43셀에서 97.5% 대 Yu 82.8%. 셀 10개(87.0%)로도 청크 한 개보다 높습니다. 이 줄을 표 4-5 옆에 복원합니다.
**말하지 말 것.** 옛 표 숫자를 새 표 숫자와 나란히 비교하는 말(정의·표본·규칙이 다 다름).

### ② "k가 검색 단위 수면 R@1·P@1 결과만 LLM에 넘기면 되지 않나, 왜 @5·10·20을 넘기나"
**답.** 표의 @1·@5·@10·@20은 넘기는 설정이 아니라 검색 품질을 깊이별로 보는 표준 표기이고, LLM에는 방법마다 입력 하나만 넘깁니다(본 방법 셀 20개, LangChain 청크 4개, 원고 표 4-4). 20개인 이유는 둘입니다. 정답 셀이 문항당 평균 2.37개라 셀 1개로는 답을 만들 수 없고(R@1 상한 58.6%, P@1 58.5%는 상한과 같음), dev 332문항 답변이 1개 6.9% → 3개 31.9% → 5개 39.2% → 20개 45.8%, 10~75개는 차이가 없습니다. 20은 미리 정한 값이고 dev로 확인만 했습니다.
**말하지 말 것.** "P@5부터 우리가 높아서". 그 역전은 단위 크기 때문(청크는 문서에 4개뿐, 셀은 정답이 2.37개뿐)이라 근거로 쓰면 역공당합니다.

### ③ "LLM 2종·인코더 2종으로 강건성을 보여라"
**답.** 둘째 LLM Qwen3-1.7B(양자화 없음): 본 방법 26.0% 대 LangChain 14.5%(우연 아님). 셋째 LLM Llama-3.2-3B(다른 계열, 양자화 없음): 28.0% 대 9.5%(우연 아님). 둘 다 원방법 비교이며 순위가 유지됩니다. Yu는 Llama 3B 출력 형식을 못 받아 답 0건(정확도가 아니라 파이프라인 불일치). 인코더 bge-m3는 진행 중.
**정직하게 덧붙일 것.** 이 격차도 지시문 차이가 포함된 원방법 비교입니다. 같은 지시문 비교의 강건성(1.7B·Llama에서 청크 + 본 방법 지시문)은 각 10분으로 추가 실행 예정이고, 검색 쪽 강건성은 bge-m3 결과로 답합니다.

### 이어질 수 있는 질문
- "그럼 답변에서 뭐가 낫나" → 같은 지시문이면 같습니다. 낫는 것은 검색(같은 셀 수에서 정답 더 담음, 넘긴 셀 중 정답 10배)과 입력 크기이고, 문서가 커서 통째로 못 넣을 때는 답변도 앞섭니다(표 101개에서 +10%p).
- "정밀도가 10배인데 답변이 같은 이유" → LLM은 틀린 셀이 많아도 헷갈리지 않고(잡음 사다리), 정답이 들어 있느냐만 봅니다. 청크는 문서를 거의 다 보내 정답 포함률이 98.5%입니다.
- "지시문 바꾸면 LangChain도 되는데" → 맞습니다. 그래서 비교군 지시문을 통일하고 답변 우위는 주장하지 않습니다.
- "k=20 왜 10이 아닌가" → dev에서 10~75가 같아 어느 값이든 결과가 같고, 20은 사전에 정한 값입니다.

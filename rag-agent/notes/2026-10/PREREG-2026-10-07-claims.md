## 1. 지시문 × 단위 2×2, 882문항 (주장 ②)
| | 본 방법 지시문(cot) | LangChain 지시문(세 문장 이내) |
|---|---|---|
| 셀 문장 20개 | 있음 408/882 (200: 115) | **새** `cell_tutorial_prompt.py --ids cell_uniq.jsonl` (200: 92) |
| LangChain 청크 4개 | **새** `langchain_chunk.py --stage answer --prompt cot` (200: 없음) | 있음 882 (200: 79) |
- 새 칸의 입력은 기존 칸과 셀·청크가 바이트 단위로 같다(context_sha256 대조). 바뀌는 것은 지시문과 프롬프트 틀뿐
  (cot = system 지시문 + "Context/Question" 틀, 튜토리얼 = user 메시지 하나에 rlm/rag-prompt).
- 판정(주 비교 2개): 같은 지시문 안에서 셀 문장 대 청크 — cot 아래, 튜토리얼 아래. 둘 다 .05 에서 셀 문장이 높으면 주장 ②를
  본문에 쓴다. 한쪽만이면 "그 지시문에서는"으로 조건을 붙여 쓴다. 둘 다 아니면 ②는 수치만 둔다.
- 보고만: 지시문 효과(셀 문장 안, 청크 안), 조회/산술 갈래, 평균 입력 토큰.
- 예측: 셀 문장 > 청크가 두 지시문에서 모두 성립(200 에서 +13·미측정). 지시문 효과는 산술에 집중.

## 2. 작은 LLM에서 문서 전체 셀 문장 대 20셀 (검색의 조건부 가치)
- `answer_accuracy_mh.py --condition fullcells`를 Qwen3-1.7B bf16·Llama-3.2-3B bf16 으로 200문항(배치 1). 20셀 쪽은 1.7B 있음(52/200), Llama 는 l3_ours_answer(대기).
- 판정: 각 LLM 에서 문서 전체 대 20셀 McNemar. 20셀이 .05 에서 높으면 "LLM 이 작으면 셀 단위 검색이 정확도를 지킨다"를 조건부로 쓴다.
  차이가 없거나 전체가 높으면 검색의 답변 기여는 한계에 적는다. 8B 에서는 차이 없음(117 대 115)이 기준.
- 예측: 1.7B·3B 에서 전체 입력(평균 4,112토큰)이 20셀보다 낮다. Llama 3B 는 13k 토큰 입력에서 메모리 부족이 날 수 있다 — 나면 실패로 적고 1.7B 만 보고한다.

## 3. 같은 모델의 양자화 효과 (김영종 ③)
- Qwen3-1.7B 4비트(NF4)로 본 방법·LangChain 200문항. bf16 결과(52·29)와 같은 문항·같은 입력.
- 보고만(판정 아님): 방법별 bf16−4비트 차이와 b:c. 두 방법의 손실이 같은 방향·비슷한 크기면 "양자화는 방법 간 격차의 원인이 아니다"의 근거로 쓴다.
  8B 양자화 없음(5)은 임대 뒤.

## 4. 잡음 사다리·정답 위치 (주장 ① 보강, 김명호 ② 답변 쪽)
- 입력 = 정답 셀 문장(색인 문장 그대로) + 검색 순위의 비정답 셀 문장 N 개(hard negative, retrieval_r100 의 ranked_units 순).
  N ∈ {0, 5, 10, 20, 50}, 정답 위치 top. N=20 에서 정답 위치 mid·bottom 추가. 200문항, 8B.
- N=0 은 부록 D 정답 셀만(133)과 문장 생성 경로가 다르다(색인 문장 대 caption_sentence) — 둘 다 적는다.
- 판정 없음, 곡선 보고: N 별 정확도와 N=0 대비 b:c, 위치 3개의 b:c. "불필요한 셀이 답을 떨어뜨린다"는 N=0 대 N=20 이 .05 이면 그렇게 쓰고 아니면 안 쓴다.
- 예측: N=0 > N=5 ≈ N=10 ≈ N=20 ≈ N=50(계단식, 문서 전체 실험과 일치). 위치는 top ≥ mid ≈ bottom.

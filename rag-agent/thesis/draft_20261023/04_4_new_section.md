# 4장 추가 절 초안 — 4.4 전달 형식, 답변 상한, 리더 LLM, 오답 원인 (2026-10-23 초안; 비교군 재실행 결과【대기】는 PREREG-2026-10-23 결과로 채움)

> 전제: 4.1~4.3 은 10월 주 설정(882문항, Qwen3.5-4B bf16, 지시문 P*, 채운 부분 표)으로 교체된다. 이 절은 그 설정 안의 분석이다. 수치 출처는 각 사전등록 파일.

## 4.4.1 전달 형식 (PREREG-2026-10-18-D-vs-A-replication.md, PREREG-2026-10-19-882-cap4096.md, PREREG-2026-10-19-mh-confirm-arith.md, PREREG-2026-10-19-hitab-newregime.md)
검색된 상위 20개 셀을 LLM 에 전달하는 형식 세 가지를 같은 지시문(부록 B 의 P*)·같은 LLM 으로 비교하였다. C 셀 문장 목록(검색 단위 그대로), D 채운 부분 표(검색된 셀이 속한 표의 행·열을 되살려 부분 표로 표시), A LangChain 청크(비교군의 상위 4개 청크). vLLM 연속 묶음 실행은 실행마다 결과가 조금씩 달라(같은 조건 3회에서 팔당 ±4~9문항), 3회 실행해 문항마다 2회 이상 맞힘(다수결)으로 판정하였다.

| 전달 형식 | 출력 상한 3,072(3회 다수결) | 출력 상한 4,096(3회 다수결) |
|---|---|---|
| D 채운 부분 표 | 629 (71.3%) | 620 (70.3%) |
| C 셀 문장 목록 | 585 (66.3%) | 588 (66.7%) |
| A LangChain 청크 | 601 (68.1%) | 600 (68.0%) |
| D 대 A McNemar | b:c 71:43, p=.011 | 71:51, p=.085 |

같은 20개 셀을 부분 표로 되살려 전달하면 셀 문장 목록보다 3~4%p 높았고(두 상한 모두 p<.05), LangChain 청크보다는 3,072 에서 우연이 아니었으나 4,096 에서는 우연 범위였다(여섯 실행 모두 D > A). 새 문항 600 (PREREG-2026-10-19-mh-confirm-arith) 에서도 D 399(66.5%) 대 A 376(62.7%), 세 실행 모두 p<.05 로 재현되었다. HiTab 300문항(단일 표, 부록 C 설정)에서는 D 257(85.7%) 대 A 247(82.3%), p=.17 로 우연 범위였다. 이득은 정답 셀이 2개 이상인 문항에 몰렸다(882: 조회 셀2+ +16, 산술 셀2+ +7~15; 셀 1개 문항은 같음).

## 4.4.2 답변 정확도의 상한 — 정답 셀만 입력 (PREREG-2026-10-19-delivery-ceiling.md, PREREG-2026-10-21-ceiling-600.md)
검색이 완벽하다고 가정했을 때의 상한을 재기 위해 데이터셋이 근거로 표시한 정답 셀만 같은 형식·지시문으로 입력하였다(1회 실행).

| 입력 | 882 맞힘 | % | 새 문항 600 |
|---|---|---|---|
| 정답 셀만(O1) | 664 | 75.3 | 475 (79.2%) |
| 정답 표 전체(O2) | 645 | 73.1 | — |
| 정답 표 안으로 제한한 D(O3) | 651 | 73.8 | 419 (69.8%) |
| D 채운 부분 표(실제 검색) | 629 | 71.3 | 399.7 (66.6%) |

정답 셀만 주어도 75.3%에 그친다. 즉 실제 검색 결과(71.3%)와 상한의 차이는 4%p 이고, 검색·전달 단계에서 더 줄일 수 있는 손실은 그 안이다. 남은 25%의 원인은 4.4.4 에서 분류한다.

## 4.4.3 리더 LLM 에 따른 답변 정확도 (PREREG-2026-10-22-reader-sweep.md)
같은 882문항, 같은 두 입력(D 채운 부분 표, O1 정답 셀만), 같은 지시문 P*, 같은 출력 상한 4,096 에서 리더만 바꾸었다. 로컬 모델은 bf16 무양자화, 외부 모델은 OpenAI API(temperature 0, seed 없음)이다.

| 리더 | 크기·구동 | D 채운 부분 표 | O1 정답 셀만 | 데이터 쪽 100문항(O1) | 출력 토큰(D) |
|---|---|---|---|---|---|
| Qwen3.5-4B (본 논문) | 4B, 로컬 bf16 | 620 (70.3%)† | 664 (75.3%) | 0 (정의상) | 579 |
| GPT-4o (gpt-4o-2024-08-06) | 외부 API | 626 (71.0%) | 662·665 (75.1·75.4%) | 10 (10%) | 151 |
| Qwen3-4B-Instruct-2507 | 4B, 로컬 bf16 | 565 (64.1%) | 579 (65.6%) | 5 (5%) | 438 |
| Phi-4-mini-instruct | 3.8B, 로컬 bf16 | 286 (32.4%) | 400 (45.4%) | 14 (14%) | 73 |

† 3회 다수결. GPT-4o 대 Qwen3.5-4B: D 에서 b:c 69:63, p=.66; O1 에서 42:44, p=.91 — 같은 입력·같은 지시문에서 외부 상용 모델과 로컬 4B 모델의 정확도는 구별되지 않았다. 둘 다 틀린 문항이 193개로 각 모델 오답의 약 4분의 3이 겹친다. 반면 같은 회사의 전 세대 4B 모델은 두 입력 모두 6~10%p 낮았고(p<.001), 다른 계열 3.8B 모델은 풀이를 거의 쓰지 않아 크게 낮았다. 즉 리더에 따른 차이는 실제로 크지만, 본 논문의 수준(70%대)은 모델 크기의 한계가 아니다.

외부 모델 사용 시 관찰된 것: 같은 882문항을 같은 조건으로 두 번 호출하면 출력 문자열이 같은 문항은 270개(30.6%)뿐이었고 정오가 뒤집힌 문항은 29개(3.3%)였다. 응답 메타데이터의 백엔드 식별자(system_fingerprint)는 한 실행 안에서 4종, 두 실행에서 6종이 섞였다. 실행 중 프로젝트 지출 한도로 한 차례 중단되었다. 로컬 모델을 한 건씩 greedy 로 두 번 돌리면 50문항의 출력이 글자 단위로 같았다(vLLM 묶음 실행과는 26/50 만 같으나 정확도는 같음). 882문항을 네 조건으로 외부에 보내는 데 입력 토큰 310만 개(문서 표 내용 포함)가 전송되었다(1장).

## 4.4.4 정답 셀만 주어도 틀리는 문항의 원인 (PREREG-2026-10-19-delivery-ceiling.md 사후 분류, PREREG-2026-10-22-reader-sweep.md)
O1 조건에서 Qwen3.5-4B 가 틀린 218문항을 사람이 전부 읽고 분류하였다(한 사람 판정, 사후).

| 원인 | 문항 | 비율 |
|---|---|---|
| L LLM 의 해석·계산 오류 | 94 | 43% |
| A 데이터셋의 정답 셀 표시가 계산에 필요한 셀을 다 담지 않음 | 56 | 26% |
| D 데이터셋 정답 규칙·정답 오류 | 44 | 20% |
| F 채점 형식·반올림 | 14 | 6% |
| T 출력 잘림 | 10 | 5% |

A·D 의 100문항은 모델이 아니라 문항 쪽 문제라는 판정을 다른 리더로 확인하였다: 같은 100문항을 정답 셀만 주었을 때 GPT-4o 10%, Qwen3-4B-2507 5%, Phi-4-mini 14% 만 맞혔다(모두 50% 미만, 사전등록 규칙 충족). 따라서 정답 셀만 주어도 틀리는 218문항 가운데 100문항(882 의 11.3%p)은 모델을 바꾸어도 회복되지 않는 데이터 쪽 몫이고, 나머지 118문항(13.4%p)이 모델 쪽 몫이다. 자동 규칙으로 만든 분류는 잘림과 형식만 잡아내고 데이터 쪽과 모델 쪽을 구분하지 못하였으므로(사람 판정 218건과 대조), 분류는 사람 판정에 의존한다. 이 100문항을 뺀 수치는 제시하지 않는다 — 본 논문 리더의 오답에서 뽑은 집합이라 그 리더에게 유리하게 치우치기 때문이다.

## 4.4.5 지시문 (PREREG-2026-10-15-prompt-sweep.md, PREREG-2026-10-22-multiprompt-600b.md) — 한계로 적을 것
지시문 P* 는 검증 집합 395문항에서 147개 변형 가운데 고른 것이다(882 는 선택에 쓰지 않음). 같은 입력에서 LangChain 튜토리얼 원문 지시문은 Qwen3.5-4B 에서 56.6~58.8% 였고 P* 는 78.8~80.2%(1,536 토큰 상한)로, 지시문 효과가 전달 형식 효과보다 훨씬 크다. 새 문항 600b 에서 지시문 4개로 D 대 A 를 다시 재면 네 지시문 12쌍 중 11쌍에서 D 가 높았으나 유의한 것은 원문 지시문의 2쌍뿐이었다 — D 의 이득은 "P* 에 한정된 결과"로 쓴다.

# Abstract

In a hierarchical table, the meaning of a cell value is fixed by a combination of multi-level row and column headers. When a table is flattened or split into rows or chunks for retrieval, cells are separated from their headers, so both the retriever and the reader lose track of what a value refers to. In a closed environment that uses only local models and no external APIs, we propose a cell retrieval method that writes one sentence per cell, containing a unique label, the row header path, the column header path and the value, and indexes these sentences with an off-the-shelf embedding model without training.

On HiTab and MultiHiertt, we compare the method with a re-implementation of TableRAG's cell retrieval and that paper's baselines (RowCol, RandRow), a heterogeneous-document chunking scheme and fixed-length chunks under the same embedding model, retriever and cell-budget rule (20 cells). Cell-level retrieval puts all gold cells into the context more often than these baselines on both datasets (.9142 on HiTab with all 538 tables in one index, Table 5-3; .8634 on MultiHiertt). On HiTab, adding the dataset-provided table title as the label significantly improves retrieval, while the sentence template itself has no effect. On MultiHiertt, when header inference missed a level and several cell sentences became identical, the reader could not tell the values apart; fixing the header rule recovered these questions. With the header rule matched, answer accuracy is higher than with fixed chunks (HiTab 237 vs 206 of 300 (template chosen after seeing results on the same sample), Holm p=.0019; MultiHiertt 408 vs 368 of 882, p=.0052); on questions where both methods retrieved all gold cells there is no difference (HiTab 29:20, p=.25; MultiHiertt 59:62, p=.86), so the answer difference comes from questions where only one method retrieved them. Answer accuracy is not significantly different from giving the reader the whole table.

Keywords: hierarchical tables, table question answering, retrieval-augmented generation, cell retrieval, header paths

# Abstract

In a hierarchical table, the meaning of a cell value is fixed by a combination of multi-level row and column headers. When a table is flattened or split into rows or chunks for retrieval, cells are separated from their headers, so both the retriever and the reader lose track of what a value refers to. In a closed environment that uses only local models and no external APIs, we propose a cell retrieval method that writes one sentence per cell, containing a unique label, the row header path, the column header path and the value, and indexes these sentences with an off-the-shelf embedding model without training.

On HiTab and MultiHiertt, we compare the method with the representations of TableRAG, a heterogeneous-document chunking scheme and fixed-length chunks under the same embedding model, retriever and cell budget (20 cells). Retrieval accuracy is .9586 on HiTab single-cell lookup and .8638 on MultiHiertt overall, higher than every baseline (tied with fixed chunks on HiTab arithmetic). On HiTab, adding the dataset-provided table title as the label significantly improves retrieval, while the sentence template itself has no effect. On MultiHiertt, when header inference missed a level and several cell sentences became identical, the reader could not tell the values apart; fixing the header rule recovered these questions. Answer accuracy is the highest among retrieval methods on both datasets (HiTab .7500, MultiHiertt weighted .3375), but not significantly different from giving the reader the whole table.

Keywords: hierarchical tables, table question answering, retrieval-augmented generation, cell retrieval, header paths

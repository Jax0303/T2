# 제7장 결론

본 연구는 외부 API 없이 로컬 모델만 쓰는 폐쇄된 환경에서, 계층형 표의 셀을 질문에 맞게 찾아 리더에 넘기는 방법을 제안했다. 제안 방법은 셀마다 고유 라벨, 행 머리글 경로, 열 머리글 경로, 값을 담은 문장을 만들고, 그 문장을 학습하지 않은 기성 임베딩 모델과 BM25로 색인해 질문과 짝지어진 표·문서 안에서 상위 20개 셀을 고른다.

두 계층형 표 데이터셋에서 같은 임베딩 모델, 같은 검색기, 같은 셀 예산으로 비교한 결과는 다음과 같다.

1. **검색 정확도.** 본 방법은 HiTab 단일 셀 조회에서 .9586, MultiHiertt 전체에서 .8638로, TableRAG(Chen)의 표현들과 그 비교군, TableRAG(Yu) 청크, 고정 청크보다 높았다. 예외는 HiTab 산술로, 고정 청크와 차이가 없었다.
2. **고유 라벨.** HiTab에서 데이터셋이 준 표 제목을 라벨로 넣으면 검색 정확도가 유의하게 올랐고, 문장 틀만 바꾸는 것은 효과가 없었다. MultiHiertt에서 표 직전 문단을 라벨로 쓰면 오히려 떨어졌다. 라벨의 효과는 데이터셋이 준 표 제목의 내용에서 나온다.
3. **셀 문장의 고유성.** 머리글 추정이 한 층을 놓쳐 셀 문장이 값만 빼고 같아지면, 정답 셀을 검색하고도 리더가 값을 구별하지 못해 틀렸다. 머리글 규칙을 고치자 이 문항들의 답변 정확도가 회복되었다. 셀 문장 방법은 셀마다 문장이 달라야 작동한다.
4. **답변 정확도.** 본 방법은 두 데이터셋 모두에서 검색 방법 중 답변 정확도가 가장 높았으나, 검색 없이 표 전체를 넣는 조건과는 유의한 차이가 없었다. MultiHiertt 산술에서는 정보를 모두 주어도 답변 정확도가 낮아, 병목이 리더의 계산에 있다.

남은 과제는 다음과 같다. 첫째, MultiHiertt의 주 조건은 같은 882건의 결과를 본 뒤 바꾼 것이므로, 겹치지 않는 문항으로 다시 확인해야 한다. 둘째, 문장 고유화의 상당 부분이 질문이 부를 수 없는 위치·표 번호에 기대고 있어, 표 안의 글이나 주변 문단에서 의미 있는 구별 정보를 찾는 방법이 필요하다. HiTab에도 같은 표 안에서 문장이 같은 셀이 3.2% 있어 같은 점검이 필요하다. 셋째, 정답 근거 주석이 조건 판정 셀을 빠뜨리는 문항에서는 검색 정확도가 실제 필요한 정보를 과대평가하므로, 조건 셀까지 포함한 평가가 필요하다. 넷째, 산술 질문에서는 검색보다 리더의 계산 능력을 높이는 방법(생각 모드, 계산 도구)이 답변 정확도에 더 큰 영향을 줄 것으로 보인다.

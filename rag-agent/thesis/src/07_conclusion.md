# 제 5 장 결론

본 논문에서는 계층형 표가 여러 개 포함된 문서에 대한 검색 증강 생성에서 질문에 필요한 셀을 찾아 LLM에 전달하기 위해 셀 문장 기반 검색 증강 생성 방법을 설계하고 구현하였다. 기존의 검색 증강 생성은 표를 텍스트로 펼친 뒤 일정한 길이의 청크로 잘라 색인한다. 그러나 계층형 표를 청크로 자르면 열 머리글이 표의 맨 위 몇 줄에만 남으므로, 청크 경계 아래의 셀 값은 그 값이 무엇의 값인지를 알려 주는 머리글과 분리된다. MultiHiertt 평가 문항 2,885개 가운데 11.8%에서 정답 셀이 열 머리글 줄이 없는 청크에만 들어 있었다. 이처럼 셀 값과 머리글이 분리되면 검색기는 질문이 가리키는 셀을 찾기 어렵고, LLM은 검색된 값의 의미를 해석할 수 없으므로, 본 논문은 셀마다 머리글을 함께 담는 검색 단위에 초점을 둔다.

본 논문에서 제안한 방법의 전체 동작 과정은 다음과 같다. 먼저 문서의 각 표에서 머리글 행과 머리글 열을 판정하고, 데이터 셀마다 행 머리글 경로와 열 머리글 경로를 구성한다. 그리고 문서 안에 경로가 같은 셀이 남지 않도록 경로를 늘린 뒤, 셀마다 캡션, 행 경로, 열 경로, 셀 값을 담은 셀 문장을 만든다. 셀 문장은 공개 임베딩 모델로 벡터화하고 BM25 색인과 함께 저장한다. 그러고 나서 질문이 주어지면 질문이 속한 문서 안에서 코사인 유사도와 BM25 점수를 가중합한 하이브리드 점수로 셀 문장의 순위를 매기고, 상위 20개 셀 문장을 LLM의 입력으로 전달하여 답을 생성한다. 제안하는 방법은 임베딩 모델과 LLM을 학습하지 않으며, 외부 API 없이 로컬 환경에서 동작한다.

제안하는 방법의 성능을 평가하기 위해 MultiHiertt 데이터셋에서 셀 문장의 머리글 경로를 제거한 조건과 비교하였고, LangChain 튜토리얼 청크, RAPTOR, 두 가지 TableRAG를 같은 LLM과 같은 임베딩 모델로 실행하여 검색 성능과 답변 정확도를 비교하였다. 실험을 통해 셀 문장에서 머리글 경로를 제거하면 882문항의 검색 성공률이 89.6%에서 13.3%로, 답변 정확도가 46.3%에서 16.2%로 떨어지는 것을 확인하였다. 그리고 제안하는 방법의 답변 정확도는 문항 그룹별로 최대 300문항씩 뽑은 882문항에서 46.3%로 LangChain 청크의 33.8%보다 12.5%p 높았고, 200문항에서 46.5%로 LangChain 청크, RAPTOR, TableRAG(Chen)보다 유의하게 높았으며, TableRAG(Yu)의 40.5%보다는 높았으나 그 차이는 유의하지 않았다. 제안하는 방법의 LLM 입력은 평균 694토큰으로, 문서의 표 전체를 넣는 경우의 1,505토큰의 절반 이하이면서 더 높은 정확도를 보였다. 또한 표마다 제목이 주어지는 HiTab에서는 셀 문장에 캡션을 붙이면 표 538개를 한 색인에 넣은 검색의 성공률이 81.2%에서 91.4%로 올랐다.

본 연구의 한계는 다음과 같다. 첫째, MultiHiertt의 공개 평가 집합에는 정답이 없어 학습 집합에서 평가 집합을 구성하였으며, 머리글 판정 규칙은 이 집합의 표를 보고 정하였다. 둘째, 기존 방법 비교군은 각 방법의 원래 지시문을 사용하므로, 비교군과의 답변 정확도 차이에는 검색 단위와 함께 지시문의 차이가 섞여 있다. 셋째, LLM을 여러 번 호출하는 비교군은 실행 시간의 제약으로 200문항에서만 평가하였다. 넷째, 산술 문항의 답변 정확도는 공식 근거 셀만 입력하여도 40% 안팎에 그쳤으나, 공식 근거 셀에 필요한 값이 모두 표시되지 않은 문항이 있고 오류 유형별 건수를 세지 않았으므로, 정보 부족·계산 오류·표기 차이의 기여를 가르지 못하였다.

향후 연구로는 표 제목이 없는 문서에서 표를 구별하는 정보를 본문에서 찾아 셀 문장에 더하는 방법과, 산술 문항에서 LLM의 계산 오류를 줄이기 위해 계산 도구를 결합하는 방법을 연구할 계획이다.

# 제 4 장 실험 및 평가

본 장에서는 제안하는 셀 문장 기반 검색 증강 생성 방법을 평가하기 위해 사용한 실험 환경과 실험 방법을 설명한다. 그리고 셀 문장에서 머리글 경로를 제거한 조건, 기존의 검색 증강 생성 방법들과 제안하는 방법의 검색 성능과 답변 정확도를 비교하고 분석한다.

## 4.1 실험 환경

### 4.1.1 하드웨어 및 소프트웨어 환경

모든 실험은 GPU 한 장을 장착한 컴퓨터 한 대의 로컬 환경에서 수행하였으며, 외부 API는 사용하지 않았다. [표 4-1]은 하드웨어 및 소프트웨어 실험 환경이고, [표 4-2]는 실험에 사용한 모델을 정리한 것이다.

표 4-1. 하드웨어 및 소프트웨어 실험 환경

| 항목 | 내용 |
|---|---|
| CPU | Intel Core i5-12400F |
| GPU | NVIDIA GeForce RTX 3060 Ti (8GB) |
| 메모리 | 8GB (WSL2 할당) |
| 운영체제 | Ubuntu 24.04.4 LTS (WSL2) |
| 언어 | Python 3.12.3 |
| 라이브러리 | PyTorch 2.12.1 (CUDA 13.0), transformers 5.12.1, sentence-transformers 5.6.0, bitsandbytes 0.50.1 |

표 4-2. 실험에 사용한 모델

### 4.1.2 데이터셋

MultiHiertt[11]는 문서 2,513개와 문항 10,440개로 구성되며, 문항은 학습 7,830개, 검증 1,044개, 평가 1,566개로 나뉜다. 각 문항에는 정답과 함께 답에 필요한 표의 셀(table evidence)과 본문 문장(text evidence)이 근거로 표시되어 있고, 수치 계산이 필요한 문항에는 계산 과정도 표시되어 있다. 원 논문에 따르면 본문만 필요한 문항이 10.24%, 표 하나만 필요한 문항이 33.09%, 여러 표가 필요한 문항이 7.93%, 표와 본문이 모두 필요한 문항이 48.74%이다.

MultiHiertt의 공개 평가 집합에는 질문만 있고 정답과 근거 셀이 포함되어 있지 않아 검색 성능을 측정할 수 없다. 따라서 본 논문에서는 정답과 근거 셀이 제공되는 학습 집합에서 평가 집합을 구성한다. 제안하는 방법과 비교군은 모두 학습 과정이 없으므로, 학습 집합을 평가에 사용하여도 시스템이 그 문항을 미리 학습한 것이 아니다. 학습 집합 7,830문항 가운데 본문 문장이 근거로 필요한 4,922문항은 셀 검색이 다룰 수 없으므로 제외하고, 남은 2,908문항 가운데 근거 표를 읽을 수 없거나 근거 셀이 빈 칸 또는 머리글 칸인 23문항을 제외하여 2,885문항을 평가 집합으로 한다. 평가 집합의 문서에는 평균 4.05개의 표와 145.7개의 데이터 셀이 있다.

평가 집합은 데이터셋의 계산 과정 표시 유무에 따라 조회 문항과 산술 문항으로 나누고, 근거 셀 수에 따라 셀 1개 문항과 셀 2개 이상 문항으로 나누어 네 그룹으로 구분한다. [표 4-3]은 평가 집합의 구성이다. 검색 성능은 2,885문항 전체로 평가한다. 답변 정확도는 LLM 실행 비용을 고려하여 각 그룹에서 최대 300문항을 고정된 난수 시드로 추출한 882문항으로 평가한다. 이 882문항은 머리글 판정 규칙을 최종 규칙으로 고치기 전의 평가 집합 2,871문항(조회·셀 1개 211문항 전부 포함)에서 추출한 것이며, 최종 규칙으로 읽을 수 있게 된 표가 늘어 검색 평가 집합은 2,885문항이 되었다. 답변 평가 표본은 다시 추출하지 않았으므로, [표 4-3]의 조회·셀 1개 그룹은 검색 평가 212문항, 답변 평가 211문항이다. 기존 방법 비교군과의 답변 정확도 비교는 검색 성능 비교와 같은 문항 집합으로 맞추기 위해, 그리고 LLM을 여러 번 호출하는 비교군의 실행 시간 제약으로, 882문항 가운데 앞의 200문항으로 평가한다.

표 4-3. 평가 집합의 구성

| 문항 그룹 | 정의 | 검색 평가 | 답변 평가 | 답변 평가(200) |
|---|---|---:|---:|---:|
| 조회·셀 1개 | 계산 없음, 근거 셀 1개 | 212 | 211 | 49 |
| 조회·셀 2개 이상 | 계산 없음, 근거 셀 2개 이상 | 367 | 300 | 67 |
| 산술·셀 1개 | 계산 있음, 근거 셀 1개 | 71 | 71 | 14 |
| 산술·셀 2개 이상 | 계산 있음, 근거 셀 2개 이상 | 2,235 | 300 | 70 |
| 전체 | | 2,885 | 882 | 200 |

## 4.2 실험 방법

### 4.2.1 비교군

제안하는 방법의 효과를 검증하기 위해 [표 4-4]의 비교군을 구성한다. 머리글 경로 제거 조건은 제안하는 방법에서 색인하는 셀 문장만 셀 값으로 바꾼 조건이다. 이 조건은 검색 단위, 검색기, 전달하는 셀 수, LLM, 지시문을 모두 제안하는 방법과 같게 두고, LLM에 전달하는 입력도 검색된 셀의 원래 셀 문장으로 구성한다. 따라서 두 조건의 차이는 색인에 머리글 경로가 들어 있는지 여부에서만 생긴다.

기존 방법 비교군은 LangChain 튜토리얼 청크[2], RAPTOR[9], TableRAG(Chen)[13], TableRAG(Yu)[14]의 네 가지이며, 각 방법의 공식 코드나 공식 튜토리얼의 파이프라인을 그대로 따른다. 모든 비교군은 제안하는 방법과 같은 조건에서 실행한다. 모든 LLM 호출에는 Qwen3-8B 4비트 모델을, 모든 임베딩에는 bge-base-en-v1.5를 사용하며, 검색 범위는 질문이 속한 문서의 표로 한정한다. 각 방법의 지시문, 검색 단위, LLM 호출 횟수는 원래의 방법을 따른다. 답변 정확도는 각 방법의 전체 파이프라인으로 측정하고, TableRAG(Yu)의 검색 성능은 4.2.3절과 같이 질의 분해 전의 첫 검색 단계로 측정한다. 검색 없이 문서의 표 전체를 LLM에 넣는 조건은 검색 단계가 없으므로 답변 정확도의 참고 조건으로만 둔다.

표 4-4. 비교군의 구성

| 비교군 | 검색 단위와 LLM 입력 | 답변 평가 |
|---|---|---|
| 머리글 경로 제거 | 셀 값만 색인, 상위 20개 셀의 셀 문장을 입력 | 882 |
| LangChain 청크[2] | 1,000자(겹침 200자) 청크, 상위 4개 청크를 입력 | 200 |
| RAPTOR[9] | 100토큰 잎 청크와 요약 노드의 붕괴 트리 검색, 2,000토큰 또는 575토큰까지 입력 | 200 |
| TableRAG(Chen)[13] | LLM 질의 확장, 스키마·셀 검색, 파이썬 프로그램 실행(최대 5회) | 200 |
| TableRAG(Yu)[14] | LLM 질의 분해, 청크 검색과 재정렬, SQL 실행(최대 5회) | 200 |
| 표 전체 입력(참고) | 검색 없이 문서의 표 전체를 마크다운으로 입력 | 882 |

RAPTOR는 원 논문의 붕괴 트리 설정인 2,000토큰과 함께, 제안하는 방법의 셀 문장 20개의 평균 길이인 575토큰으로 입력 길이를 맞춘 설정을 함께 평가한다. TableRAG(Chen)과 TableRAG(Yu)는 원 논문에서 상용 LLM을 사용하였으나, 본 실험에서는 같은 조건을 위해 모든 호출에 Qwen3-8B를 사용한다. TableRAG(Yu)의 재정렬 모델은 GPU 메모리 제약으로 CPU에서 실행하였으며, 재정렬 점수는 GPU에서 실행한 경우와 같은 모델과 정밀도로 계산된다.

### 4.2.2 평가 지표

검색 성능은 재현율(Recall@k), 정밀도(Precision@k), 평균 역순위(Mean Reciprocal Rank, MRR)로 측정한다. 문항의 정답 근거 셀 집합을 G, 방법이 돌려준 순위 목록의 상위 k개 검색 단위가 담은 셀의 집합을 R_k라 할 때, 재현율은 |G ∩ R_k| / |G|의 문항 평균이다. 정밀도는 상위 k개 단위 가운데 정답 셀을 하나 이상 담은 단위의 비율의 문항 평균이며, 순위 목록이 k개보다 짧아도 분모는 k로 둔다. MRR은 정답 셀을 담은 첫 단위의 순위의 역수의 문항 평균이다. 여기서 k는 검색 단위의 개수이며, k는 1, 5, 10, 20으로 한다. 검색 단위 하나에 담기는 셀 수는 방법마다 다르므로, 결과에는 단위당 평균 셀 수를 함께 보고한다. 이 정밀도는 검색 단위 기준이므로 단위 안의 불필요한 셀 수는 반영하지 않는다. 전달된 셀 가운데 정답 셀의 비율은 셀 정밀도 |G ∩ R_k| / |R_k|의 문항 평균으로 따로 보고한다.

머리글 경로 제거 실험에서는 제안하는 방법과 같은 셀 단위를 사용하므로, 위의 지표와 함께 상위 20개 셀 안에 정답 근거 셀이 모두 들어간 문항의 비율을 검색 성공률로 보고한다. 검색 성공률은 LLM 입력에 공식 근거 셀이 빠짐없이 들어간 문항의 비율이다. 공식 근거 셀에 답에 필요한 값이 모두 표시되어 있지 않은 문항이 있으므로(부록 D), 검색 성공률은 답에 필요한 정보를 모두 확보한 비율이 아니라 공식 근거 셀을 모두 포함한 비율이다.

답변 정확도는 LLM의 답이 정답과 일치하는 문항의 비율이다. 채점은 MultiHiertt 공식 채점 코드의 규칙을 따라 조회 문항은 문자열 비교로, 산술 문항은 수치 비교로 한다. 두 방법의 정확도 차이는 같은 문항끼리 짝지은 McNemar 검정[16]으로 판정하며, 여러 비교군을 함께 판정할 때는 Holm 보정[17]을 적용한다. 검정의 상세 결과는 부록 A에 싣는다.

### 4.2.3 실험 구성

실험은 다음 세 가지로 구성한다. 첫째, 제안하는 방법과 기존 방법 비교군의 검색 성능을 비교한다. RAPTOR와 TableRAG(Chen)은 색인이나 검색 단계에서 LLM을 호출하므로 답변 평가와 같은 200문항에서 검색 성능을 측정하고, 나머지 방법은 2,885문항 전체에서도 측정한다. TableRAG(Yu)의 검색 성능은 LLM의 질의 분해 없이 질문 자체로 수행한 첫 번째 검색(회수 30개, 재정렬)의 순위 목록으로 측정한다. 따라서 이 값은 전체 파이프라인의 최종 검색 성능이 아니라 초기 검색 단계의 성능이며, 전체 파이프라인이 LLM에 넣은 셀의 합집합에 대한 검색 성공률과 셀 정밀도는 4.3.1절에서 따로 보고한다. 둘째, 882문항에서 제안하는 방법과 머리글 경로 제거 조건의 검색 성능과 답변 정확도를 비교하여 머리글 경로의 효과를 확인한다. 셋째, 검색 성능을 비교한 것과 같은 200문항에서 제안하는 방법과 기존 방법 비교군의 답변 정확도를 비교한다. 머리글 경로 제거 실험은 실행 전에 예측과 판정 기준을 기록한 뒤 수행하였다.

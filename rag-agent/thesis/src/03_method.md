# 제 3 장 셀 문장 기반 검색 증강 생성 시스템

본 장에서는 제안하는 셀 문장 기반 검색 증강 생성 시스템의 구조와 작동 원리를 살펴본다. 먼저 기존의 청크 분할 방식에서 셀 값과 머리글이 분리되는 현상을 분석하고, 제안하는 방법이 필요한 이유를 설명한다. 그리고 제안하는 시스템의 전체 구조와 구성 요소를 살펴본다. 마지막으로 머리글 경로 구성, 셀 문장 생성, 색인, 유사도 계산, 답변 생성의 각 단계를 상세히 설명한다.

## 3.1 청크 분할 방식의 머리글 분리 분석

기존의 검색 증강 생성은 표를 마크다운과 같은 텍스트로 펼친 뒤 일정한 길이의 청크로 잘라 색인한다. 계층형 표를 이 방식으로 펼치면 열 머리글은 표 텍스트의 맨 위 몇 줄에 모이고, 그 아래의 각 줄은 행 머리글 하나와 여러 개의 셀 값으로 이루어진다. 따라서 표가 두 개 이상의 청크로 나뉘면 두 번째 청크부터는 열 머리글 줄이 들어 있지 않다.

[그림 3-1]은 MultiHiertt 문서의 표를 1,000자 단위의 청크로 나눈 예를 단순화한 것이다. 첫 번째 청크에는 연도를 나타내는 열 머리글 줄이 들어 있지만, 두 번째 청크에는 "Total consumer" 행의 값 18,768, 20,854, 20,839만 남는다. 두 번째 청크만 검색되면 LLM은 20,854가 어느 연도의 값인지 청크 안에서 알 수 없다. 반면 제안하는 방법의 셀 문장은 "Consumer > Total consumer > December 31 > 2010: 20,854"와 같이 값과 그 값의 행 머리글 경로, 열 머리글 경로를 한 줄에 함께 담는다.

![그림 3-1. 청크 분할에서 머리글과 값이 분리되는 예](fig/fig3_1_chunk_split.png)

이러한 분리가 실제로 얼마나 일어나는지 확인하기 위해, MultiHiertt 평가 문항 2,885개의 문서를 LangChain 튜토리얼[2]과 같은 설정(1,000자, 겹침 200자)으로 분할하고 정답 셀이 담긴 청크를 조사하였다. 열 머리글 줄은 표 텍스트의 맨 위에서 첫 데이터 행 바로 앞까지이므로, 정답 셀을 담은 청크 가운데 어느 것도 그 표의 첫 데이터 행을 담지 않으면 그 청크에는 열 머리글 줄이 없는 것으로 보았다. 이는 열 머리글 줄 자체를 확인한 것이 아니라 첫 데이터 행의 포함 여부를 대리 기준으로 삼은 판정이다. 그 결과 정답 셀 7,651개 가운데 730개(9.5%)가 이 기준으로 열 머리글 줄이 없는 청크에만 들어 있었고, 문항 기준으로는 2,885개 가운데 339개(11.8%)가 이러한 정답 셀을 하나 이상 포함하였다. 이 비율은 대리 기준으로 측정한 값이며, 행 머리글이 분리되는 경우는 세지 않았다.

기존의 표 대상 검색 방법도 셀과 머리글의 연결을 보장하지 않는다. [표 3-1]은 2장에서 설명한 방법들이 색인하는 단위와 단위 하나에 담기는 평균 셀 수, 머리글이 분리되는 경로를 정리한 것이다. 단위당 평균 셀 수는 4장의 평가 문항에서 각 방법의 검색 순위 목록에 오른 단위를 기준으로 측정하였다.

표 3-1. 기존 방법의 색인 단위와 머리글 분리 경로

| 방법 | 색인 단위 | 단위당 평균 셀 수 | 머리글이 분리되는 경로 |
|---|---|---:|---|
| LangChain 청크[2] | 1,000자 청크 | 37.5 | 청크 경계에서 열 머리글 줄이 빠짐 |
| RAPTOR[9] | 100토큰 잎 청크와 요약 노드 | 13.3 | 잎 청크는 청크 경계에서, 요약 노드는 요약 과정에서 셀 값과 머리글이 빠짐 |
| TableRAG(Chen)[13] | 스키마 문서와 열-값 쌍 문서 | 0.5 | 행 머리글이 없고, 숫자 열은 최솟값·최댓값 요약으로만 색인됨 |
| TableRAG(Yu)[14] | 1,000자 청크와 관계형 스키마 | 30.6 | 청크 경계에서 열 머리글 줄이 빠지고, 여러 층의 머리글이 열 이름 하나로 합쳐짐 |

따라서 계층형 표가 포함된 문서에서는 셀 값과 그 값을 해석하는 데 필요한 머리글을 하나의 검색 단위에 함께 담는 방법이 필요하다. 본 논문에서 제안하는 시스템은 셀 하나를 검색 단위로 삼고, 각 셀에 캡션과 머리글 경로를 붙인 셀 문장을 색인한다.

## 3.2 시스템 구조 및 구성 요소

제안하는 시스템의 흐름도는 [그림 3-2]와 같다. 시스템은 머리글 경로 구성, 셀 문장 생성, 임베딩과 색인, 하이브리드 유사도 계산, LLM 입력 구성과 답변 생성의 다섯 단계로 이루어진다. 앞의 세 단계는 문서가 주어질 때 한 번 수행하는 색인 단계이고, 뒤의 두 단계는 질문이 주어질 때마다 수행하는 질의 단계이다.

![그림 3-2. 제안하는 시스템의 흐름도](fig/fig3_2_system.png)

제안하는 시스템의 구성 요소는 다음과 같다.

- **머리글 경로 구성기**: 문서의 각 표에서 머리글 행과 머리글 열을 판정하고, 데이터 셀마다 행 머리글 경로와 열 머리글 경로를 만든다. 문서 안에서 경로가 같은 셀이 남지 않도록 경로를 늘린다.
- **셀 문장 생성기**: 데이터 셀마다 캡션, 행 머리글 경로, 열 머리글 경로, 셀 값을 하나의 문장으로 만든다. 표에 캡션이 없으면 캡션을 생략한다.
- **색인**: 셀 문장을 임베딩 모델로 벡터화하여 저장하고, 같은 셀 문장으로 BM25 색인을 만든다. 색인은 문서마다 만든다.
- **하이브리드 검색기**: 질문과 셀 문장의 코사인 유사도와 BM25 점수를 가중합하여 순위를 매기고, 상위 20개 셀 문장을 고른다.
- **LLM**: 상위 20개 셀 문장과 질문을 입력받아 계산 과정과 최종 답을 생성한다.

제안하는 시스템은 임베딩 모델과 LLM을 학습하지 않는다. 모든 단계는 외부 API 없이 로컬 환경에서 수행한다.

## 3.3 제안하는 시스템의 작동 원리

### 3.3.1 머리글 경로 구성

셀 (i, j)의 행 경로는 i행에 해당하는 행 머리글을 상위 계층부터 차례로 나열한 것이고, 열 경로는 j열에 해당하는 열 머리글을 상위 계층부터 차례로 나열한 것이다. 경로의 각 층은 " > " 기호로 잇는다. [그림 1-1]의 셀 860은 행 경로 "Revenue > Product"와 열 경로 "2019 > Foreign"을 가진다.

문서의 표는 머리글 칸이 따로 표시되지 않은 HTML 표로 주어지므로, 제안하는 시스템에서는 다음 규칙으로 머리글 행과 머리글 열을 판정한다. 머리글 행은 표의 왼쪽 위 모서리 칸이 비어 있는 경우 행 머리글 칸에 처음으로 글자가 나타나는 행의 바로 위까지로 정하고, 이 신호가 없으면 행 머리글 칸을 제외한 칸의 절반 이상이 숫자인 첫 행의 바로 위까지로 정한다. 머리글 열은 머리글 블록의 마지막 행에서 비어 있는 왼쪽 열의 수로 정하고, 이 신호가 없으면 숫자 칸이 절반 이상인 첫 열의 앞까지로 정한다. 가로로 병합된 머리글 칸은 병합 범위의 모든 열에 같은 머리글을 부여하고, 데이터 칸이 모두 비어 있는 행은 절 제목 행으로 보아 그 아래 행들의 행 경로 맨 앞에 붙인다.

머리글 경로만으로는 서로 다른 셀이 같은 경로를 가질 수 있다. 예를 들어 한 문서 안에 같은 구조의 표가 두 개 있으면, 두 표의 같은 위치 셀은 같은 행 경로와 열 경로를 가진다. 두 셀의 경로가 같으면 검색기는 두 셀을 머리글로 구별할 수 없고, LLM도 어느 값이 무엇인지 알 수 없다. 제안하는 시스템에서는 문서 안에 경로가 같은 셀이 남지 않을 때까지 다음 순서로 경로를 늘린다. 첫째, 행에는 바로 위의 절 제목 행을, 열에는 첫 값이 나오기 전까지 그 열 윗부분의 글을 경로에 더한다. 둘째, 그래도 같으면 행 번호 또는 열 번호를 더한다. 셋째, 문서 안의 다른 표와 경로가 같은 표는 모든 행 경로 앞에 문서 안 표 순서를 붙인다. 이 규칙은 경로가 같은 행과 열에만 적용되며, 나머지 셀의 경로는 바꾸지 않는다.

### 3.3.2 셀 문장 생성

머리글 경로가 구성되면 데이터 셀마다 하나의 셀 문장을 만든다. 표에 캡션이 있는 경우 셀 문장은 캡션, 행 경로, 열 경로, 셀 값을 다음 틀에 넣어 만든다.

> In the table '{캡션}', among {행 경로}, the value of {열 경로} is {값}.

표에 캡션이 없는 경우에는 캡션 자리를 생략하고 다음 틀로 만든다.

> {행 경로} > {열 경로}: {값}

캡션은 셀이 어느 표에 속하는지를 알려 주므로, 문서나 색인 안에 표가 여러 개 있을 때 다른 표의 셀과 구별하는 데 쓰인다. 본 논문의 주 평가 데이터인 MultiHiertt의 표에는 캡션이 없으므로, 4장의 실험에서 셀 문장은 행 경로, 열 경로, 셀 값으로 구성된다. 표마다 제목이 주어지는 HiTab에서 캡션의 효과를 확인한 결과는 부록 C에 싣는다. 머리글 칸과 빈 칸은 셀 문장을 만들지 않는다.

[그림 3-3]은 표의 일부에서 셀 문장이 만들어지는 예이다. 셀 문장 하나는 셀 하나의 값과 그 값의 의미를 정하는 머리글을 한 줄에 담는다. 따라서 셀 문장 하나만 LLM에 전달되어도 LLM은 그 값이 무엇의 값인지 읽을 수 있다. 이 성질은 3.1절에서 설명한 것처럼 청크 안의 데이터 줄이 머리글 줄 없이는 해석될 수 없는 것과 대비된다.

### 3.3.3 셀 문장 임베딩과 색인

셀 문장은 임베딩 모델 BAAI/bge-base-en-v1.5[4]로 768차원 벡터로 변환하여 저장한다. 벡터는 길이가 1이 되도록 정규화하여 내적이 곧 코사인 유사도가 되게 한다. 같은 셀 문장으로 BM25 색인도 함께 만든다. 색인은 문서마다 만들며, 한 문서의 색인에는 그 문서에 포함된 모든 표의 셀 문장이 들어간다. 임베딩 모델은 학습하지 않고 공개된 가중치를 그대로 사용한다.

### 3.3.4 질문과 셀 문장의 유사도 계산

질문이 주어지면 질문을 같은 임베딩 모델로 벡터화하고, 질문이 속한 문서의 색인에서 질문과 셀 문장의 유사도를 계산한다. 임베딩 모델의 사용법에 따라 질문 앞에는 검색용 지시문을 붙이고, 셀 문장에는 붙이지 않는다. 유사도는 코사인 유사도와 BM25 점수를 문서 안의 후보 셀 집합에서 각각 최소-최대 정규화한 뒤 다음과 같이 가중합한 하이브리드 점수로 계산한다.

> score = 0.7 × minmax(cosine) + 0.3 × minmax(BM25)

코사인 유사도는 질문과 셀 문장의 의미 유사도를 반영하고, BM25 점수는 질문에 나온 머리글 단어와 숫자가 셀 문장에 그대로 나타나는지를 반영한다. 재무 보고서의 질문에는 항목 이름과 연도가 그대로 나타나는 경우가 많으므로 두 점수를 함께 사용한다. 순위는 문서 안의 모든 셀 문장에 대해 계산하며, 근사 최근접 탐색은 사용하지 않는다. 하이브리드 점수의 상위 20개 셀 문장을 LLM의 입력으로 전달한다.

### 3.3.5 LLM 입력 구성과 답변 생성

상위 20개 셀 문장을 유사도 순위대로 한 줄씩 나열하여 LLM 입력을 구성한다. LLM 입력은 "Context:" 줄 다음에 셀 문장을 한 줄씩 쓰고, 빈 줄 뒤에 "Question:"과 질문, "Answer:"를 붙인 형태이다. LLM에는 공개 모델인 Qwen3-8B[15]를 4비트로 양자화하여 사용하며, 생각 모드를 끄고 탐욕 디코딩으로 최대 384토큰을 생성한다. LLM에 주는 지시문은 "주어진 표 자료만 사용하여 답하라. 행과 열의 라벨을 읽어 해당 값을 찾아라. 단계별로 계산 과정을 쓰고 마지막 줄에 'Final answer: '와 최종 값만 써라"라는 내용이며, 원문은 부록 B에 싣는다. LLM의 답은 마지막 "Final answer:" 뒤의 값으로 읽는다.

셀 문장 20개의 길이는 평균 574토큰이며, 지시문과 질문을 포함한 LLM 입력 전체는 평균 694토큰이다. 이는 문서의 표 전체를 마크다운으로 넣은 LLM 입력의 평균 1,505토큰의 절반 이하이다.

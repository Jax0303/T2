# 제1장 서론

## 1.1 연구 배경

대규모 언어 모델(LLM)은 자연어 질문에 답할 때 외부 자료를 문맥으로 받아 쓰는 검색 증강 생성(Retrieval-Augmented Generation, RAG) 방식으로 널리 쓰인다. 기업·기관의 보고서와 통계 자료는 상당 부분이 표로 되어 있으므로, 표를 근거로 답하는 질의응답은 RAG의 주요 적용처다.

실무 문서의 표는 대개 계층형이다. 계층형 표는 행 머리글과 열 머리글이 여러 층으로 쌓여 있고, 셀 하나의 의미가 여러 층 머리글의 조합으로 정해진다. 예를 들어 통계 보고서의 표에서 값 `52.1`은 "지역 = 동부 온타리오 > 프랑스어 사용 노동자", "산업 = 퍼센트 > 음식 서비스"라는 두 경로가 함께 붙어야 비로소 "동부 온타리오 프랑스어 사용 노동자 중 음식 서비스업 종사 비율 52.1%"라는 사실이 된다.

LLM에 표를 넣으려면 표를 텍스트로 바꿔야 한다. 흔한 방식은 표를 마크다운이나 쉼표 구분 텍스트로 펴는 것이다. 그런데 계층형 표를 행 단위로 펴면, 상위 머리글은 표 맨 위의 몇 줄에만 남고 아래쪽 데이터 행에서는 떨어져 나간다. 그 결과 특정 셀 값이 어느 머리글 조합에 속하는지가 텍스트 안에서 사라진다. 이 문제는 표 일부만 잘라 검색하는 RAG에서 더 커진다. 검색 단위가 데이터 행 몇 줄뿐이면, 그 줄에는 해석에 필요한 머리글이 들어 있지 않기 때문이다.

본 연구는 외부 API를 쓰지 않고 로컬 모델만으로 동작해야 하는 폐쇄된 환경을 전제로 한다. 보안상 자료를 외부 서비스로 보낼 수 없는 기관의 문서 질의응답이 대표적인 경우다. 이 환경에서는 임베딩 모델과 리더(답을 생성하는 LLM)를 모두 로컬에서 돌려야 한다. 본 연구의 실험은 8GB 메모리의 소비자용 GPU 한 장에서 수행했다.

## 1.2 문제 정의

본 연구는 표 질의응답 연구의 closed-domain 설정을 따른다. 이 설정에서는 질문과 짝지어진 표(HiTab) 또는 문서(MultiHiertt)가 직접 주어진다(Zhou et al., 2026; Cheng et al., 2022). 검색은 그 표·문서 안에서 답에 필요한 정보를 담은 셀을 찾는 일이다. 검색된 상위 20개 셀이 표를 대신해 리더의 입력이 된다. 이 구성은 표 안 검색기(inner table retriever)가 찾은 부분 표가 원래 표 대신 어떤 표 질의응답 시스템의 입력으로도 쓰일 수 있다는 Lin et al.(2023)의 정의와 같다.

풀려는 문제는 다음과 같다.

- **머리글 소실.** 표를 평평하게 펴거나 행·청크 단위로 자르면 셀 값이 무엇의 값인지를 알려 주는 머리글 경로가 셀에서 분리된다. 그러면 검색기는 질문이 가리키는 셀을 머리글 정보 없이 찾아야 하고, 리더는 검색된 조각만 보고 값의 의미를 해석해야 한다.

본 연구는 검색 성공을 다음과 같이 정의한다. 한 질의에 대해 데이터셋이 주석한 정답 근거 셀이 **전부** 리더에게 전달되는 20개 셀 안에 들어 있으면 성공, 하나라도 빠지면 실패다. 검색 정확도는 성공한 질의의 비율이다.

## 1.3 연구 내용과 기여

본 연구는 셀 하나하나를 "고유 라벨 + 행 머리글 경로 + 열 머리글 경로 + 값"으로 이루어진 문장으로 만들고, 그 문장을 학습하지 않은 기성 임베딩 모델로 색인하는 셀 검색 방법을 제안한다. 여기서 고유 라벨은 데이터셋이 표에 붙여 둔 제목류(HiTab의 절 제목과 페이지 제목)다. 본 연구의 기여는 다음과 같다.

1. **고유 라벨의 기여를 문장 틀과 분리해 측정했다.** HiTab 단일 셀 조회 991건에서, 같은 문장 틀에 라벨만 넣고 빼는 비교를 했다. 질문이 속한 표 안에서 검색할 때 검색 정확도는 .9445에서 .9637로 올랐고(McNemar 23:4, p=3.1×10⁻⁴), 538개 표를 한 색인에 넣었을 때는 .8123에서 .9142로 올랐다(121:20, p=8.3×10⁻¹⁹). 반면 문장 틀 자체의 효과는 두 조건 모두 유의하지 않았다. 이득은 라벨의 내용에서 나온다.
2. **두 계층형 표 데이터셋에서 발표된 표 표현들과 같은 조건으로 비교했다.** TableRAG(Chen et al., 2024)의 셀·스키마 표현 두 가지와 이 논문이 비교군으로 쓴 RowCol·RandRowSampling, 이종 문서용 TableRAG(Yu et al., 2025)의 청크 표현, 업계 관행인 고정 길이 청크를 구현했다. 이들을 같은 임베딩 모델, 같은 검색기, 같은 셀 예산(20셀)에 놓았다. 검색 정확도에서 본 방법은 HiTab 단일 셀 조회(.9586)와 MultiHiertt 네 질의 그룹 모두에서 1위다. 짝지은 McNemar 검정에서 비교 칸 대부분이 유의했다(5장).
3. **답변 정확도까지 같은 질의로 측정했다.** 검색 결과를 그대로 로컬 리더에 넣어 HiTab 300건, MultiHiertt 882건의 답변 정확도를 쟀다. 검색 없이 표 전체를 리더에 넣는 조건도 함께 쟀다(5장).
4. **한계를 수치로 밝혔다.** 표 직전 문단을 라벨로 쓰면(MultiHiertt) 검색 정확도가 오히려 떨어진다(.8495→.8304, p=.0014). 또 MultiHiertt의 정답 근거 주석은 조건 판정에 필요한 셀을 빠뜨리는 문항이 약 23.5% 있다고 추정했다(6장).

모든 비교는 실행 전에 사전등록한 규칙에 따라 수행했다. 결과를 본 뒤 설정을 바꾸지 않았다.

## 1.4 논문 구성

2장은 계층형 표 질의응답 데이터셋, 표 안 검색과 표 RAG, 문맥 속 무관 정보가 리더에 미치는 영향에 관한 선행 연구를 정리한다. 3장은 제안 방법을 설명한다. 4장은 데이터, 비교군, 지표, 통계 검정을 포함한 실험 설정을 기술한다. 5장은 고유 라벨 효과, 검색 정확도, 답변 정확도 결과를 보고한다. 6장은 결과의 해석과 한계를 논의하고, 7장에서 결론을 맺는다.

# 제 1 장 서론

## 1.1 연구 배경

재무 보고서, 통계 자료, 기술 문서와 같은 기업과 기관의 문서에는 본문과 함께 여러 개의 표가 들어 있다. 재무 보고서 기반 질의응답 데이터셋인 MultiHiertt[11]의 경우, 본 논문의 평가에 사용한 문서 한 건에는 평균 4.05개의 표와 145.7개의 데이터 셀이 포함되어 있다. MultiHiertt의 표는 행 머리글과 열 머리글이 여러 층으로 이루어진 계층형 표이다[11]. 계층형 표에서는 셀 하나의 값이 무엇을 뜻하는지가 그 셀이 속한 행의 머리글들과 열의 머리글들을 모두 합쳐야 정해진다. [그림 1-1]은 계층형 표의 예이다. 음영으로 표시한 셀의 값 860은 행 머리글 경로 "Revenue > Product"와 열 머리글 경로 "2019 > Foreign"이 함께 붙어야 "2019년 해외 제품 매출 860"이라는 사실이 된다.

![그림 1-1. 계층형 표와 셀의 머리글 경로](fig/fig1_1_hier_table.png)

대규모 언어 모델(Large Language Model, LLM)은 자연어 질문에 답하는 능력이 높지만, 학습에 쓰이지 않은 문서의 내용은 알지 못한다. 이를 보완하기 위해 질문과 관련된 문서 조각을 먼저 찾아 LLM의 입력에 함께 넣는 검색 증강 생성(Retrieval-Augmented Generation, RAG)이 널리 쓰인다[1]. RAG는 일반적으로 문서를 일정 길이의 청크(chunk)로 나누어 색인하고, 질문과 가장 유사한 청크를 찾아 LLM에 전달한다[2].

그러나 계층형 표를 청크로 나누면 셀 값과 머리글이 분리된다. 표를 텍스트로 펼치면 열 머리글은 표의 맨 위 몇 줄에만 남고, 행 머리글은 각 행의 왼쪽에만 남는다. 이 텍스트를 여러 청크로 자르면 아래쪽 청크에는 열 머리글이 들어 있지 않으므로, 청크 안의 숫자가 어느 머리글 조합에 속하는지 알 수 없게 된다. 실제로 MultiHiertt 평가 문항 2,885개 가운데 339개(11.8%)는 정답 셀이 담긴 청크에 그 표의 열 머리글 줄이 들어 있지 않았다(3.1절). 이러한 경우 검색기는 질문이 가리키는 셀을 머리글 없이 찾아야 하고, LLM은 검색된 조각만 보고 값의 의미를 해석해야 한다. 또한 문서 하나에 여러 개의 표가 있으면 서로 다른 표의 같은 위치 셀이 비슷한 텍스트로 표현되므로, 머리글 없이는 셀을 구별하기가 더 어렵다.

따라서 계층형 표가 포함된 문서에 대한 RAG에서는 표를 청크 단위로 자르는 대신, 각 셀이 자신의 머리글 정보를 가진 채로 검색되도록 하는 방법이 요구된다. 그리고 보안상 문서를 외부 서비스로 보낼 수 없는 기관에서는 외부 API 없이 로컬 환경의 공개 모델만으로 동작하는 구성이 필요하다.

## 1.2 검색 증강 생성

검색 증강 생성은 [그림 1-2]와 같이 색인 단계와 질의 단계로 이루어진다. 색인 단계에서는 문서를 일정한 단위의 조각으로 나누고, 임베딩 모델(embedding model)로 각 조각을 고정 차원의 벡터로 바꾸어 벡터 데이터베이스에 저장한다. 질의 단계에서는 사용자의 질문이 주어지면 검색기(retriever)가 질문을 같은 임베딩 모델로 벡터화하고, 벡터 데이터베이스에서 질문 벡터와 유사도가 높은 조각을 찾는다. 검색된 조각은 질문과 함께 LLM의 입력으로 전달되며, LLM은 이 입력을 바탕으로 답을 생성한다.

![그림 1-2. 검색 증강 생성의 구조](fig/fig1_2_rag.png)

생성된 답은 답변 검증 단계를 거칠 수 있다. 답변 검증은 생성된 답이 검색된 조각에 근거하는지를 확인하는 단계로, 검증을 통과하면 답을 사용자에게 반환하고 통과하지 못하면 답을 다시 생성하게 할 수 있다. 예를 들어 Self-RAG는 LLM이 반성 토큰을 생성하여 자신이 생성한 답이 검색된 조각에 근거하는지를 스스로 평가하고, 여러 후보 가운데 가장 나은 답을 고른다[8]. 본 논문의 시스템은 답변 검증 단계를 사용하지 않으며, 검색 단계에서 문서를 어떤 단위로 나누어 색인하는지에 초점을 둔다.

LLM의 입력에 답에 필요한 정보가 빠져 있으면 LLM은 답을 맞힐 수 없다. 따라서 문서를 어떤 단위로 나누어 색인하는지가 검색 증강 생성의 성능을 좌우하며, 1.1절에서 설명한 것처럼 계층형 표가 포함된 문서에서는 이 선택이 특히 중요하다.

## 1.3 연구 목적 및 내용

본 논문에서는 계층형 표가 여러 개 포함된 문서에서 질문에 필요한 셀을 찾아 LLM에 전달하는 셀 문장 기반 검색 증강 생성 방법을 제안한다. 기존의 RAG는 표를 청크 단위로 잘라 색인하기 때문에, 청크 경계에서 셀 값과 머리글이 분리되면 검색기와 LLM이 셀 값의 의미를 알 수 없다. 따라서 제안하는 방법은 문서의 각 데이터 셀을 표의 캡션, 행 머리글 경로, 열 머리글 경로, 셀 값을 담은 하나의 문장으로 변환하고, 이 셀 문장을 검색 단위로 삼는다. 표에 캡션이 없는 경우에는 행 머리글 경로, 열 머리글 경로, 셀 값만으로 셀 문장을 만든다. 셀 문장은 임베딩하여 색인하고, 질문이 주어지면 질문과 셀 문장의 하이브리드 유사도로 상위 20개 셀을 찾아 LLM의 입력으로 전달한다. 제안하는 방법은 임베딩 모델과 LLM을 학습하지 않으며, 공개된 모델을 로컬 환경에서 그대로 사용한다.

제안하는 방법의 효과는 MultiHiertt 데이터셋[11]으로 검증한다. 먼저 셀 문장에서 머리글 경로를 제거한 조건과 비교하여 머리글 경로가 검색과 답변에 미치는 영향을 확인한다. 그리고 LangChain 공식 튜토리얼의 청크 분할 방식[2], RAPTOR[9], 두 가지 TableRAG[13][14]를 원래의 파이프라인대로 구현하고, 모든 방법에 같은 LLM과 같은 임베딩 모델을 사용하여 검색 성능과 답변 정확도를 비교한다. 답변 정확도는 각 방법의 전체 파이프라인으로 측정하며, TableRAG(Yu)의 검색 성능은 질의 분해 전의 첫 검색 단계로 측정한다. MultiHiertt의 표에는 캡션이 없으므로, 캡션의 효과는 표마다 제목이 주어지는 HiTab 데이터셋[10]으로 부록 C에서 확인한다.

## 1.4 본 논문의 구성

본 논문의 구성은 다음과 같다. 2장에서는 검색 증강 생성의 개념과 구성 요소, 문서 분할과 검색 기법, 계층적 요약 기반 검색, 계층형 표 질의응답과 표 대상 검색 증강 생성에 관한 연구를 설명한다. 3장에서는 청크 분할 방식에서 셀 값과 머리글이 분리되는 현상을 분석하고, 제안하는 셀 문장 기반 검색 증강 생성 시스템의 구조와 작동 원리를 기술한다. 4장에서는 실험 환경과 방법을 설명하고, 머리글 경로 제거 실험과 비교군 실험을 통해 제안하는 방법의 검색 성능과 답변 정확도를 평가한다. 마지막으로 5장에서 결론을 맺는다.

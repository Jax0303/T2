## 1. 이번 라운드에서 확정된 것

### 1.1 선행연구 검증 — 직렬화는 기여가 아니다 (원문 직접 확인)

MT2Net(Zhao et al., MultiHiertt, ACL 2022, arXiv:2206.01347) PDF를 직접 읽고 §4 5쪽에서 확인:

- "we turn each cell into a sentence, along with its **hierarchical row and column headers**"
- 예시 문장이 본 저장소 S3 템플릿(`For {row_path}, {col_path} is {value}`)과 구조 동일
- "the **top-n sentences are retrieved** as supporting facts"
- 계층 출처도 차별점 아님 — "a **pre-processing script to extract the hierarchical structure**
  of each HTML-format table" (사람 주석 아님)
- 평탄화 대비 우위 실험도 이미 발표 — TAGOP/FinQANet은 "ignore the table's hierarchical
  structure in the retrieving part"

**→ "셀을 문장화해서 임베딩·검색한다"는 2022년에 있다. 기여로 서술하면 이 문단 하나로 무너진다.**
`RESEARCH_STRUCTURE.md` §3.3에 인용 추가함.

### 1.2 MT2Net "64% 오류"를 표적 삼는 프레이밍은 못 쓴다

Table 6은 **생성된 수식**을 사람이 100건 분류한 taxonomy다 (Wrong Operand or Span 43%,
Missing Operand 21%, Wrong Program 19%, Lack of Domain Knowledge 4%).
예시가 `G: (1203+1437+1896+1774)/4` / `P: (1203+1774)/2` — 리즈닝이 만든 수식이 틀린 것이고,
논문은 이 오류를 **검색 실패 / 추론 실패로 귀속 분해하지 않았다.**
"검색이 64% 놓친다"로 인용하면 표 하나 펴는 순간 깨진다.

우리 데이터는 오히려 반대를 말한다 — **분해가 맞으면 `osc_given_decomp = 1.00`**
(`results/e6_scope_treatments.json`, `results/e2_osc_enum*.json`).
병목은 검색이 아니라 **무엇을 찾을지 정하는 단계**다.

### 1.3 '누락 재검색으로 보정'은 이미 세 번 죽었다

| 시도 | 결과 | 출처 |
|---|---|---|
| 스코프 열거 union | OSC .4252→.5654 (셀 10→19), **예산 맞춤 대조 후 +.014 p=.55** | §5 |
| 구조/서브트리 재검색 | base .4161→.5963 (셀 19.2→**30.3**), plain dense@10 대비 여전히 **−.193** | `results/e6_scope_treatments.json` |
| 완전성 게이트 | base k≥3에서 **발동 0회**. k=1의 12건 회복은 전부 "k를 넓힌다" 단계에서 나옴 | `results/gate_k{1,2,3}.json` |

**표준 규칙(확정):** 증거 집합을 키우는 arm은 **per-query 예산 맞춤 대조**(같은 셀 수를
유사도 순위만으로 채운 통제군)를 보고하기 전에는 델타를 인용하지 않는다.

**추가 2026-08-08 — 네 번째 사망, 그리고 그 이상.** 위 표의 처방들은 정작 그 규칙의 대조를
한 번도 안 받았다(dense@10과 비교했을 뿐이고 그건 S2 행-청크라 단위가 다르다).
제대로 붙이니 주입은 **예산 무효가 아니라 유의한 손해**(k=5/10/20에서 −.149/−.137/−.075,
p=.005/.001/.043)였고, 같은 대조를 base에 걸면 **표적 분해 자체가 단순 유사도에 진다**
(−.180/−.137/−.130, p≤9.4e-4). `scripts/inject_osc_matched.py`, `RESEARCH_STRUCTURE.md` §5.1.
**범위는 HiTab 표 내부.** 코퍼스 규모 반복 전까지 일반화 금지.

### 1.4 E-A — 리랭커 효과는 풀 크기에 단조

`scripts/ea_pool_size_sweep.py` + `ea_crossover_stats.py`, gold를 항상 풀 안에 넣어
**순수 순위 문제**만 측정. ΔOSC@10 (hybrid→cross, Holm family=18):

| pool | flat | S3 | p_holm(S3) |
|---|---|---|---|
| 50 / 100 | −.003 | +.027 | 1.00 |
| 200 | −.027 | −.007 | 1.00 |
| 500 | −.055 | −.079 | **.043** |
| 1000 | −.085 | −.106 | **.0012** |

§2.2의 "코퍼스에선 해롭고 문서 내에선 도움"이라는 모순은 없었다 — **0 근처의 잡음**이었다.
⚠️ 작은 풀에서 "무해"까지 주장 금지(검정력 부족). "풀이 작을수록 0에 수렴"까지만.
⚠️ 구 §2.2의 93→63(pool=100)과 직접 비교 금지 — 저건 1단계 top-100이라 풀 회수 실패가 섞인다.

### 1.5 E-B — 재현은 문제가 아니었다. 출처 추적이 문제였다

메인 3종은 237/68/33개 수치가 **전부 0 diff**로 재현. 빠져 있던 건 환경 기록뿐
(→ `rag_agent/runenv.py::run_env`가 이제 `env` 블록 기록).

그런데 "메인 3종" 목록에 **`operand_collision_within_doc.py`가 빠져 있었고**, 그게
주장 4와 §2.2 문서 내 수치의 실제 출처였다. 재실행하니 S2_shuf 값 57개가 움직였다.

**구 주장 4("hybrid에서 S2 = S2_shuf 소수 4자리 일치")는 순열 한 번의 우연이었다.**
순열 6회 분포로 재작성(§4.1): 단어 효과는 크고 일관, **순서 효과는 검출 안 됨**.
→ 무작위 대조군은 평균 ± 범위로만 인용. `--shuffle-seed`로 draw 선택,
`tests/test_s2_shuf_determinism.py`가 `PYTHONHASHSEED` 0/1/12345로 결정성 검증.

### 1.6 주장 5 — 유의성은 run이 끊긴 지점이 만든 값이었다

주입이 검색을 실제로 바꾸는(OSC 0→1) 질의는 161건 중 **10건(6.2%)뿐**.
`--flips-first`가 그 10건을 맨 앞에 두므로 TPD로 일찍 끊긴 표본일수록 flip이 진해진다
(10/86 = 11.6%). 완주한 gpt-4o 기록을 앞에서부터 잘라 채점하면 절단 지점만으로 값이 움직인다 —
**유의성은 N≤104에서만 존재**(§4.3 표).

살아남는 것: flip 10건에서 gpt-oss-120b .00→.90(9:0), gpt-4o .00→.50(5:0), **손해 0**.
"회수를 고치면 답도 고쳐진다"는 성립. "그래서 모집단 정확도가 오른다"는 불성립.
산술 천장 = 6.2% × .90 ≈ **5.6pp**. **절단 표본 p값 전부 인용 금지.**

## 2. 지금 서 있는 자리

**살아남은 주장 3개** (전부 예산·조건 명시 필수):

1. **지표** — OSC(전부-아니면-무). 기존 표 QA는 top-n을 리더에 넘기고 답으로만 재므로 이 성질이 안 보인다.
2. **진단** — 리랭커는 **좁은 예산에서만** 집합을 깬다(@50에선 소멸, 두 실험 일치) ·
   이득은 조상 헤더 **단어**에서 오고 **순서 기여는 검출 안 됨** · 천장은 검색이 아니라 **질의 분해**.
3. **방법** — 의미 헤더-경로 resolver. **예산 맞춤 대조를 통과한 유일한 개입**
   (train n=1,006, k=5/10/20 각각 +.049/.038/.040, p=8.1e-4/6.2e-3/1.6e-3).

**부수 검증:** RealHiTBench에서 S1 flat vs S2 header-path가 3개 솔버 계열 전부 동방향
(+.149 p=.004 / +.106 p=.021 / +.136 p=.070). 이건 "우리가 제안"이 아니라
**S2가 베이스라인 대비 유효함의 재확인**으로만 쓴다(§1.1 참조).

**격하된 것:** 총합행 주입 → HiTab 전용 **사례연구**. 헤드라인 금지.

## 5. 환경 주의

- 실험은 **반드시 `rag-agent/.venv`**. 시스템 파이썬으로 확인하면 GPU 없음/의존성 깨짐으로 오진한다.
- API 키는 `.env`에 있고 export 안 돼 있다 → `set -a; . ./.env; set +a`
- 현 OpenAI 프로젝트 키는 `gpt-4o`까지만 접근 가능(gpt-5.1은 403 model_not_found).
- LLM 레그는 질의당 1레코드 append + `--resume`이라 일일 한도로 작업이 날아가지 않는다.
  **단, 백엔드를 바꿔 resume하지 말 것** — 한 records 파일의 두 arm은 같은 솔버여야 한다.

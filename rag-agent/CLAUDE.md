## 1. 논문

- 제목: **폐쇄된 환경에서 계층형 표 구조의 셀 문장 임베딩 기반 RAG** (사용자 확정, 바꾸지 말 것).
- 폐쇄된 환경 = 외부 API 없이 로컬 모델만 쓴다(로컬 임베딩 + 로컬 Qwen 리더).
- 형식: 한국어 Word(.docx) 약 30쪽. 원고 `thesis/src/*.md`, 그림 `thesis/make_figs.py`(본 방법만 파랑 #2a78d6),
  빌드 `NODE_PATH=<scratch>/thesis/node_modules node thesis/build_docx.js`(docx npm 은 스크래치에 설치).
- 과제 설정: **closed-domain.** 질문과 짝지어진 표(HiTab) 또는 문서(MultiHiertt)가 주어지고 그 안에서 답에 필요한 셀을 검색한다.
  "표를 이미 찾았다"라고 쓰지 않는다.
- 문제 정의: **표를 평평하게 펴면 셀 값이 무엇의 값인지(헤더)가 사라진다.** 이것 하나다.
  "표가 크면 리더 문맥에 안 들어간다"는 **폐기**(2026-09-24 사용자 재확인) — 문제 정의로 쓰지 말 것.
- 주장(2026-09-23 사용자 결정): **고유 라벨을 넣은 셀 문장을 만들어 임베딩하면 정답 셀 검색 정확도가 오른다.**
  셀마다 문장이 서로 달라야 한다는 것은 방법의 정의다(§2.1).
  - "유사도 점수가 오른다"가 아니라 "검색 정확도가 오른다"로 쓴다.
  - 고유 라벨의 이득은 데이터셋이 준 표 제목일 때만 확인됐다. MultiHiertt 처럼 표 직전 문단을 라벨로 쓰면 떨어졌다.
  - 계층 경로의 기여, 질의당 비용(토큰·호출 수)은 주장하지 않는다 — 부록·ablation 으로만.

## 2. 본 방법

### 2.1 셀 문장 — 핵심 정의 (2026-09-13 확정, 2026-09-25 재확인)

**셀마다 문장이 서로 달라야 한다. 그래야 유사도로 셀이 구별된다.**

    문장 = 고유 라벨 + 행 경로 + 열 경로 + 셀 값  →  임베딩  →  색인

- 고유 라벨 = 셀이 속한 표를 구별해 주는 자연어 데이터(데이터셋이 준 표 제목·섹션 제목·페이지 제목).
  판단 기준은 "그 데이터가 셀 문장끼리의 유사도를 구별되게 만드느냐"다.
- 질의가 맞출 수 없는 인위적 식별자(표 번호, 행·열 번호, 문서 id)는 **라벨이 아니다.**
- 검색 범위 안에 같은 문장이 남으면 가른다(MultiHiertt 적용, HiTab 은 §9 결정 대기). 순서: ① 표 안의 글(절 제목 행, 열 윗부분 머리글) ② 위치(`row N`/`column N`)
  ③ 다른 표와 겹치면 `Table k`. ②③은 라벨이 아니라 같은 문장을 가르는 마지막 수단이다 — 결과를 쓸 때 ①과 ②③의 비율을 함께 적는다.
- **MultiHiertt:** 머리글 규칙 **v3.3u**(= v3.3 + 위 고유화, `scripts/mh_arms.py: unique_paths, unique_doc`)가 주 조건이다
  (2026-09-25 사용자 결정, 사전등록 커밋 `dd7be66`). 문서 안 셀 문장 중복이 남으면 코드가 멈춘다.
  v1 결과는 "이전 주 조건"으로만 싣는다. 라벨은 쓰지 않는다(표 직전 문단 라벨이 검색을 낮췄다, `PREREG-2026-09-13-table-label.md`).
- **HiTab:** 템플릿 `sleaf`(s3c 문장 + 행·열 잎 라벨). 라벨 분리 실험은 `s3c` 기준. 문장 틀("In the table …")은 유의한 효과가 없었고
  이득은 라벨 내용에서 온다(`--template s3frame` 분리 실험).

### 2.2 검색과 리더

- 인코더: 기성품 `BAAI/bge-base-en-v1.5`. **학습 없음** — 파인튜닝 인코더 수치는 이 논문의 수치가 아니다.
- 검색기: hybrid(dense + BM25), **α=0.7 고정**(값 자체는 임의 — 코퍼스마다 튜닝하지 말 것).
  색인·계측 모두 전수 내적이다. **"ANN"이라고 쓰지 말 것.**
- 검색 범위: HiTab 은 질문이 속한 표 하나, MultiHiertt 는 질문이 속한 문서(표 여러 개).
- 운영점: 리더에게 주는 셀 **20개**. 올리지 말 것 — 발명신고서에 "상위 20개 셀"이 판정 조건으로 나갔다.
- 리더(데이터셋마다 사전등록으로 정함, 통일하지 않음):
  - HiTab: `Qwen2.5-7B-Instruct` 4bit, neutral 프롬프트, temperature 0.
  - MultiHiertt: `Qwen3-8B` 4bit 비생각 모드, greedy, **cot 프롬프트, 최대 384토큰**(`PREREG-2026-09-13-reader-qwen3.md`).
    생성은 continuous batching `--batch-size 128`(배치 확인 통과, `PREREG-2026-09-24-mh-answer-cap300.md`).
    `answer_accuracy_mh.py` 옛 기본값(neutral/64)으로 돈 결과는 **무효**다.

## 3. 평가 규칙

### 3.1 지표

- **검색 정확도** = 20셀 문맥이 정답 근거 셀을 **전부** 담은 질의 수 / query count. 주 표는 이 운영점 하나.
  - `all`(정답 셀 전부)이 주지표. 답 자체가 헤더인 질의용 `any` 는 기준이 낮으므로 섞지 말고 따로 적는다.
  - recall@k 류는 외부 비교군을 그 방법 고유의 평가로 잴 때 써도 된다(2026-09-20 완화). 주 표에 k 사다리를 올리지 말 것.
  - `정답셀 1등률`은 방법 간 비교 지표로 쓰지 않는다 — 색인 단위 크기에 오염된다.
- **답변 정확도** = EM. HiTab `metrics.hitab_exact_match_text`, MultiHiertt `eval/multihiertt_em.mh_exact_match`(공식 포팅).
  MultiHiertt 정답은 공식 파일에서 읽는다(`bevaya/MultiHiertt` 는 정답을 유효숫자 6자리로 잘라 둠). DocMath 보조 채점은 판정에 쓰지 않는다.
- 표본 크기는 문서에서 **query count** 로 적는다(`n` 금지). 결과 JSON 의 `"n"` 키는 코드가 읽으므로 그대로 둔다.

### 3.2 보고 형태

- 표 두 개: **검색 정확도 표**와 **답변 정확도 표**, 같은 질의·같은 운영점. 리더는 검색이 고른 셀을 그대로 받는다.
- 정답 셀만 넣은 조건은 주지표가 아니다 — 리더 점검용 진단, 부록.
- "표 전체를 리더에 넣기" 비교군을 함께 싣는다.
- 지는 칸도 싣는다. 유리한 쪽만 고르지 않는다.

### 3.3 데이터와 모집단

- **HiTab:** test 만 쓴다(dev·train 은 쓰지 않는다). 주 모집단은 단일 셀 조회(정답 셀 하나). 답변 정확도는 단일 셀 조회만,
  **질문이 속한 표 안에서만 검색한 조건**으로만 보고한다. 산술은 답변 정확도에서 뺀다 — 이유는 범위 결정(2026-09-08)이다.
  **"산술이 적어서"라고 쓰지 말 것.** 산술 검색 정확도는 유형별 표에 그대로 싣는다.
- **MultiHiertt:** train 으로 평가한다(test 는 정답 근거가 없다). validation 은 리더·라벨 파일럿에만 썼다.
  표 근거만 필요한 질문을 조회/산술 × 셀 1개/2개 이상 4그룹으로 나누고 그룹당 상한 300(seed 20260913), 전체는 모집단 비율 가중.
  `interim200` 은 "사후 분석·개발에 사용된 표본"이라 부른다 — dev·unseen test 라 부르지 말 것.
  헤더 규칙을 train 표본을 보고 고친 이력이 있다(`DATA-USE-2026-09-14.md`) — 논문에 명시한다.
- gold 를 못 푸는 질의는 **사유를 붙여 제외하고 개수를 보고**한다. 조용히 분모에서 빼지 않는다.

### 3.4 통계와 해석

- 방법 간 차이는 같은 질의끼리 정확 McNemar. **차이를 발견이라 부르기 전에 반드시 검정한다**(특히 1~2%p).
- 주요 값에 95% CI(MultiHiertt 는 그룹 층화 부트스트랩, `scripts/mh_cap300_report.py`).
- 상관만 보고 기전을 단정하지 않는다. 사후 분석은 사후라고 적는다.

### 3.5 사전등록

- 개입은 **예측을 먼저 커밋하고** 실행한다(`PREREG-*.md`). 결과를 보고 규칙·조건을 고르지 않는다.
- 결과를 본 뒤 추가하는 조건은 "사후 조건"으로 등록하고 따로 보고한다. 실행 중 바뀐 것은 PREREG 에 적는다.
- 사전등록은 결과 전에 커밋한다. 그 밖의 커밋·푸시는 사용자 지시 후.

### 3.6 채점 점검 — 채점 코드를 건드린 세션은 전부 다시 확인

1. 예산 정의가 방법마다 같은가(겹치는 단위가 같은 셀을 두 번 배달할 때 중복을 세지 않는가). `tests/test_arm_fairness.py`.
2. 결과 파일만 보고 명령을 복원할 수 있는가.
3. 같은 코드를 두 번 돌리면 같은 판정이 나오는가(임베딩 캐시를 비우고 재인코딩).
4. gold 해석 두 갈래가 어긋나지 않는가.
5. 제외가 대칭인가 — 사유별 개수를 매번 출력해 대조.
6. 분모와 분자가 같은 질의 집합인가.
7. 좌표 변환 상수를 데이터로 검증했는가.
8. 예산보다 큰 gold 가 있는가.

참고 자료(사용자 지정): <https://wikidocs.net/335602> — 이 환경에서는 열리지 않는다. 사람에게 받아 읽지 못했으면 "참고했다"고 쓰지 않는다.

## 4. 비교군 이름

- `flat` = 우리가 만든 ablation 하한(기존 방법도 baseline 도 아님).
- `chunk` = 업계 관행(발표된 시스템 아님).
- TableRAG(Chen et al. NeurIPS 2024) `tablerag_path`/`tablerag_leaf` = 텍스트 표현은 구글 공식 코드와 대조한 포트, 검색기는
  본 방법과 같은 임베딩 → "구글 TableRAG 시스템 결과"로 인용하지 말 것. `rowcol`·`randrow` = 같은 논문의 비교군.
- `trag_hetero`(Yu et al. 2025) = 청킹 표현만 재현, SQL 경로·전용 검색은 재현 안 함.
- MultiHiertt 비교군 검색 레코드는 머리글 v1 이다. `rowcol`·`tablerag_*` 는 머리글 경로를 쓰므로 본 방법(v3.3u)과 머리글 차이가
  섞인다 — 결과에 적는다.

- "HiTab 은 산술이 적어서 뺐다" → 범위 결정.
- "산술 병목은 리더다" — neutral/64 설정의 산물일 수 있다.
- HiTab 에서 본 방법이 chunk 보다 답변이 유의하게 낫다 — 유의하지 않았다.
- LLM 필터링 .82 — 출처 없음. 공정 필터링 결과(`PREREG-2026-09-21-fair-llm-filtering-hitab.md`)는 부록.
- "필터 비용(토큰)이 큰 청크에 불리하다" — 실측이 반대다.
- MultiHiertt 답변 중 neutral/64 결과 전부, `results/K_LADDER_TABLES-2026-09-16.md` 의 수치(538표 한 색인 조건),
  HiTab 산술 필터링 노선(모집단 결함으로 폐기), `SUMMARY_TABLES-2026-09-18.md` §1.
- "본 방법이 MultiHiertt 조회에서 지는 이유는 한 행이 문장 여러 개로 흩어져서" — 틀린 설명이다(2026-09-25 확인).
  실제로 관찰된 것은 값만 다르고 문장이 같은 셀이다(`PREREG-2026-09-24-mh-answer-cap300.md` 끝).
- RealHiTBench·AIT-QA 수치 — gold 를 답 문자열로 복원해 오염됐다. 이 논문에 쓰지 않는다.
- 파인튜닝 인코더 수치, 옛 지표(`all-covered@k`, `setEM@k`, OSC)로 낸 수치.

## 6. 닫힌 노선 — 다시 제안하지 말 것

## 7. 실행 운영

- 오래 걸리는 실행은 `setsid nohup` 으로 떼어 돌리고, 진행은 로그·`*.jsonl` 줄 수로 본다.
- **`pkill -f <패턴>` 금지** — 자기 셸 명령줄과 맞아 셸을 죽인다(3번 발생). PID 로 kill.
- 파이프 뒤 `$?` 를 믿지 말 것 — `${PIPESTATUS[0]}` 와 결과 파일을 같이 본다.
- 결과 파일을 덮어쓰지 않는다. 새 실행은 새 `--out`. 답변 실행은 `--resume` 으로만 이어 쓴다(실행 조건이 다르면 멈춘다).
- 8GB GPU 를 Windows 쪽 프로그램과 나눠 쓴다 — 느려지거나 `CUDA unknown error` 가 나면 그 실행을 같은 설정으로 이어 돌린다.
- PC 가 꺼지거나 절전이면 WSL 실행이 멈춘다. 밤 실행 전 사용자에게 켜 두라고 알린다.

## 8. 사용자와 소통

- 한국어로, 짧게, 핵심만. 결정 요청은 쉬운 말 두세 줄 + 실제 예시 하나.
- 비유 금지 — 계산식·실측 숫자·조건으로 설명한다.
- 플래그 이름(`gold corpus`, `split corpus` 등)을 그대로 쓰지 말고 검색 범위를 뜻으로 풀어 쓴다(예: "질문의 표 안에서만 검색").
- 채팅에는 수치와 결정을 적고 결과 파일 경로는 생략한다.
- 모르는 것·확인 안 한 것·틀렸던 설명은 그대로 말한다.

# 논문 중간 정리 (2026-09-23)

이 문서는 2026-09-23 세션에서 사용자와 확정한 논문 스토리와 지금까지의 수치를 한곳에 모은다.
`CLAUDE.md` §0.2(정답 셀 조건 필수), §2(차별점 = 질의당 비용), §3(모든 종류의 쿼리)와 어긋나는
부분은 이 문서가 대체한다. 수치의 원본 파일은 §10.

## 1. 제목과 설정

- 제목: **폐쇄된 환경에서 계층형 표 구조의 셀 문장 임베딩 기반 RAG** (사용자 확정)
- 폐쇄된 환경: 외부 API 없이 로컬 모델만 쓴다 — 로컬 임베딩(`BAAI/bge-base-en-v1.5`) + 로컬 Qwen 리더.
- 과제 설정: **closed-domain**. 질문과 짝지어진 표(HiTab) 또는 문서(MultiHiertt)가 주어지고,
  그 안에서 답에 필요한 셀을 검색한다. 다른 논문과 같은 설정을 쓰려는 것이지 차별화가 아니다.
  - "표를 이미 찾았다"는 표현은 확인한 11편 어디에도 없다. 쓰지 않는다.
  - 근거 문장(원문 인용 확인):
    - Zhou et al. 2025 서베이(arXiv 2510.09671): "closed-domain setting where target inputs are given directly", HiTab 을 이 설정의 예로 든다.
    - HiTab(Cheng et al., ACL 2022): "given a hierarchical table t and a question x in natural language, output answer y."
    - ITR(Lin et al., ACL 2023, 2023.acl-long.551) §3.1: "find one or more sub-tables Tsub containing the most relevant information from T needed to answer q; Tsub can replace T as the input to virtually any existing TableQA system."
  - 논문 문장 초안: "We adopt the closed-domain setting, in which the table (HiTab) or document (MultiHiertt) paired with a question is given directly; retrieval finds the cells containing the information needed to answer the question, and the top-20 cells replace the table as the reader input."
  - 표 안 셀 검색 단계의 이름은 논문마다 다르다: "cell retrieval"(TableRAG, Chen et al. NeurIPS 2024), "inner table retriever"(ITR), "table sampling"(TAP4LLM).

## 2. 문제 정의

- 표를 평평하게 펴면 셀 값이 무엇의 값인지(헤더)가 사라진다.

"표가 크면 리더 문맥에 다 들어가지 않는다"는 문제 정의에서 **폐기**했다(사용자, 2026-09-24 재확인).
실측도 이를 뒷받침하지 않는다 — 표 전체 토큰 수(리더 토크나이저, `results/table_token_lengths.json`):
HiTab 질문의 표 중앙 627·최대 5,190(본 방법 20셀 문맥 중앙 1,264), MultiHiertt 질문 문서의 표 전부 중앙 1,321·최대 5,190
(20셀 문맥 중앙 522). 둘 다 리더 문맥 32K 안에 전부 들어간다. 이 수치는 "표 전체" 비교군의 실행 가능성 판단에만 쓴다.

## 3. 주장

**고유 라벨을 넣은 셀 문장을 만들어 임베딩하면 정답 셀 검색 정확도가 오른다.**

- "유사도 점수 상승"이 아니라 "검색 정확도 상승"으로 쓴다 — 라벨은 같은 표의 셀 전부의 점수를 함께
  올리므로 점수 자체는 증거가 되지 않는다.
- 고유 라벨 = 데이터셋이 준 표 제목류(HiTab: 섹션 제목 + 페이지 제목).
- **조건이 붙는다:** MultiHiertt 처럼 표 제목이 없어 표 직전 문단을 라벨로 쓰면 검색 정확도가 떨어졌다(§6.5).
  논문에는 "데이터셋이 준 표 제목이 있을 때"로 범위를 적는다.
- 계층 경로의 기여는 이 논문의 주장이 아니다.
- 질의당 비용(토큰 수·모델 호출 수)은 주장하지 않는다. 관련 수치는 부록/ablation 으로만.

## 4. 방법

```
셀 → 문장(고유 라벨 + 행 헤더 경로 + 열 헤더 경로 + 값) → bge-base-en-v1.5 임베딩(학습 없음)
   → 질문이 속한 표/문서 안에서 hybrid 검색(dense + BM25, α=0.7) → 상위 20셀 → 로컬 Qwen 리더
```

- HiTab 본 방법 템플릿은 `sleaf`(s3c 문장 앞에 행·열 잎 라벨을 붙인 것). 라벨 분리 실험은 `s3c` 기준으로 했다.
  둘은 표 안 검색에서 구별되지 않는다: .9586 대 .9637, 7:12, p=.36 (query count=991).
- MultiHiertt 본 방법은 **라벨 없이** 돈다(헤더 v1, 라벨 none) — §6.5 결과 때문.
- 리더는 데이터셋마다 사전등록으로 정한 설정을 쓴다. 논문에 둘 다 적는다.
  - HiTab: `Qwen2.5-7B-Instruct` 4bit, neutral 프롬프트, temperature 0.
  - MultiHiertt: `Qwen3-8B` 4bit 비생각 모드, greedy, cot 프롬프트, 384토큰
    (`PREREG-2026-09-13-reader-qwen3.md` 선택, `PREREG-2026-09-23-reader-thinking-pilot.md` 에서 생각 모드는 시간 가드 초과로 제외).

## 5. 실험 설계

### 5.1 데이터

| | HiTab | MultiHiertt |
|---|---|---|
| 분할 | test (1,584 질의, 채점 1,581, 제외 3건 사유 명시) | train (test 는 정답 근거 없음) |
| 검색 범위 | 질문이 속한 표 1개 | 질문이 속한 문서(평균 표 4.06개 = 11,793/2,908) |
| 모집단 | 단일 셀 조회 991 | 표 근거만 필요한 질문 2,908, 채점 2,871 (텍스트 근거 필요 4,922 제외) |
| 답변 정확도 대상 | 단일 셀 조회만 | 4그룹 전부 |

- **HiTab 산술(216건)은 답변 정확도에서 뺀다.** 이유는 2026-09-08 범위 결정("정답 셀이 하나인 조회만 본다")이다.
  **"산술이 적어서"라고 쓰지 말 것** — 216건은 MultiHiertt 단일산술 71건보다 많다. 산술은 MultiHiertt(2,295건)로 다룬다.
  HiTab 산술의 검색 정확도는 유형별 표에 그대로 싣는다.
- MultiHiertt 데이터는 비공식 재포장본 `bevaya/MultiHiertt` 이고 정답은 공식 파일에서 읽는다(커밋 7551b15, 재포장본은 답을 유효숫자 6자리로 잘라 둠).
- MultiHiertt 헤더 규칙은 train 표본(interim200)을 보고 고친 적이 있다 — `DATA-USE-2026-09-14.md` §5. 논문에 명시한다.

### 5.2 MultiHiertt 그룹 (조회/산술 × 답에 필요한 셀 1개/2개 이상)

| 그룹 | 전체 | 상한 300 적용 |
|---|---:|---:|
| 조회, 셀 1개 | 211 | 211 |
| 조회, 셀 2개 이상 | 365 | 300 |
| 산술, 셀 1개 | 71 | 71 |
| 산술, 셀 2개 이상 | 2,224 | 300 |
| 합계 | 2,871 | 882 |

- 조회/산술 구분(program 유무)은 공식 `question_type` 과 100% 일치한다.
- 전체 정확도 = 그룹별 정확도를 모집단 비율로 가중(TableBench, Wu et al. AAAI 2025 방식). 상한으로 잘랐으므로 단순 평균은 쓰지 않는다.
- 전수를 쓰는 그룹은 표본 오차가 없다. 전체 95% CI 는 본 방법 현재 값 기준 약 ±3.6%p.
- 그룹별 값은 query count 와 함께 보조 표에 둔다.

### 5.4 지표와 통계

- 검색 정확도 = 예산 20셀 안에 정답 근거 셀이 전부 든 질의 수 / query count. 주지표는 이 운영점 하나.
- 답변 정확도 = EM. HiTab `hitab_exact_match_text`, MultiHiertt 공식 `evaluate.py` 갈래.
- 방법 간 차이는 같은 질의끼리 McNemar. 주요 값에 95% CI.
- 정답 셀만 넣은 조건은 주지표가 아니다. 리더 점검·상한 확인용 진단으로 부록에.
- 표본(부분집합) 평가 선례(원문 확인): Deng et al. 2024(arXiv 2402.12424) 100건 + McNemar 등 검정,
  Wang et al. 2026(arXiv 2603.15402) 500건 + 부트스트랩 CI, TableLlama(NAACL 2024) 500건, RealHiTBench(Findings ACL 2025) 500건.
  seed 공개·부분집합 대 전체 비교를 한 선례는 찾지 못했다 — 할 수 있으면 선례보다 강한 근거다.

### 6.4 MultiHiertt 답변 정확도 — **기존 값 무효, 재실행 필요**

- 원인: 기존 답변 실행 15개(전수, 7개 방법 299건, 예산 사다리, 정답 셀만)가 채택 설정(cot/384)이 아니라
  neutral 프롬프트("설명 없이 답만") + 64토큰으로 돌았다. 산술 예측의 48.6%가 계산값 대신 피연산자를 쉼표로 나열했다.
- 채택 설정 재실행 683건(전수 실행 중 중단, 같은 질의 비교):

| 그룹 | query count | neutral/64 | cot/384 | McNemar |
|---|---:|---:|---:|---|
| 산술 셀 2+ | 530 | .0132 | .2623 | 136:4, p=2.3e-35 |
| 산술 셀 1개 | 15 | .1333 | .3333 | 3:0, p=.25 |
| 조회 셀 1개 | 54 | .5370 | .5741 | 6:4, p=.75 |
| 조회 셀 2+ | 84 | .4048 | .4762 | 14:8, p=.29 |

- cot/384 에서 산술 545건의 남은 오답: 그 외 오답 35.6%, 검색 실패 16.9%, 형식만 다름 13.8%(퍼센트 100배 표기 등),
  정답이 음수라 공식 규칙상 못 맞힘 4.6%, 384토큰 안에 최종 답 없음 2.8%. 정답 26.4%.

### 6.6 MultiHiertt 조건 셀 누락 규모 (2026-09-24, 표본 검토 추정)

- 정답 근거(`table_evidence`)가 계산 피연산자만 담고, 조건 판정 셀("Outstandings 가 가장 낮은 해의 X 증가율"에서 Outstandings 행,
  "가장 큰 해는?"에서 비교 대상 셀)을 빼는 문항.
- 방법: 조건 표현 정규식(highest/largest/most/greater than/when/which 등)으로 2,871 을 나눔(표시 888 / 미표시 1,983),
  표시 40 + 미표시 60 을 seed 고정 무작위로 뽑아 질문·program·근거 좌표를 직접 읽고 판정(`results/mh_condition_cell_audit_20260924.jsonl`).
- 결과: 표시 20/40 누락(판정 불가 3), 미표시 7/60 누락 → 추정 888×.50 + 1,983×.117 ≈ **675건(23.5%)**, 대략적 95% 범위 15~36%.
- 그룹별 모양: 조회 셀 1개의 표시 문항은 검토한 6/6 이 누락(최상급 질문인데 근거가 답 셀 1개) → 이 그룹 211 중 표시 138(65%)이 누락 후보.
  조회 셀 2개 이상은 표시 문항 대부분이 비교 행 전체를 근거로 담아 누락이 적다(2/16, 판정 불가 3). 산술 셀 2개 이상은 표시 12/18, 미표시 7/59 누락.
- 이 누락은 모든 방법에 같은 정의로 적용된다. 행·청크 단위 방법은 조건 셀을 같은 행에서 함께 가져올 수 있어, 셀 단위인 본 방법의
  검색 우위가 이 문항들에서 과대일 수 있다. **답변 정확도는 리더가 조건 셀을 실제로 받았는지까지 반영하므로 이 영향을 포함한다.**

### 6.5 MultiHiertt 라벨 — 검색 정확도 하락 (사전등록 2026-09-13)

- 라벨 = 표 직전 문단 문장(L1). 문서 안 검색 .8495 → .8304 (117:172, p=.0014),
  여러 문서 한 색인 .2654 → .2264 (160:272, p=7.9e-8).
- HiTab 의 "생성 제목을 붙이면 떨어진다"(`CLAUDE.md` §5)와 같은 방향: 이득은 데이터셋이 준 이름의 내용에서 온다.

## 7. 2026-09-23 결정 사항

1. 주장 = 고유 라벨 셀 문장 → 검색 정확도 상승 (§3).

3. 질의당 비용 주장 제외 → 부록.

## 8. 쓰면 안 되는 서술

- "표를 이미 찾았다" → "closed-domain 설정".
- "유사도 점수가 오른다" → "검색 정확도가 오른다".
- "HiTab 은 산술 질의가 적어서 뺐다" → 범위 결정으로.
- "고유 라벨은 항상 오른다" → 데이터셋이 준 표 제목일 때만(§6.5).
- MultiHiertt 답변 정확도 기존 값(조회 .4787 등, 산술 .0121 등) — 무효(§6.4).
- "산술 병목은 리더다" — neutral/64 설정의 산물일 수 있다.
- 본 방법이 chunk 보다 답변에서 유의하게 낫다(HiTab) — p=.050.
- LLM 필터링 .82 — 출처 없음.

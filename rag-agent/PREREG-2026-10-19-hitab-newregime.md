# 사전등록: HiTab 300 을 새 설정으로 다시 측정 — LangChain 청크(A) 대 셀 문장 목록(C) 대 채운 부분 표(D), 3회 실행 (2026-10-19, 실행 전)

## 왜
- MultiHiertt 882 에서 채운 부분 표(D)는 LangChain(A)보다 약 3%p 앞선다(PREREG-2026-10-18-D-vs-A-replication.md). 이 차이가 다른 데이터셋(HiTab: 계층 머리글 표, 단일 셀 조회)에서도 나는지, 크기가 다른지 본다. 예전 HiTab 답변 결과(본 방법 215 대 청크 187, 538표 한 색인)는 검색 범위가 달라 지금 조건과 비교할 수 없다.
- 조건 원칙은 MultiHiertt 와 같다: 질문의 표 하나 안에서, 같은 지시문·같은 LLM·같은 토큰 수(T = LangChain 4청크 토큰), 4,096 토큰 상한(PREREG-2026-10-19-prompt-table-rule.md 에서 표준 채택).

## 고정 조건
- 문항: HiTab test 300(`results/ksweep_population_300.json`, 시드 42, 단일 셀 조회).
- 검색: 표 안 s3c 셀 문장, α0.7, 상위 100(`results/hitab_newregime_20261019/retrieval/`, CPU 재실행, 넘침 0).
- 입력(`build_hitab.py`, 실행 전 생성·커밋): A = 표 전체 markdown(markdown_source, 제목 포함) → RecursiveCharacterTextSplitter(1,000자, 겹침 200) → bge-base 코사인 상위 4개(표당 청크 평균 2.30, 281/300 은 4개 이하라 **표 전체**가 들어감); C = 셀 문장 순위대로 T 까지; D = 순위대로 셀을 더해 행×열 교차 칸을 채운 부분 표("Table: 제목", 머리글 경로 라벨), T 까지. 값 표기는 C·D 모두 자료 행렬 값(80.0)이고 A 는 원문(80)이다 — 채점 함수가 1557.0 ↔ 1,557 을 같게 봄을 확인했다.
- 정답 셀 포함: A 300 / C 280 / D 299. 전달 셀 평균 117.5 / 17.2 / 99.0. 입력 토큰 평균 961 / 931 / 822.
- LLM Qwen3.5-4B bf16, vLLM greedy 비생각, 지시문 R0X1F1B2D1C1E0(P* 에서 역할 문장만 원문 R0; R1 "재무 분석가"는 재무 표 전용이라 뺌 — 세 팔 동일), 최대 4,096 토큰(`--max-model-len 8192`), 실행 3회(동시 32/24/16).
- 채점 `score_hitab.py`: 마지막 Final answer 줄(굵은 라벨 허용)에 정답 목록 원소가 모두 포함(형식 허용 v2), 보조 = 공식 HiTab EM. 판정 = 3회 다수결 McNemar(882 반복 실행과 같은 규칙).

## 판정 규칙(결과 전 고정)
- 주 비교 D 대 A(다수결). **"HiTab 에서도 D > A" 는 세 실행 모두 D > A 이고 다수결 McNemar p < .05 일 때만 쓴다.** 아니면 "HiTab 에서는 차이가 우연 범위"로 쓴다.
- 보조: D 대 C, C 대 A. 이 실험으로 고르는 설정은 없다(선택 없음).

## 예측(확률; 실행 전 고정)
- A(표 전체가 94% 들어감) 정확도 70~88%: 75%.
- D − A(다수결): [−10, +15] 안 70%; D > A 55%; +15(5%p) 이상 20%; +30(10%p) 이상 7%; **판정 규칙 충족 25%.**
- C < A: 75%(정답 셀 빠진 20건 + 문장이 길어 셀 17개뿐); C − A ≤ −10: 50%. D > C: 80%.
- 잘림 팔당 ≤ 9건(3%): 70%.
- 근거: MultiHiertt 에서 셀 1개 문항은 D ≈ A(153 대 154)였고 HiTab 300 은 전부 셀 1개 문항이다. D 가 유리할 여지는 행 머리글 계층(들여쓰기)이 markdown 에서 사라지는 큰 표뿐이다.
- 빗나가면 그대로 적는다.

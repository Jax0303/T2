## 개입과 arm

문맥·검색·예산·채점기·리더는 실험 1 과 전부 동일하다. 바뀌는 것은 출력 형식뿐이다.
조건 대조란, 번호나 값을 내기 전에 **질문이 요구하는 표·행·열 조건을 적고 후보 줄을
그 조건에 맞춰보게** 하는 것이다.

    BASE  기존 자유 생성 (프롬프트·max_new_tokens 64 그대로)   ← 필수 비교 기준
    C0b   실험 1 그대로(p1, 조건 대조 없음) + max_new_tokens 256  ← 길이 효과 분리
    A     조건 대조 후 → `Answer: [#n]` (셀 ID 출력, 값은 코드가 반환)
    B     조건 대조 후 → `Answer: <값>` (리더가 값을 직접 출력)

**A 와 B 의 대조가 이 실험의 핵심이다.** 둘은 앞부분(조건 대조)이 글자 그대로 같고
마지막 줄만 다르다. 따라서

    B - BASE   = 조건 대조 자체의 효과 (출력 방식은 둘 다 값)
    A - B      = ID 출력 방식의 영향 (조건 대조는 둘 다 있음)

로 분리된다. 실험 1 은 이 둘을 합친 것만 보았다.

## 채점·파싱 규칙 (실행 전 고정)

- A: 마지막 `Answer:` 줄에서 첫 `[#n]`/`[n]`/`#n`. `Answer:` 가 없으면 출력 전체의
  마지막 ID. 그래도 없으면 **빈 예측 = 오답**. 복수 ID 는 등장 순으로 값을 `", "` 로 잇는다.
- B: 마지막 `Answer:` 뒤 텍스트. `Answer:` 가 없으면 출력 전체.
- C0b: 실험 1 의 `bracket_bare` 규칙 그대로.
- **기권은 오답이다.** `Answer: none`, "문맥에 없음" 등은 빈 예측으로 채점하며
  **문항을 분모에서 빼지 않는다.** 정답을 이용한 fallback(오답일 때 다른 arm 으로
  갈아타기)은 **금지**한다. 어떤 arm 도 다른 arm 의 결과를 참조하지 않는다.
- gold 정답·좌표·정답 개수·실패 유형은 예측에 쓰지 않는다. 사후 분해에서만 쓴다.
- oracle(여러 실행 중 맞는 것 고르기) 수치를 EM 으로 보고하지 않는다.

## 게이트 — test 로 넘어가는 조건 (실행 전 고정)

홀드아웃 주지표 602문항에서, **A 또는 B 가 같은 문항의 BASE 대비**

    (1) EM 이 최소 +0.02 높고
    (2) paired 차이의 95% 신뢰구간 **하한 > 0**

**둘 다** 만족할 때만 test 를 돌린다. C0b 대비 개선은 기전 분석용이며 게이트가 아니다.
신뢰구간은 paired bootstrap B=10,000, seed=42. McNemar exact p 도 함께 보고한다.
arm 이 둘(A, B)이므로 Holm 보정한 p 를 함께 싣는다.

중단 조건: **형식 파손율 > 5%** 인 arm 은 장치 결함으로 보고 그 arm 의 EM 개선을
주장하지 않는다. EM 보다 먼저 본다.

**통과하지 못하면**: 추가 프롬프트 탐색을 하지 않고 test 를 돌리지 않는다.
`results/cell_id_v3/VERDICT.md` 에 **"조건 대조 방식의 실패"** 로 기록하고 끝낸다.

# 사전등록 — 파인튜닝 인코더 위에서 hybrid α 재조정

작성 2026-09-02, 실행 전. 선행 `PREREG-2026-09-01-neg-cross-sweep.md`,
`results/rank_ft/SWEEP.md`, `results/rank_ft/x0/VERDICT.md`.

## 무엇을 묻는가

hybrid 점수는 `α·minmax(dense) + (1−α)·minmax(BM25)`이고 α=0.7은 **기성품 인코더
위에서** 고른 값이다 (`results/retrieval_to_90_verdict.json` §α sweep). 그 인코더를
갈아끼웠으므로 0.7이 더는 최적이라는 보장이 없다. **학습 없이, 색인 한 번으로 잰다.**

모델은 dev에서 선택된 `models/bge-cell-ft-x0` (형제만, `--neg-cross 0`) 하나로 고정한다.

## arm

α ∈ {0.0, 0.3, 0.5, 0.6, **0.7**, 0.8, 0.9, 1.0}. 0.0 = BM25 전용, 1.0 = dense 전용,
0.7 = 현행. 나머지 전부 고정 (S3c, `hitab_dev_lookup_all`, 같은 코퍼스).

## 계측기와 그 통제

`analysis/alpha_retune.py` — 색인을 **한 번만** 짓고 질의당 dense/BM25 점수를 한 번
계산해 α만 바꿔 정렬한다. `cell_rank_dump.py`를 여러 번 돌리는 것과 산술이 같아야 하므로
**α=0.7 칸이 `results/rank_ft/x0`의 setEM@10 .9072를 재현하는지**를 통제로 건다.
재현하지 않으면 스윕 전체를 폐기한다.

## 선택과 확정 (실행 전 고정)

1. 선택은 `hitab_dev_lookup_all` (n=830) setEM@10 하나로만. test는 선택에 안 쓴다.
2. 동점이면 **0.7에 가까운 쪽** (현행 유지가 기본값).
3. 선택된 α 1개로만 `hitab_test_lookup_all` + `hitab_test_lookup_multi`를 **1회**.
4. **목표 도달** = 선택된 α의 test setEM@10 ≥ **.90**.
5. 주검정: 선택 α vs α=0.7, 830건 페어드 exact McNemar 양측 α=.05.
6. 8개 α 전부의 전 지표를 표에 넣는다. `hitab_dev_lookup_multi`도 전 α에서 돌리되
   선택에는 안 쓴다 (n=33).
7. 음수여도 그대로 보고한다.

## 예측 (실행 전 커밋)

`hitab_dev_lookup_all` setEM@10. α=0.7은 실측(.9072)이라 예측하지 않는다.

| α | 예측 (점) | 예측 구간 |
|---:|---:|---|
| 0.0 (BM25 전용) | **.700** | .62 – .78 |
| 0.3 | **.880** | .85 – .905 |
| 0.5 | **.898** | .88 – .915 |
| 0.6 | **.905** | .89 – .918 |
| 0.7 | (.9072 실측) | — |
| 0.8 | **.912** | .900 – .925 |
| 0.9 | **.908** | .895 – .922 |
| 1.0 (dense 전용) | **.900** | .88 – .920 |

- **dev 최적 α**: **0.8**로 예측한다 (차점 0.9). 인코더가 강해졌으므로 최적점이
  dense 쪽으로 **올라간다**는 것이 이 개입의 가설이다.
- **0.7 대비 최적 α의 델타**: **+.005** (구간 −.002 – +.015). 작은 값을 예측한다.
- **선택 α의 test setEM@10**: **.875** (구간 .855 – .895) → 목표 .90 **미달로 예측한다.**

## 미리 적어두는 교란 요인

- 8개 α가 **같은 dev에서 골라진다.** 최댓값은 위로 편향된다. test 1회가 유일한 장치.
- 인코더 선택(x0)도 dev에서 골랐다. dev 편향이 **두 겹**이다.
- α는 minmax 정규화 위에서 정의된다. 정규화는 전체 점수 벡터 기준이라 후보를 자르면
  값이 바뀐다 — 이 스윕은 자르지 않는다.
- `--mine-topk`, `--neg-per-query`, epoch/lr는 이번에도 스윕하지 않는다.

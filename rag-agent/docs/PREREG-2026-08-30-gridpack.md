# 사전 등록 — `gridpack`: 순위는 그대로, 렌더링만 공유

등록 2026-08-30. 실행 전 작성. 결과를 보고 이 문서를 고치지 않는다.

## 무엇을 바꾸나

**색인 단위와 순위는 손대지 않는다.** `cell` arm과 **동일한** S3c 셀 인덱스, 동일한
hybrid α=0.7 랭킹, 동일한 `c_order`. 바뀌는 것은 admit된 셀 집합을 문맥에 **쓰는 방식**
하나뿐이다.

현재(`cell`): 셀마다 자기 완결 문장 — 표 제목 + 행 경로 + 열 경로 + 값을 매번 다시 쓴다.
`gridpack`: 같은 셀들을 표별로 모아 제목 1회, 열 경로 1회, 행 경로 1회씩만 쓴다.

```
[T] <표 제목>
[C1] <열 경로 1>
[C2] <열 경로 2>
<행 경로 a> :: C1=<값> ; C2=<값>
<행 경로 b> :: C2=<값>
```

경로 정보는 하나도 버리지 않는다(무손실). OSC 집계는 admit된 `(tid,i,j)` 집합 그대로라
`cell`과 정확히 짝지어진다.

## 왜 이것인가 (측정된 병목)

`results/osc_rank_mechanism.json` — MultiHiertt, 예산 512, α=.7, n=399, OSC .6065.

- 예산이 admit하는 셀 수: **중앙값 29개** (min 9 / max 54)
- 실패 157건의 max(gold rank): ≤50 20.4% / ≤100 38.9% / ≤200 **55.4%** / ≤500 70.1%,
  **중앙값 152**

랭커는 실패 건의 절반 이상에서 gold 셀을 이미 top-200에 넣어 두었고, 예산은 29개만 산다.
따라서 남은 레버는 순위가 아니라 **셀당 토큰 단가**다.

정적 압축비(코퍼스 전수, 표 전체 기준 상한):

| dataset | 문장 tok/cell | 격자 tok/cell | R_static |
|---|---|---|---|
| hitab | 38.19 | 6.74 | 5.66 |
| multihiertt | 19.19 | 8.45 | 2.27 |
| aitqa | 19.36 | 9.13 | 2.12 |
| realhitbench | 30.83 | 7.84 | 3.93 |

R_static은 **상한**이다. 실제로는 표당 2~10개 셀만 admit되므로 공유가 덜 일어난다.

## 예측 (숫자)

### 1. 실현 압축비 R_real (admit된 셀 수의 배수, `cell` 대비)

| dataset | budget | 예측 R_real |
|---|---|---|
| hitab | 1024 | 2.0 ~ 3.5 |
| multihiertt | 512 | 1.3 ~ 1.9 |
| aitqa | 512 | 1.2 ~ 1.7 |
| realhitbench | 512 | 1.6 ~ 2.8 |

HiTab이 가장 크다: 문맥에 든 표가 2.88개뿐이라 표당 셀이 많고, 제목이 길어 중복 비용이 크다.
AIT-QA가 가장 작다: 표가 9.7개로 흩어져 공유할 상대가 적다.

### 2. OSC

MultiHiertt 512는 랭크 파일에서 **정확히** 계산된다 — `max(gold rank) < cutoff × R`:

| R | 1.2 | 1.5 | 2.0 | 2.5 | 3.0 | 4.0 |
|---|---|---|---|---|---|---|
| OSC | .6391 | .6817 | .7068 | .7293 | .7494 | .7744 |

예측 R_real 1.3~1.9 → **MultiHiertt 512 OSC .64 ~ .70** (현재 .6115).

나머지 셋은 랭크 파일이 없어 R과 현재 OSC로부터의 구간 예측이다:

| dataset | budget | 현재 cell OSC | 예측 gridpack OSC |
|---|---|---|---|
| hitab | 1024 | .8819 | **.90 ~ .94** |
| multihiertt | 512 | .6115 | **.64 ~ .70** |
| aitqa | 512 | .6519 | **.67 ~ .72** |
| realhitbench | 512 | .4026 | **.44 ~ .52** |

### 3. 반드시 성립해야 하는 것 (아니면 버그)

- `gridpack`의 `n_tables` ≥ `cell`의 `n_tables` (셀이 더 들어가므로 표도 같거나 늘어난다)
- `gridpack`의 실제 렌더링 토큰 수 ≤ 예산 (초과하면 공정 비교가 아니다)
- `flat` arm의 수치가 `cell` 실행 때와 **바이트 동일** (짝지음 대조, §7)

### 4. 기각 조건

`gridpack` OSC가 `cell`보다 어느 데이터셋에서도 유의하게 높지 않으면 기각한다.
"토큰 단가가 병목"이라는 진단이 틀린 것이므로, 남은 병목은 랭킹으로 되돌아간다.

### 5. 이 실험이 판정하지 않는 것

**답변 EM은 여기서 판정하지 않는다** (CLAUDE.md §3: 1단계 판정은 검색 지표).
`group` arm이 OSC는 올리고 EM은 안 움직인 전례가 있다. 문맥이 격자로 바뀌면 리더가
`C1=` 참조를 풀어야 하고, 그 비용은 3단계에서 따로 잰다.

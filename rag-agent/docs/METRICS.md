## 1. 기호

| 기호 | 뜻 |
|---|---|

## 2. 검색 지표 (RAG) — 리더 없음

### 2.1 주지표 `all-covered@k` — "정답 셀이 전부 들어왔나, YES or NO"

```
all-covered@k = (1/n) · Σ_q [ G_q ⊆ R_q(k) ]
              = (1/n) · Σ_q [ max_{c ∈ G_q} rank_q(c) ≤ k ]
```

정답 셀을 **하나라도 빠뜨리면 0** 이다. 부분 점수가 없다. `m_q = 1` 인 조회 질의에서는
"정답 셀이 상위 k 안에 있나"와 정확히 같은 값이고, `m_q ≥ 2` 부터 다른 지표와 갈라진다.

이 지표를 주지표로 쓰는 이유는 §4 에 있다 — **리더가 답을 맞히려면 셀이 전부 필요하기 때문**이다.
셀이 하나라도 빠졌을 때 리더가 맞히는 비율(`λ@k`, §3.5)은 산술에서 0.00~0.05 로 측정됐다.

⚠️ **`k` 는 고정 예산이어야 한다.** `k = c·m_q` 처럼 `m_q` 에 비례해 늘리면 gold 셀 개수를 알아야 하므로
**오라클**이 된다 (`VERDICT_METRIC.md` §3). 주지표는 `k = 20` 고정이다 — `m_q` 의 최대가 dev 12 / test 11
이라 `k < 12` 면 정의상 못 맞히는 질의가 생기고, 20 은 등록된 사다리 `(1,3,5,10,20,50)` 에서 12 이상의
가장 낮은 칸이다. 사전등록(`PREREG-2026-09-06-cell90.md`)의 판정 지표는 `@10` 이고 그건 안 바꾼다.

### 2.2 문헌 표준 지표 (같은 순위, 채점 규칙만 다름)

```
hit@k       = (1/n) · Σ_q [ |G_q ∩ R_q(k)| ≥ 1 ]                     (하나라도 들어오면 1)
Recall@k    = (1/n) · Σ_q  |G_q ∩ R_q(k)| / m_q                       (덮은 비율, 부분 점수)
Precision@k = (1/n) · Σ_q  |G_q ∩ R_q(k)| / k
F1@k        = (1/n) · Σ_q  2·|G_q ∩ R_q(k)| / (k + m_q)
MRR         = (1/n) · Σ_q  1 / min_{c ∈ G_q} rank_q(c)                (첫 정답 셀만 본다)
R-Prec      = (1/n) · Σ_q  |G_q ∩ R_q(m_q)| / m_q                     (컷오프를 질의마다 k = m_q)

nDCG@k      = (1/n) · Σ_q  DCG_q(k) / IDCG_q(k),   이진 관련도
  DCG_q(k)  = Σ_{c ∈ G_q, rank_q(c) ≤ k}  1 / log2(rank_q(c) + 1)
  IDCG_q(k) = Σ_{i=1}^{min(m_q, k)}       1 / log2(i + 1)
```

**표 단위 지표** (진단용, `analysis/stage1_board.py`):

```
표@k        = (1/n) · Σ_q [ gold 표 ∈ 상위 k 표 ]      (셀 순위를 표로 투표해 얻은 표 순위)
셀|표@k     = (1/n) · Σ_q [ G_q ⊆ R_q^{gold 표}(k) ]   ⚠️ 오라클 (gold 표를 맞혔다고 가정)
표@1 × 셀|표@k                                          실제 2단계 캐스케이드 (오라클 아님)
```

### 2.3 엄격도 순서 — 비교의 방향을 정하는 부등식

같은 순위·같은 `k` 에서 항상

```
all-covered@k  ≤  Recall@k  ≤  hit@k
```

(`G ⊆ R_k` 이면 `|G∩R_k|/m = 1` 이고, `|G∩R_k|/m ≤ 1 ≤ [|G∩R_k| ≥ 1]` 이 `|G∩R_k| ≥ 1` 일 때 성립.)
`m_q = 1` 이면 **셋이 정의상 같은 값**이다 (`R-Prec` 도 `k=m=1` 이라 정답셀 1등률과 같다).
그래서 지표가 갈라지는 것은 다중·산술뿐이고, **그 간격이 곧 관대한 지표가 가리는 불완전성**이다.

### 2.5 이 지표들로 **하면 안 되는** 것

- **`Precision@k` 를 싣기** — `m ≤ k` 이면 `Recall@k · m/k` 라 질의 단위로 새 신호가 없고, 상한이 `m/k`
  라서 `m=1` 조회는 어떤 검색기로도 `@20` 에서 .05 를 못 넘는다.
- **`@1`·`@3` 을 산술·다중의 검색 성능으로 읽기** — `m > k` 면 정의상 0 이다. dev 산술 `@1` 은 167건 중
  **132건이 정의상 0**, `lookup_multi @1` 은 항상 정확히 0.
- **`m > k` 질의를 분모에서 빼기** — 열마다 `n` 이 달라져 같은 행 안에서도 비교가 깨진다. 세어서 밝힐 것.
- **같은 `k` 에서 조회와 산술을 나란히 비교하기** — 여유 `k/m` 이 20배 대 2배로 다르다. **m 층화**
  (`TABLES-2026-09-07.md` §1-2) 로 같은 `m` 칸끼리 비교할 것. m=1 에서는 산술 .9429/.9423 과
  조회 .9666/.9587 이 사실상 같다.
- **청크 크기가 다른 방식을 같은 `k` 에서 비교하기** — `table` 은 한 청크에 셀 139개(중앙)를 담는다.
  축을 맞춘 것이 **넘긴 셀 개수 예산** `@B cells` 이고 (`TABLES` §3), 그 축에서는 셀 단위가 24칸 전부 이긴다.

## 3. 답변 지표 (LLM) — 검색을 고정하고 리더만 잰다

리더 `Qwen2.5-7B-Instruct` 4-bit NF4, `temp=0`, `seed=42`, `max_new_tokens=32`.
채점기 `analysis/phase4_summary.em`, 계측기 `analysis/answer_board.py`.

### 3.1 EM

```
EM(c) = (1/n) · Σ_q [ em(â_q, a_q) ]        c = 문맥 조건
```

`em` 은 숫자 정규화 후 완전일치다 (다중 답은 순서 무시 집합 일치). 서술형 채점이 아니므로
LLM-as-judge 는 쓰지 않는다 — HiTab 답은 표에서 읽은 값이거나 그 산술 결과다.

**진단 열 `EM(표기허용)`**: 부호 또는 ×100(퍼센트↔비율)만 다른 같은 수를 맞다고 세는 것
(`analysis/stage3_board.py: conv_em`, 1% 허용). HiTab 의 `div` gold 는 비율인데 질문은 "몇 퍼센트"라 묻고
`opposite`/`diff` 는 감소를 양수로 적는다. **주지표가 아니다** — 채점 규칙을 바꿀지는 사람이 정한다.

### 3.2 문맥 조건 — 무엇을 넣었는지가 지표를 정한다

| 조건 | 문맥 `C_q` | 성격 |
|---|---|---|
| `gold` | `G_q` 만 | **리더 천장.** 검색이 완벽할 때의 답변 정확도 |
| `top-k` | `R_q(k)` | **종단(end-to-end).** 실제 파이프라인 |
| `orc-k` | `G_q ⊆ R_q(k)` 이면 `G_q`, 아니면 상위 1 | ⚠️ **오라클.** 재정렬의 상한 |

`orc-k` 는 "검색이 못 찾은 셀은 재정렬기도 만들어낼 수 없다"는 제약을 지키므로 재정렬 상한이다.
**성능 주장에 쓰면 안 된다** — 성립하는 문장은 "여기에 +.15 가 놓여 있다" 뿐이다.

### 3.3 리더 천장

```
Ceiling = EM(gold)
```

검색이 100% 여도 이 값을 넘을 수 없다. 측정치: 단일 .89~.90 / 다중 .79~.90 / **산술 .37~.56**.

### 3.4 리더 충실도 `η@k` — **이것이 LLM 지표다**

```
Cov@k = (1/n) · Σ_q [ G_q ⊆ C_q(k) ]        (검색 몫. top-k 조건에서는 = all-covered@k)

η@k = EM|cov = Σ_q [ em ]·[ G_q ⊆ C_q ] / Σ_q [ G_q ⊆ C_q ]
              = P( 맞힘 | 정답 셀이 문맥에 전부 있음 )
```

**정답 셀을 다 줬을 때 리더가 맞히는 비율.** 검색 성능이 분모에서 나눠지므로 `Cov` 와 (거의) 독립이고,
검색기를 바꿔도 리더가 같으면 안 변해야 한다. 검색 개선을 평가할 때의 **통제 열**이다.

### 3.5 누출 `λ@k` 와 distractor 내성 `τ@k`

```
λ@k = EM|¬cov = P( 맞힘 | 정답 셀이 문맥에 없음 )      (0 이어야 정상. 크면 gold·채점기를 의심)
τ@k = η@k / EM(gold)                                    (distractor 가 리더를 얼마나 깎았나)
```

`τ = 1` 이면 문맥에 섞인 오답 셀이 리더를 전혀 방해하지 않은 것이다.

## 4. 두 지표를 잇는 항등식 — "검색 정확도가 .9 면 답변 정확도도 .9 여야 한다"

### 4.1 분해

문맥이 정답 셀을 다 담았느냐로 질의를 두 조각으로 가르면, 정의상 **항등식**이 성립한다
(`analysis/answer_board.py` 가 전 행에서 `assert` 한다):

```
EM@k  =  Cov@k · η@k  +  (1 − Cov@k) · λ@k
         ↑검색 몫       ↑리더 몫              ↑누출 (≈0)
```

`λ ≈ 0` 이면

```
EM@k ≈ Cov@k · η@k        즉        η@k ≈ EM@k / Cov@k
```

**따라서 "검색 .9 → 답변 .9" 는 `η@k = 1` (정답 셀을 다 주면 리더가 항상 맞힘) 일 때만 성립한다.**
기대가 어긋나는 만큼이 전부 `η` 이고, `η` 는 검색기가 아니라 리더의 값이다.

### 4.2 측정 — 기대는 `top-1` 에서 맞고 `top-10` 에서 깨진다

`EM / Cov` 열이 곧 "검색 정확도가 답변으로 전달된 비율"이다.

| 실행 · 조건 | Cov | EM | **EM / Cov** | 해석 |
|---|---:|---:|---:|---|
| `p0_dev_all` `top1` | .7193 | .6807 | **0.946** | 기대가 성립 |
| `single_test` `top1` | .6710 | .6424 | **0.957** | 기대가 성립 |
| `p0_dev_all` `top10` | .9446 | .7205 | **0.763** | 깨진다 |
| `single_test` `top10` | .9246 | .6970 | **0.754** | 깨진다 |
| `p0_dev_all` `orc10` ⚠️오라클 | .9446 | .8699 | **0.921** | 문맥을 다시 정리하면 회복된다 |
| `e4_arith_test_value` `top10` | .8268 | .1899 | **0.230** | 산술은 애초에 리더가 못 푼다 |

**셀 하나만 주면 리더는 거의 완벽하다** (`η@1` = .92~.93, `τ ≈ 1`). 같은 리더가 정답 셀을 포함한 10셀을
받으면 `.75` 로 떨어진다 (`τ ≈ 0.83`). **차이는 검색이 아니라 같이 들어온 9개의 distractor 다** —
프롬프트도 107 → 631 토큰으로 늘어난다. 완벽히 재정렬해 gold 만 남기면 `.92` 로 돌아온다(`orc10`).

### 4.3 전달률 — 검색을 개선하면 답변은 따라오는가

`K` 를 **고정한 채** 검색기를 바꿨을 때 (같은 830건, `results/answer_ret/VERDICT.md` §판정):

```
전달률 T = ΔEM / ΔCov
```

| 개입 | K | ΔCov | ΔEM | **T** |
|---|---|---:|---:|---:|
| 기성품 α=.7 → `a0` | 1 | +.1662 | +.1494 | **0.90** |
| `a0` → `p0` | 1 | +.0374 | +.0373 | **1.00** |
| `a0` → `p0` | 10 | +.0301 | +.0301 | **1.00** |
| `top1` → `top10` (K 를 키움) | 1→10 | +.2326 | +.0470 | **0.20** |
| `top5` → `top10` (K 를 키움) | 5→10 | +.0278 | +.0085 | 유의하지 않음 (51:44, p=.54) |

**정리 — 사용자 기대는 반은 맞다.**
1. **`K` 고정하고 검색 정확도를 올리면 답변은 거의 1:1 로 따라온다** (T = 0.90~1.00). 이 구간에서
   "검색 .9 → 답변 .9" 는 성립한다.
2. **`K` 를 키워 `Cov` 를 올리는 것은 20%만 전달된다.** 산 `Cov` 만큼 distractor 도 같이 사기 때문이다
   (`η` 가 .92 → .75 로 무너진다). **`all-covered@20` 이 .9666 이라고 답변이 .96 이 되지 않는 이유가 이것이다.**
3. **산술은 위 둘과 다른 문제다.** `η(gold)` 자체가 .37(dev)/.56(test) 이다 — 정답 셀을 다 줘도 7B 리더가
   계산을 못 한다. 검색을 아무리 올려도 답변 상한이 여기다. 실패의 절반은 계산이 아니라 표기 관행이고
   (`EM(표기허용)` 이 .3713 → .7605), **채점 규칙을 유지할지는 사람이 정한다.**

### 4.4 그래서 답변 성능을 올리는 순서

```
목표 EM = Cov@k · η@k
```
둘 다 1 에 가까워야 하는데 지금 병목은 `η` 다.

| 레버 | 크기 | 근거 |
|---|---:|---|
| 재정렬 (top10 → gold만) | **+.1494** | `orc10` vs `top10`, 149:25, p=1.1e-22 ⚠️오라클 상한 |
| 인코더 재학습 (`a0`→`p0`) | +.0301 | 60:35, p=.013 |
| 질의 종류별 답변 모드 분기 | 산술 +.08~.10 | E4: 풀이형이 `top10` 에서만 이득 (dev 21:8 p=.024) |

⚠️ 재정렬은 두 번 시도해 두 번 기각됐다 (기성품 §12 −.101, 도메인 학습 §18 −.058). **오라클 크기는
놓여 있는 이득이지 달성한 값이 아니다.**

## 5. 타 논문과의 대조 — 지표 사전 없이 인용하면 전부 틀린 인용이 된다

### 5.1 지표 매핑

| 남들이 쓰는 이름 | 이 문서의 정의 | 엄격도 |
|---|---|---|
| Hit@k, C-HR (FT-RAG, HD-RAG, MixRAG) | `hit@k` (§2.2) | 가장 관대 |
| Recall, C-R (FT-RAG, TableRAG, MixRAG) | `Recall@k` (§2.2) | 중간 |
| — (**아무도 안 쓴다**) | `all-covered@k` (§2.1) | 가장 엄격 |

`all-covered@k ≤ Recall@k ≤ hit@k` (§2.3) 이므로, 우리 주지표 열은 **더 어려운 시험의 점수**다.
비교할 때는 반드시 대응 지표(`hit@k`/`Recall@k`)로 내려서 같은 `k` 끼리 짚는다.

### 5.3 답변 — **아직 대조하지 않았다**

위 논문들의 answer accuracy 와는 아직 대조하지 않았다. 이유는 두 가지다.

1. **리더가 다르다.** 우리 리더는 로컬 `Qwen2.5-7B-Instruct` 4-bit 이고 (`CLAUDE.md` §7), 저쪽은 GPT-4o 급이다.
   답변 EM 을 나란히 놓으면 검색이 아니라 **리더 체급을 비교하는 것**이 된다. `η(gold)` 산술 .37 이 그 증거다.
2. **원문 수치 미확인.** MultiHiertt 원논문 EM/F1 을 원문에서 확인해 대조하는 것이 이월 항목이다.
   `MEASURED: NO` — 확인 전에는 숫자를 적지 않는다.

**대조하려면 지금 필요한 것**: (a) 같은 리더로 양쪽 검색 결과를 읽히는 통제, 또는 (b) `η` 를 리더 지표로
따로 보고하고 검색 지표만 대조. **(b) 가 이 문서의 구조이고, 그래서 §2 와 §3 을 나눴다.**

## 6. 인용 규칙 (요약)

- 검색 숫자에는 **예산 `k` 와 단위**(문서 / 표 / 증거조각 / 셀)를 반드시 붙인다. 빼면 틀린 인용이다.
- 답변 숫자에는 **조건**(`gold` / `top-k` / `orc-k`)과 **리더**를 반드시 붙인다. `orc-k` 는 오라클이다.
- `all-covered@20` test 산술 .9106 을 **"산술 목표 .9 달성"으로 쓰지 않는다** — 사전등록 판정 지표는
  `@10` 이고 판정은 미달(dev .6407 / test .8268)로 남는다. 판정은 다음 사전등록에서.
- `@(c·m)`, `셀|표@k`, `orc-k` 는 전부 오라클이다. **성능 주장에 쓰지 않는다.**
- 종단 EM 하나만 인용하지 않는다. **`Cov` · `η` · `EM` 세 개를 같이 적는다** — 그래야 검색 탓인지
  리더 탓인지 읽는 사람이 안다.

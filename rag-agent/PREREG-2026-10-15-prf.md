# 사전등록: 검색 결과를 질문 앞에 붙여 다시 검색(의사 적합성 피드백) — dev 선택 → 882 확인 (2026-10-15)

## 왜
교수 말씀 "RAG 검색 결과를 쿼리 앞에다 붙여라"(10-12, 사용자 전달)를 검색 절차로 읽는다: 1차 검색 상위 단위의 글을 질문 앞에 이어 붙여
새 질문을 만들고 그 질문으로 다시 검색(pseudo-relevance feedback, 질의 확장). 프롬프트 순서 읽기는 `PREREG-2026-10-15-prompt-order.md` 에서 효과 없음 확인.
GPT-4o 882 사후 분석(10-14~15)에서 본 방법이 지는 자리는 개수 세기·훑어보기(행이 끊겨 넘어감)와 같은 이름 행이 여러 표에 있는 문항이었다.
2차 검색은 상위 셀과 머리글 경로를 공유하는 셀(같은 행·열·표)을 끌어올리므로 이 두 자리를 겨냥한다. 9-17 에 접은 HyDE(LLM 이 가짜 답을 써서 검색)와 다르고 닫힌 노선에 없다.

## 방법 (`scripts/mh_arms.py --prf N --prf-text full|path`, 이 커밋에서 추가)
- 1차: 지금 규칙(셀 문장 s3c, v3.3u, 0.7·cos + 0.3·BM25, 문서 안 순위).
- 새 질문 = 상위 N 단위의 글(full = 셀 문장 전체 / path = 마지막 ": 값" 을 뺀 경로) 을 공백으로 잇고 그 뒤에 원래 질문.
- 2차: 새 질문으로 dense·BM25 점수를 다시 계산해 문서 안 순위를 다시 매김. 그 뒤(전달 규칙·지시문·LLM·채점)는 전부 그대로.
- 전달: `results/prf_20261015/build_inputs.py` — cellform C 규칙(점수 순 셀 문장, 같은 문항의 LangChain 토큰 수 T 직전까지). 기존 기록으로 dev 332/332·train 882/882 본문 재현 확인.
- LLM: Qwen3-8B 4비트, LangChain 원문 지시문(Question → Context), 384토큰. 채점 `score_fix_20261014/score_v2.included_v2`.

## 후보와 선택 규칙 (dev = validation 332, `results/reader_format_20260927/mh_dev_pop332.jsonl`)
- 후보 6: N ∈ {1, 3, 5} × {full, path}. 기준 = 기존 dev C(`results/cellform_dev_20261012/ans_C`, 같은 규칙으로 재채점).
- 선택 지표 = 정답 포함 채점 v2 맞힌 수. **예/아니오 정답 문항은 선택 지표에서 뺀다**(낱말 없는 출력은 사람 판정이 필요해 후보마다 판정하면 선택이 흔들림). 개수를 적는다.
- 채택: 후보 최고가 기준 C 보다 **크면** 그 후보 하나(동률이면 N 작은 쪽, path 우선). 아니면 채택 없음 — 882 안 돌리고 결과만 적는다.
- 검색 지표(정답 포함률)는 보조로만 적는다.

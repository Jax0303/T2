# 사전등록 2026-10-22 — 지시문 4개 × 세 입력 × 3회, 새 문항 600b (지시문에 걸친 순서 유지 확인)

## 왜
- 공정 비교 원칙(메모리 feedback-fair-prompt-comparison): 지시문 2개 이상에서 결과를 보고해 순서가 유지되는지 보인다(Mizrahi 2024·Sclar 2024·Voronov 2024). 지금까지 평가 문항에서 잘라낸 표 대 LangChain 은 P* 하나(+X3 는 600 에서만)로 보고됐다.
- 사용자 결정 대기 항목 "주 지시문을 원문+최소 변경으로 바꿀지"에 평가 문항 수준의 근거가 없다(dev 만 있음).
- 사용자(10-22 새벽): "우리 방법을 더 올릴 수 있을지 테스트하면서 최선의 방향으로만 진행" — 검색·전달 축은 소진(상한 진단·고르기·쪼개기 닫힘), LLM 축은 조건 밖. 남은 최선은 주장의 견고성을 평가 문항에서 확정하는 것.

## 고정 조건
- 문항 600b: 882·dev·앞선 600 밖 산술 셀 2개+ 모집단 1,335 에서 시드 20261022 로 600(`ids600b.json`, 앞선 600 과 겹침 0). 입력 `A/C/D_records.jsonl`(`build_fresh_b.py`, 앞선 600 과 같은 규칙; 정답 셀 포함 A 589·C 567·D 595, 토큰 평균 A 1,253·C 1,237·D 1,152).
- LLM Qwen3.5-4B bf16, vLLM, temperature 0, 비생각, 출력 4,096, 3회(동시 32/24/16).
- 지시문 4개(원문 불변, `scripts/prompt_variants.py`): P1 원문 LangChain 튜토리얼 R0X0F0B0D0C0E0 · P2 원문+최소 변경 R0X0F0B2D0C1E0(계산식 먼저 + Final answer 줄) · P3 P* R1X1F1B2D1C1E0 · P4 P*+꺽쇠 설명 R1X3F1B2D1C1E0.
- 채점: Final answer 줄이 있는 P2~P4 는 마지막 줄 포함 v2, 없는 P1 은 전체 포함(10-15 와 같은 규칙). 실행별 McNemar, 3회 평균, 다수결 없음. `run.sh` → `run{1,2,3}/`, `score.txt`, `compare.py` → `compare.txt`.
- 이 실행은 선택용이 아니다: 어느 지시문도 이 결과로 고르지 않는다(지시문 선택은 dev 에서 끝남).

## 판정 규칙(결과 전 고정)
- **순서 유지**: 잘라낸 표 > LangChain 이 세 실행 모두 성립하고 2회 이상 p<.05 인 지시문 수를 센다. 4개 중 3개 이상 → "지시문에 걸쳐 유지"로 적는다. 2개 → "고른 지시문 계열에서 유지"로 적는다. 1개 이하 → "P* 에 한정된 결과"로 적는다.
- **목록 대 LangChain**: 지시문별 수치를 그대로 적는다(앞선 결과: 우연 범위).
- **주 지시문 결정 근거**: P2 의 잘라낸 표 3회 평균이 P3 보다 12(2%p) 이상 낮으면 "원문+최소 변경으로 바꾸면 절대 점수 손실 2%p 이상"으로 적고, 아니면 "손실 2%p 미만"으로 적는다. 결정은 사용자.

## 예측(확률; 실행 전 고정)
- P3 에서 세 실행 모두 잘라낸 표 > LangChain, 2회 이상 유의: 70%(앞선 600: 3회 모두 유의). P4: 60%. P2: 50%. P1: 35%(원문은 답 줄이 없어 전체 포함 채점이라 차이가 묻힘).
- 순서 유지 지시문 수 3개 이상: 40%. 2개: 35%. 1개 이하: 25%.
- P2 잘라낸 표 평균이 P3 보다 12 이상 낮음: 60%(dev 에서 284 대 292).
- 목록 대 LangChain 네 지시문 모두 우연 범위: 70%.

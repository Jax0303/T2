# 사전등록 2026-10-22 — 잘린 답변 마무리 단계(최대 출력에 닿으면 'Final answer:'를 덧붙여 32 토큰 안에 답하게 함), 전 집합·전 입력

## 왜
- 출력 상한(4,096)에 걸려 잘린 답변은 마지막 줄이 없어 전부 오답 처리된다. 600 실행 평균: 잘라낸 표 26, 셀 문장 목록 38, LangChain 청크 39. 882: 35/44/49. 잘린 것 중 풀이에 정답이 등장한 문항이 잘라낸 표 600 실행1 에서 10. 끝났는데 Final 줄이 없는 경우는 0 → 손실은 전부 잘림.
- 상한을 3,072→4,096 으로 올려도 합계가 안 움직였다(반복 루프). 그래서 "더 길게"가 아니라 "강제로 끝맺기"(Muennighoff 외 2025, s1 의 budget forcing)를 쓴다. 디코딩 규칙이라 세 입력·모든 실행에 같은 방식으로 적용된다. 잘리지 않은 답변은 손대지 않는다.
- 사용자(10-22): "의구심 해결 실험 얼마든지, 반드시 성과." 이 단계는 점수를 내릴 수 없고(마지막 줄 없음 → 0 에서 시작) 올릴 수만 있다. 어느 입력이 더 많이 오르는지가 관건이다(LangChain 이 더 많이 잘리므로 격차가 줄 수 있음 — 그대로 적는다).

## 고정 조건
- `scripts/force_final.py`: finished=False 이고 'Final answer' 줄이 없는 행만. 프롬프트 = 원 채팅 프롬프트 + 생성문 + "\nFinal answer:", greedy 32 토큰, 첫 줄만 채택. 출력은 `<variant>.forced.jsonl`(원본 보존).
- 대상: dev 395(sentence_dev run1·2, A·D·Cp), 600(run1~3, D·C·A), 882 4,096(run1~3, D·C·A), 600b(run1~3 × 지시문 4 × D·C·A). 채점 규칙은 집합별 기존 그대로(P1 은 전체 포함).
- 비교 `results/budget_forcing_20261022/compare.py`: 전·후 맞힘, 실행별 늘어남, D 대 A 전·후 McNemar.

- 보고는 항상 전·후 둘 다. **표준 절차로 채택**: 600 과 882 모두에서 세 입력 전부 늘어남 ≥ 0 이고(정의상 참) 어느 한 입력이라도 3회 평균 +6(1%p) 이상이면 "마무리 단계 포함"을 표준 보고에 넣고, 아니면 보조 수치로만 둔다.

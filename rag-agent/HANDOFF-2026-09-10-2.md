교집합이었기 때문이다 — 고친 코드로 전수 재실행해 **판정 변동 0건**을 확인했다(§3).
보류해야 하는 것은 **리더 쪽 수치(답변 EM·조건부 EM)** 다.

## 1.1 감사 주장 중 **재현하지 못한** 것 — 인용 금지

- **`_pack()` 대 `RecursiveCharacterTextSplitter` 가 538표 중 330표에서 다르다.**
  langchain 이 이 환경에 없다. 저쪽 splitter 를 직접 다시 구현해서 비교하면 **비교
  대상을 내가 만든 것**이 되므로 하지 않았다. 코드를 읽어 확인되는 사실만 적었다:
  우리 `_pack` 은 렌더된 **줄 단위**로 병합하고 줄 안에서 자르지 않는데, 저쪽은
  구분자를 재귀적으로 내려가며 글자까지 자른다 — **같은 설정값이어도 같은 분할이 아니다.**
- **HiTab `test_samples_qualitycheck.jsonl` 과 229건 차이.** 그 파일이 `data/hitab` 에
  없다. 대신 **실행이 읽은 질의 파일의 SHA-256 을 요약에 적게 했다**(`data_sha256_16`).
  어느 판으로 잰 점수인지가 파일에 남는다.
- **BGE 512 절단의 arm 별 건수.** 감사 수치를 옮겨 적는 대신 **계측을 코드에 넣었다** —
  이제 모든 실행이 자기 숫자를 `encoder_truncation` 에 싣는다 (§3).

## 2. 고친 것 넷 (전부 `BUGFIX_LOG.md` 2026-09-10 항목에 상세)

### 2.1 P1 `rowcol_select()` — 교집합으로 채점, 합집합을 배달

`RowColRetrieval` 은 `df.iloc[row_ids, col_ids]` 를 준다. 우리는 `R & C` 로 채점하고
**행 문장 + 열 문장을 이어붙여** 전달했다. 첫 행 `{a,b}` 와 첫 열 `{a,c}` → 채점 `{a}`,
배달 `a,b,c`.

**수정**: `subtable_lines()` — 채점한 교집합을 그대로 sub-table 로 잘라 배달한다.
렌더링은 코퍼스 자신의 `line_text()` 를 재사용하므로 문맥과 색인 단위 표기가 갈라지지 않는다.

### 2.2 P1 `budget_select()` — `dump` 가 쓰기만 멈추고 훑기는 안 멈췄다

셀 0개 문서(TableRAG schema/stub)가 gold 앞에 오면 gold 없는 문맥이 HIT 로 기록된다.
**수정**: 예산이 고른 단위를 **전부** 쓴다 (`dump` 는 스위치이지 두 번째 예산이 아니다).

⚠️ **반대로 고치지 마라.** 훑기를 `dump` 에서 끊어도 채점=배달은 회복되지만 운영점이
"20셀"에서 "20단위"로 옮겨 가고, 그 차이는 **셀 0개 단위를 갖는 arm 에서만** 생긴다
(`tablerag` 평균 배달 셀 20.87 → 9.90). 우리가 한 baseline 에만 handicap 을 얹는 것이라
`CLAUDE.md` §0.1(운영점 = 리더에게 주는 셀 수)과 `tests/test_arm_fairness.py` 양쪽에
걸린다. 단위 제한 손잡이는 `--max-units` 로 따로 있다. **이 세션이 처음에 이 함정에
빠졌다가 되돌렸다.**

### 2.3 gold 좌표 `[:64]` 절단 — 삭제

검색은 전체 gold 로 채점하는데 gold/oracle 리더 레그만 잘린 집합을 받고 있었다.

### 2.4 표 생성기가 옛 리더 레그를 읽고 있었다

`gold_v2` 를 재실행해 뒀는데 생성기는 조건 이름을 파일 이름으로 그대로 써서 제목 버그
수정 **전** 레그를 계속 읽었다. **수정**: `accuracy_tables.LEG` 한 곳이 조건→파일을
정하고 모든 자리가 `leg_file()` 을 지난다. `compose_oracle.py` 는 어느 gold 레그로
합성할지를 인자로 받는다(기본 `gold_v2` → `oracle_v2`).

**문서에 반영된 변화** (실험 재실행 없이 값이 바뀐 것):

|---|---:|---:|

| `oracle` (주지표) | 0.8819 (874/991) | **0.8809** (873/991) |

### 2.5 재발 방지 계측 (같은 사고가 다시 숨지 못하게)

- `context_sha` — 검색 기록과 답변 기록 **양쪽**에. 채점한 문맥과 답한 문맥이 같은지가
  파일만 보고 확인된다. 이 감사가 손으로 다시 해야 했던 일이다.
- `encoder_truncation` — dense 인코더가 자르는 색인 단위 수와 `max_seq_length`.
  **리더 문맥창이 아니라 검색 입력의 한계**이고, 기록되지 않으면 점수만 보고는 안 보인다.
- `code_revision` · `data_sha256_16` · `chunk_overlap` — 재현 정보.
- 회귀 테스트 둘: `test_rowcol_delivers_the_subtable_it_scored`,
  `test_budget_never_scores_a_cell_it_did_not_deliver`. 그리고 낡은 단언 하나를 고쳤다
  (`build_schema_corpus` 포팅 후 범주 열도 `"dtype"` 문서를 갖는다). **98 passed.**

## 3. 표기 수정 — 실험 재실행 없이 문장만 고친 것

- **표 1 의 `분류` 열이 `분류 (재현 범위)` 가 됐다.** `발표 논문` 이 "그 시스템을
  재현했다"로 읽히던 것을 `발표 논문 — 검색 레그만` / `— 색인 코퍼스만` /
  `— 검색 컴포넌트` 로 갈랐다. 표 머리에 **"이 표의 어떤 행도 '그 시스템을 이겼다'의
  근거가 되지 않는다"** 를 못 박았다.
- **Huawei 두 행**: 본문 라벨을 `TableRAG (Huawei) 의 **청킹만** — 공통 검색기·공통 리더`
  로 바꾸고, `◆` 각주에 SQL·질의 분해·반복 추론·BGE-M3·재순위화가 전부 없다는 것과,
  **2,400자는 1,000토큰의 어림값이지 토큰 기반 분할이 아니라는 것**을 적었다.
- **`ANN` 이라고 쓰지 않는다.** 색인(`hybrid_index.py`, FAISS `IndexFlatIP`)도
  계측기(`emb @ q` + `np.argsort`)도 전수 내적이다. 성립하는 문장은 **질의당 모델 호출
  1회**이고 조회 지연시간 주장은 계측이 따로 있어야 한다. (`README` §2, `CLAUDE.md` §2)

## 4. 문헌 — 기여 후보 3 이 죽었다 ⚠️

`LITERATURE-2026-09-10-retrieval-vs-answer.md` §8 에 원문 인용과 함께 적었다.

**MixRAG (Zhang et al., SIGKDD 2026, arXiv:2504.09554)** 원문에서 확인:

- 코퍼스 출처가 **MultiHiertt + HiTab** 이다 — *"we scrape contextual information
  utilizing webpage links provided in HiTab (Cheng et al., 2022), reconstructing
  heterogeneous documents"*. 데이터셋 `DocRAGLib`, **2,178문서 / 4,468 QA**.
- **코퍼스 전역 검색이다** — *"the most relevant document D\* from the document corpus"*.
- 계층을 **H-RCL** (행·열 수준 요약) 로 표현하고 **LLM 재순위화**를 쓴다.
- 지표는 **HiT@K (문서 단위)**. HiT@1 54.1% (GPT-4o).

**따라서 "계층표 + 코퍼스 검색은 선행연구에 없다"는 더 못 쓴다.** `HANDOFF-2026-09-10.md`
§7 의 기여 후보 3 을 기각 표시했다.

**남는 차이 — 그리고 왜 남는지**: MixRAG 의 색인 단위는 **행·열 요약문**이고 검색 성공의
정의는 **문서를 맞혔나**다. 이 리포는 **셀**을 색인하고 **정답 근거 셀이 문맥에 왔나**를
잰다. 기여 후보 1(분해 프레임)·2(색인 단위가 조건부 정확도를 바꾼다)는 이 차이 위에
그대로 서지만, **"세팅이 새롭다"는 더 이상 그 근거가 아니다.**

곁들여 확인한 둘:
- **FT-RAG (arXiv:2605.01495)** — entry-level 단위 + 구조 그래프, table/cell-level Hit
  Rate 를 둘 다 보고. **자체 벤치마크(Multi-Table-RAG-Lib)만 쓰고 HiTab 은 평가 안 함.**
  초록의 *"exact value accuracy recall"* 은 정의를 못 찾았다 — HiTab EM 과 같게 취급 금지.
- **OHD (ICML 2026, arXiv:2602.01969)** — 표 하나를 column tree + row tree 로 분해하는
  **표현** 방법이고 **코퍼스 검색을 하지 않는다.** 비교할 시스템이 아니라 직렬화 비교
  후보다. (README §2 의 현재 인용 용법이 맞다.)

**안 읽은 것**: FGTR(arXiv:2603.12702), ASTRA(arXiv:2604.08999). **읽었다고 쓰지 말 것.**

## 5. 재실행 — GPU 없이 한 것

`results/audit_fix_20260910/`. 검색 전용이라 CPU 로 돌았고 임베딩 캐시가 전부 적중했다
(코퍼스 텍스트는 바뀌지 않았다 — 바뀐 것은 **선택기**다).

**검색 정확도는 어느 arm 에서도 버그 수정으로 바뀌지 않았다.** 두 결함 다 채점하는

본 방법 S3c 는 주 모집단 0.9142 재현, 판정 변동 0건, 문맥 줄수 20.0 그대로 —
**대조군이 움직이지 않았다는 것이 이 재실행의 신뢰 근거다.**

### 5.2 TableRAG 두 행은 **다른 이유로** 낡아 있었다 (감사가 못 잡은 것)

`build_schema_corpus` 포팅(이전 세션)이 코퍼스를 17,425→18,605 / 18,576→19,779 로
키웠는데 **표 1 의 두 행은 그 뒤로 재실행된 적이 없다.** 같은 날 `results/tablerag_fair/`
는 새 코퍼스(18,605/19,779)를 쓰고 있어서 두 문서가 서로 어긋나 있었고, `TABLES.md` 의
출처 감사 줄은 **"`build_schema_corpus` 누락"** 이라고 적혀 있었다 — 코드는 이미 포팅된
뒤였다. 셋이 삼자 불일치였다.

효과는 작다: 주지표 **0.0686 → 0.0676 / 0.1433 → 0.1423** (각각 991건 중 1건).
"닿는 셀 0개 변화라 측정에 영향 없다"는 옛 서술은 **틀렸다** — 셀 0개 문서가 1,180개
이상 들어오면 순위가 달라진다. `TABLES.md` 의 두 서술을 고치고 실측을 붙였다.

### 5.3 인코더 절단 — 감사 §3.4 를 우리 코드로 재현

`encoder_truncation` 이 이제 모든 실행 요약에 실린다 (`max_seq_length=512`).

| 색인 | 512토큰 초과 / 전체 | 비율 |
|---|---:|---:|
| S3c 셀 | 0 / 67,664 | 0.0% |
| RowCol | 0 / 12,950 | 0.0% |
| TableRAG'24 leaf/path | 0 / 18,605 · 0 / 19,779 | 0.0% |
| Huawei 청킹 1,000자 | 29 / 1,143 | 2.5% |
| 고정 청킹 1,000자 | 109 / 922 | **11.8%** |
| **Huawei 청킹 2,400자** | **248 / 618** | **40.1%** |

**감사 수치와 소수점까지 일치한다.** 읽는 법: 이것은 **리더 문맥창이 아니라 검색 입력의
한계**다. 2,400자 arm 은 청크 열에 넷은 뒤쪽이 dense 벡터에 아예 안 들어간다. BM25 는
전문을 쓰므로 "검색 정보가 다 사라진다"는 뜻은 아니고, 순위·EM 손실의 크기는 더 긴
encoder 나 다른 청크로 다시 재야 안다.

3. TableRAG 공정 비교의 주지표 991 답변 EM 재측정.

### 6.2 사전등록이 먼저인 것 — **그냥 돌리지 말 것**

감사 §6.4 가 요구하는 **토큰 기반 splitter arm**(논문의 1,000토큰 설정)은 새 arm 이다.
`CLAUDE.md` 는 개입마다 **실행 전 사전등록**을 요구하므로, 예측치와 기각 기준을 먼저
문서로 박고 돌린다. 이 세션은 그래서 **돌리지 않았다** — 라벨과 결함만 적었다.
(이 세션의 재실행은 새 arm 이 아니라 **버그 수정 후 재측정**이고, `CLAUDE.md` §0.6 이
"채점 코드를 건드린 세션은 전부 다시 돌린다"고 요구하는 바로 그것이다.)

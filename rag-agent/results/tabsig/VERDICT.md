# 표를 잘못 고르는 8% — 왜 지는가 (2026-09-04)

**사전등록 없는 사후 진단. arm 을 고르지 않았고 개입도 하지 않았다.**
계측기 `analysis/table_signal.py`, 원본 `results/tabsig/table_signal.json`.
인코더 `models/bge-base-cell-ft-p0` α=0.8 `--title-mode page`,
랭크 `results/p0_confirm/*_ranks.jsonl`, 이긴 표 덤프 `results/colsig/*_above.jsonl`.

`tableconf/VERDICT.md` 가 제목 충돌로 표 오인 108건을 설명했고, page 제목 복구
(`p0`, `RESULTS.md` §13)로 표 recall@1 이 .8661 → .9324 로 올랐다. **그러고도 남은
6.8%(test 52 / dev 67)가 무엇인지는 측정된 적이 없다.** 그것을 잰다.

## 0. 먼저 — "표 검색"이라는 별도 단계가 없다

`table_rank_cellvote` 는 표 검색기의 출력이 아니라 **셀 랭킹에서 그 표가 처음 등장한
위치**다 (`scripts/corpus_dump_vs_cell.py:1074`). 그러므로 "표 오인"은 **다른 표의 셀
하나가 gold 표의 모든 셀을 이겼다**는 뜻이고, 셀 랭킹과 같은 실패다.

진짜 표 단위 집계로 바꾸는 것은 이미 측정돼 죽었다 — `sum/mean/count_topK` 가 HiTab
gold 표 recall@3 을 최대 **+.005** 움직이고 AIT-QA 에서는 **진다**(.488 → .479,
커밋 `0677973`, 계측기 `scripts/table_ranker_sweep.py`).

## 5. ⚠️ 원인 가설과 그 기각 — dev 에서만 성립한다

가설: **질문이 자기 표를 이름으로 부르지 않아서 진다.** HiTab 질문은 표를 보면서
쓰였으니 표 정체를 생략한다(`how many thousand dollars were for r&d?`, 8토큰).

성공/실패를 가르는 대조로 쟀다 — 질문이 gold 표 제목의 단어(불용어 제외)를 하나도
안 쓰는 비율:

| | n | 질문 토큰 중앙 | 제목 단어 겹침 0 | |
|---|---:|---:|---:|---|
| **dev** 성공 | 763 | 15 | .0813 | |
| **dev** 실패 | 67 | 14 | **.3284** | chi2 **p=5.0e-10** |
| **test** 성공 | 717 | 15 | .1423 | |
| **test** 실패 | 52 | 15 | .1923 | chi2 **p=.433** |

**dev 에서 4배로 갈리는 것이 test 에서 재현되지 않는다.** 효과 크기 자체가 작아졌고
(.328 → .192), 성공 쪽 기저율도 .081 → .142 로 달라졌다. 검정력 부족만으로 설명되지
않는다.

🚫 **"질문이 자기 표를 안 불러서 진다"를 원인으로 쓰지 말 것.** dev 관측이고 test 가
받쳐주지 않는다. 두 스플릿에서 다 성립하는 것은 §1(2등이 다수)과 §3(형제 표)뿐이다.

질문 길이는 두 스플릿 모두 무관하다 (Mann-Whitney p=.259 / .346) — **짧아서 지는 게
아니다.**

## 6. 고칠 값어치 — 두 조건이 엇갈린다 (dev)

| | 건수 |
|---|---:|
| A. 표를 고칠 신호가 있다 (§4) | 31 (.463) |
| B. 표만 고치면 셀도 1등이 된다 (§1) | 31 (.463) |
| **A ∩ B** | **15 (.224)** |

**우연히 같은 31 이지만 같은 집합이 아니다.** 신호가 있는 31 중 절반은 표를 맞혀도
표 안에서 다시 지고, 표만 고치면 되는 31 중 절반은 애초에 신호가 없다.

**표 축에서 실제로 회수 가능한 상한 = dev R@1 +15/830 = +.0181** (.7193 → .7374).
오라클 표 게이팅이 주는 +.047(test)은 신호 유무를 안 따진 값이므로 그 3분의 1 수준이
실제 여지다.

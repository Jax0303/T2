# 표 안에서 지는 이유 — 질문이 정답을 특정하는가 (2026-09-03)

**사전등록 없음. 사후 분석이고 arm 을 고르지 않는다.**
계측기 `analysis/col_signal.py` (단어 일치), `analysis/col_signal_phrase.py` (구절 비교).
덤프는 `cell_rank_dump.py --dump-above 5`, 인코더 p0, 모집단 `hitab_dev_lookup_all`(830).

`HANDOFF-2026-09-02-3.md` §3 이 "행 헤더를 붙잡고 열 헤더를 못 가른다"까지 갔고
어휘 처방이 죽은 자리에서 이어간다. 묻는 것: **그 신호가 애초에 질문 안에 있는가.**

## A. α=0.8 대 α=1.0 — BM25 는 양날이다

가설: BM25(20%)가 오답 헤더의 단어를 그대로 올리니 빼면 나아진다.

| | α=0.8 (확정 arm) | α=1.0 (BM25 뺌) |
|---|---:|---:|
| R@1 | **.7193** | .7024 |
| setEM@10 | **.9446** | .9301 |
| 표 안 실패 (1등이 정답 표) | 166 | 176 |
| ② 질문이 **오답** 쪽 단어를 씀 | 44 (.265) | **37 (.210)** |
| ④ 질문이 **정답** 쪽만 지목했는데 짐 | **9 (.054)** | 21 (.119) |

**방향은 맞고 처방으로는 기각.** BM25 를 빼면 ② 가 7건 줄지만 ④ 가 12건 는다.
질문 단어를 그대로 가진 칸을 올리는 성질이 **정답 헤더가 질문과 같은 단어를 쓸 때는
이득, 오답 헤더가 쓸 때는 손해**다. 순효과는 BM25 쪽이 이긴다.

→ **α 는 두 실패를 맞바꿀 뿐 아무것도 없애지 못한다.** 동의어 문제는 α 로 못 푼다.

🚫 **"BM25 를 빼면 동의어 오인이 준다"** — 다시 제안하지 말 것.

## B. 파인튜닝은 동의어 문제를 안 고쳤다

② 비율이 a0 α=1.0 에서 34/156 = .218, p0 α=1.0 에서 37/176 = .210. **거의 그대로다.**
p0 의 검색 이득(+.0377 test)은 동의어가 아니라 표 판별에서 왔다.

## C. 실패가 표 안으로 내려온 것이 전체 집합에서 재확인됐다

| | 전체 실패 | 1등이 정답 표 안 |
|---|---:|---:|
| a0 α=1.0 | 264 | 156 (.591) |
| p0 α=0.8 | **233** | **166 (.712)** |

실패 총량은 줄었는데 표 안 실패는 **늘었다.** 2차 핸드오프가 totto 86건에서 본
"72% 가 표 안으로 옮겨갔다"가 dev 830 전체에서 성립한다.

## D. 단어 코사인으로는 이 측정을 못 한다 — 기록해 둘 것

동의어를 잡으려 단어 임베딩(기성품 bge-base)을 보정했더니:

| 동의어여야 | | 달라야 | |
|---|---:|---|---:|
| percent ~ percentage | .951 | **2013 ~ 2014** | **.795** |
| male ~ men | .773 | canada ~ provincial | .617 |
| count ~ number | .747 | goals ~ league | .631 |
| **female ~ women** | **.738** | women ~ canada | .507 |
| total ~ all | .652 | percent ~ goals | .529 |
| assault ~ victimization | .643 | 2013 ~ population | .509 |

**`2013`~`2014` (.795) 가 `female`~`women` (.738) 보다 높다.** 연도는 우리가 가르려는
바로 그 구별자인데 단어 코사인이 동의어보다 가깝다고 본다. **임계값이 존재하지 않는다.**

→ `col_signal.py --tau` 는 남겨두되 쓰지 말 것. 대신 임계값 없는 구절 비교(E)를 쓴다.

## E. 구절 비교 — 질문은 대개 오답 쪽을 가리킨다

정답 칸과 1등 칸의 헤더 경로 **차집합**을 각각 한 구절로 묶고 질문과의 코사인을 견준다.
판정기는 검색에 쓴 인코더가 아니라 **기성품 bge-base** 이고, 공유 구간을 뺀 **차이
부분만** 보므로 검색기가 한 계산이 아니다. 임계값 없음.

p0 α=0.8, 표 안 실패 166건:

| | 건수 | |
|---|---:|---|
| 질문이 **정답** 쪽에 더 가깝다 | **56 (.337)** | 신호 있음 → 고칠 수 있다 |
| 질문이 **오답** 쪽에 더 가깝다 | 105 (.633) | **검색으로 불가** |
| 경로가 완전히 동일 (값만 다름) | 5 (.030) | 색인 단위의 절대 천장 |

내역: 양쪽 다 구별 내용이 있어 **진짜 코사인 비교**인 것이 151건 (정답쪽 49 : 오답쪽 102),
정답에만 내용 7, 오답에만 내용 3, 동일 5. **|margin| < 0.02 인 애매한 건 29/151.**

## F. 그래서 R@1 의 상한

| | 문자열 일치판 | **구절 비교판** |
|---|---:|---:|
| dev | .889 | **.868** |
| **test** | .856 | **.827** |

산식(test): 이미 1등 516 + 표 밖 실패 52(표 검색이 완벽해진다 치고) +
표 안 실패 201 × .337. dev 카테고리 비율을 test 에 적용한 것이다.
애매한 29건이 **전부** 유리하게 뒤집혀도 dev .902 / test .873.

**의미 기반으로 재면 상한이 오를 것이라던 예상은 틀렸다.** 문자열로 "단서 없음"이던
것 상당수가 실은 **질문이 오답 칸을 가리키는** 경우였다. 상한은 내려갔다.

독립 확인: 오라클 표 게이팅 @1 = **.7178** (test, `results/p0_confirm/`). 표 검색을
100% 완벽히 해도 셀 R@1 은 거기까지다.

## 판정

**R@1 .90 은 검색으로 도달 불가능하다.** 현실적 최대치 test ≈ .83 이고 그것도
표 검색 100% + 고칠 수 있는 것 전부 완벽히 고친 가정이다. 표 안 실패의 **66%가
원리적으로 못 푸는 것**이다 — 질문이 오답을 가리키거나(.633), 두 셀 문장이 동일(.030).

**이것은 setEM@10 을 주지표로 삼은 결정을 사후에 정당화한다.** "왜 R@1 로 안 재냐"에
"질문의 절반 이상이 단일 셀을 특정하지 않으며 이를 실측했다"고 답할 수 있다.
지금까지 그 근거가 없었다.

### 판정 — 실패는 셀이 뭉개져서가 아니라 **질의가 오답 쪽에 가까워서**다

**인코더는 두 셀을 잘 구별한다.** cos(정답,1등) .825 는 같은 표 무작위 쌍 .454 보다
훨씬 높지만 1.0 과는 멀다. 사실상 구별 불가(cos>.99)는 **4.2%(7건)** 뿐이다.

**질의가 오답 셀을 명확히 선호한다.** 차이 중앙 **+.047**, 접전(<.005)은 **10.8%** 뿐.
동전 던지기가 아니라 **실제 선호**다.

→ 위 본문의 "**질문이 오답 쪽만 지목** 105건(63.3%)"과 **같은 이야기이며,
헤더 경로 차집합과 임베딩이라는 서로 다른 두 계측이 일치한다.** colsig 판정의
독립 확인으로 쓸 수 있다.

🚫 **문자열 겹침으로 기전을 주장하지 말 것.** 전체 문장 자카드 .825 는 **템플릿과 표
제목** 때문에 부풀려져 있다 — 둘 다 같은 표의 두 셀이 **무조건** 공유한다. 내용만 보면
.500 이다. 2026-09-03 에 .825 를 근거로 "bi-encoder 가 구별 정보를 평균에 묻는다"고
적었다가 **위 코사인 측정에 반증됐다.** 그 문장은 철회한다.

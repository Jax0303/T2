# 예상 질문과 답변: 비교군은 왜 줄었나

## 질문 1. 예전에는 비교군이 7~8개였는데 왜 4개로 줄었나?

**답: 개수를 줄인 것이 아니라 "원래 논문의 방법 그대로인 비교군"만 남겼습니다.**

예전 비교군 대부분은 다른 논문의 색인 형식만 옮겨 온 변형이었습니다. 원 논문의 검색 단계, LLM 호출, 프로그램 실행은 빠져 있었습니다. 이런 비교는 "허수아비와 비교했다"는 지적을 받을 수 있습니다. 그래서 지도교수님이 정한 기준으로 다시 골랐습니다.

선정 기준(2026-09-28 지도교수 지시):
1. 계층형 표가 들어 있는 문서에서 근거를 검색해 답하는 **같은 문제**를 푸는가
2. **공개 코드**가 있는가
3. 계층형 표 벤치마크에서 평가할 수 있는가
4. 8GB GPU 한 장, 학습 없이, 외부 API 없이 **재현할 수 있는가** (논문 제목의 "폐쇄된 환경" 조건)

예전 비교군에서 빠진 것과 이유:

| 예전 비교군 | 처리 | 이유 |
|---|---|---|
| 고정 청크 (머리글 반복) | LangChain 튜토리얼 청크로 교체 | 특정 논문이 없는 자체 변형이었음. 가장 널리 쓰이는 공식 튜토리얼 설정으로 대체 |
| TableRAG(Yu) 청킹 이식 | Yu 원방법으로 교체 | 청크 형식만 옮기고 질의 분해·재정렬·SQL 단계가 빠져 있었음 |
| TableRAG(Chen) 셀 검색 이식 | Chen 원방법으로 교체 | 셀 문서 형식만 옮기고 질의 확장·프로그램 실행 단계가 빠져 있었음 |
| 행·열 단위 (RowCol) | 제외 | TAP4LLM·Chen 논문의 기본선일 뿐 RAG 방법이 아님 |
| 무작위 행 (RandRow) | 삭제 | 지도교수님 지시. 표 샘플링 기법이며 RAG 방법이 아님 |
| 표 단위 | 제외 | 외부 방법이 아니라 검색 단위 크기를 바꾼 자체 변형. 상한 비교는 "표 전체 입력" 참고 조건이 대신함 |
| MT2Net | 제외 | 지도교수님 지시. 학습이 필요한 모델이라 무학습 조건과 맞지 않음. 관련 연구에서 인용만 |

남은 4개는 RAG 방법의 서로 다른 네 계열을 하나씩 대표합니다.

| 계열 | 비교군 | 출처 |
|---|---|---|
| 기본 청크 RAG | LangChain 공식 튜토리얼 | 가장 널리 쓰이는 표준 구성 |
| 계층적 요약 RAG | RAPTOR | ICLR 2024 |
| 스키마·셀 검색 + 코드 실행 | TableRAG (Chen) | NeurIPS 2024 |
| 청크 검색 + SQL 실행 | TableRAG (Yu) | EMNLP 2025 |

여기에 **머리글 경로 제거 실험**을 더해 "무엇이 효과를 내는가"를 직접 보였습니다. **표 전체 입력**은 검색 없이 모든 표를 넣는 참고 조건으로 두었습니다.

## 질문 2. 더 최근이거나 더 가까운 방법은 왜 비교하지 않았나?

**답: 조사했지만 네 기준을 모두 만족하면서 로컬에서 돌릴 수 있는 방법이 없었습니다.** 2026년 기준 후보 조사 결과는 다음과 같습니다.

| 후보 | 제외 이유 |
|---|---|
| FT-RAG (2026) | 문제 정의가 가장 가깝지만 공개 코드·모델이 없어 재현 불가 |
| Mixture-of-RAG (KDD 2026) | 여러 문서 가운데 문서를 찾는 문제. 질문의 문서가 주어지는 본 논문의 설정과 다름 |
| TabRAG (2025) | PDF 페이지 이미지를 입력으로 받는 방법. 텍스트 표가 아님 |
| MoCA-Agent (2026) | 검색 없는 에이전트 방식, 27B 모델 필요 |
| Fortune (2025) | 강화학습으로 학습해야 함 |
| GRAB (2026) | 그래프 인코더 학습 필요 |
| TAT-LLM (2024) | 미세조정 필요, 검색 없음 |
| GraphOTTER (2024) | 표 하나만 다루고 72B 모델 필요 |

## 질문 3. RAPTOR·Chen·Yu는 왜 200문항만 평가했나?

**답: 문항 하나에 LLM을 여러 번 부르는 방법이라 882문항 전체는 시간상 불가능했고, 축소는 결과를 보기 전에 정해 두었습니다.**

- **실행 시간:** Yu는 문항당 LLM을 평균 6.7번 부르고, 실측으로 문항당 약 1~2.5분이 걸립니다. 882문항이면 Yu 하나에만 13~37시간이 걸립니다. Chen은 최대 5번의 코드 실행 반복, RAPTOR는 문서마다 요약 트리 생성이 필요합니다.
- **사전등록:** 200문항으로 줄이는 결정은 세 방법의 결과가 나오기 전에 기록했습니다(커밋 5149534).
- **선정 방식:** 200문항은 882문항의 고정된 순서에서 앞 200개입니다. 문항을 고를 재량이 없었습니다. 네 그룹이 모두 들어 있습니다: 산술·셀 2개 이상 70, 조회·셀 2개 이상 67, 조회·셀 1개 49, 산술·셀 1개 14.
- **같은 문항 비교:** 본 방법, LangChain, 표 전체 입력도 같은 200문항으로 잘라 함께 비교합니다. 모든 비교가 같은 문항끼리 짝지은 McNemar 검정입니다.
- **대표성:** 882문항 결과가 있는 방법은 200문항에서도 비슷합니다. 본 방법 46.3% 대 46.5%, LangChain 33.8% 대 30.0%입니다.
- **검정력:** 200문항에서도 지금까지 결과가 나온 비교군과의 차이는 모두 통계적으로 유의했습니다. TableRAG(Yu)와 Chen 512토큰 재실행은 결과가 나오면 추가합니다. 문항이 적어서 차이를 놓쳤다는 우려는 해당하지 않습니다.

## 질문 4. 재현율에서는 청크 방법이 더 높은데?

**답: 재현율@k의 k는 "검색 단위의 개수"라서, 단위가 큰 방법일수록 높게 나옵니다.**

- **단위 크기:** LangChain 청크 하나에는 셀이 평균 37.5개, Yu 청크에는 30.6개가 들어 있습니다. 본 방법은 1개입니다.
- **문서 전체가 들어감:** 문서 하나가 청크 4~5개로 나뉘므로, 청크 방법은 상위 5개만 가져와도 문서 전체를 가져옵니다.
- **정밀도:** 그래서 정밀도@5 이상에서는 본 방법이 모든 방법 가운데 가장 높습니다.
- **답변 정확도:** LangChain 청크는 882문항 중 98.3%에서 정답 셀을 모두 넣고도, 답변 정확도가 33.8%로 본 방법의 46.3%보다 12.5%p 낮았습니다.
- **효과의 증명:** 셀 문장의 효과는 같은 조건에서 머리글 경로만 뺀 실험으로 따로 증명했습니다. 이 실험에서 검색 성공이 89.6%에서 13.3%로, 답변이 46.3%에서 16.2%로 떨어졌습니다.

## 질문 5. Chen은 왜 그렇게 낮나? 구현이 잘못된 것 아닌가?

**답: 우리 구현의 결함이 아니라, 공식 코드의 호출당 128토큰 상한이 Qwen3-8B의 코드를 중간에서 자른 것이 주원인이었습니다. 그래서 상한을 512토큰으로 올려 다시 실행했습니다.**

- **원인:** 코드 실행 오류 360건 중 343건이 코드가 줄 중간에서 잘린 경우였습니다. 200문항 중 127문항이 영향을 받았습니다.
- **배경:** 원 논문은 짧게 답하는 GPT-3.5·GPT-4를 썼기 때문에 128토큰으로 충분했습니다.
- **재실행:** 512토큰 재실행은 사전등록한 뒤 돌렸습니다(커밋 5f0f771). 본문에는 512 결과를 싣고, 원래 설정인 128 결과는 부록에 함께 싣습니다.

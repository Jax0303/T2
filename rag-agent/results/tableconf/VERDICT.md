## 2. 원인 — 제목 충돌 (title collision)

셀 문장은 `In the table '<제목>', among <행경로>, the value of <열경로> is <값>.` 이다.
제목이 문장의 첫 자리를 차지한다.

**dev 코퍼스 424개 표 중 179개(42.2%)가 다른 표와 제목이 완전히 같다.**

| 제목 | 그 제목을 쓰는 표 수 |
|---|---:|
| career statistics | **61** |
| statistics | 34 |
| club | 27 |
| regular season | 10 |
| singles | 8 |

| gold 표 제목 | n | **표 오인율** |
|---|---:|---:|
| **겹침** | 75 | **.4533** |
| **고유** | 755 | **.0980** |

**Fisher exact p = 2.1e-13.** 4.6배 차이. 질의의 9%(75건)가 표 오인 실패의
31.5%(34/108)를 만든다.

- 표 오인 108건 중 **뽑힌 표의 제목이 정답 표와 글자까지 동일한 것이 13건(12.0%).**
- 제목이 겹치는 표 179개 중 **176개가 ToTTo(위키피디아) 출신**이다. 통계 보고서 표는
  214개 중 211개가 고유 제목이다. **HiTab이 두 출처를 섞은 결과다.**

## 3. 구분 정보는 있다 — 제목이 아니라 헤더에 있다

"career statistics" 표 61개의 헤더 라벨을 쌍별로 비교하면 **자카드 겹침 중앙 0.178**이다.
즉 헤더의 82%가 서로 다르다.

```
105_totto12493-3  헤더: ... fitzroy united alexander ... south melbourne hellas ...
112_totto13192-1  헤더: ... leek town ... port vale ... sacramento republic ...
```

**구단명이 헤더에 있다.** 제목만 같을 뿐 표는 충분히 구분된다.

**기전: 판별력 없는 제목이 문장의 첫 자리에서 임베딩을 지배하고, 판별력 있는 헤더가
문장 뒤로 밀린다.** 61개 표의 셀 문장이 전부 `In the table 'career statistics', ...`로
시작한다.

## 4. 이 저장소에 이미 같은 논리의 선례가 있다

`rag_agent/serialization/templates.py`의 STRUCTURAL_COMPACT는 **제목이 비었을 때**
프레임을 버리고 S2 경로 문자열로 떨어진다. 주석의 논거:

> 프레임은 제목을 문장에 앉히려고 존재한다. 제목이 없으면 **아무것도 주장하지 않으면서
> 토큰만 쓴다.**

**제목이 61개 표에 공유될 때 같은 논거가 그대로 성립한다** — 판별에 관해 아무것도
주장하지 않으면서 토큰을 쓰고, 게다가 61개 표를 서로 닮게 만든다. 빈 제목보다 나쁘다.
기존 선례는 `title == ""`만 보고 `title이 고유한가`는 보지 않는다.

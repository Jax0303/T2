## 읽는 법

1. **셀+범위가 셀만을 이기는 구간은 좁다.** 12개 (모집단 × 인코더) 중 예산 50셀에서만 두 곳이 이긴다 —
   산술 dev p1 .8263 대 .7964, 다중 dev 1.0000 대 .9355. 예산 20셀 이하에서는 전부 진다.
   범위 문장 하나가 8~12셀을 쓰기 때문에 작은 예산에서는 정답 하나를 넣는 자리를 범위가 먹는다.
2. **표 통째는 셀 예산으로 맞추면 무너진다.** 산술 test 에서 예산 10셀 .0000, 200셀에서도 .7278.
   `results/baselines/BOARD.md` 가 표 단위를 .96~.99 로 적은 것은 **청크 수**로 셌기 때문이고,
   같은 실행의 다른 축이다. 두 수치를 같은 문장에 쓰려면 어느 축인지 반드시 밝힐 것.
3. **p2(범위 라벨로 학습)가 p1 보다 낮다 — 단, 교란이 있다.** p2 는 기성품 베이스에서 범위 쌍 3,998행으로
   학습했고 p1 은 같은 베이스에서 셀 쌍 5,970행으로 학습했다. p2 의 **셀만** arm 이 p1 의 셀만 arm 보다
   낮으므로(산술 dev .5928 대 .6407) 차이는 범위 단위가 아니라 **학습 데이터가 줄고 바뀐 것**이다.
   범위 단위 자체의 효과는 인코더를 고정한 p1 행에서 읽어야 하고, 거기서도 기각이다.

## 살아남는 것

- 넘긴 셀 수로 맞춘 비교 축 자체 (`@B cells`). 표 단위 검색의 우위가 청크 수 축의 산물임을 보인다.
- 수식에서 범위 라벨을 유도하는 절차(`analysis/scope_bench.py: min_cover`) — 학습 쌍 3,998행 중 810행이
  범위 positive 였다. 재사용 가능하나 **이 형태로는 검색을 개선하지 않는다.**

## 단서

- 범위 단위는 행/열/조상그룹 네 종류뿐이다. 임의의 셀 부분집합(예: 여러 표에 걸친 피연산자)은 못 만든다.
- 다중 셀 모집단은 n=31/29 라 방향만 본다.
- p2 는 `max_seq_length=512` 로 학습했다(범위 문장이 길어서). p1 은 기본값이다.

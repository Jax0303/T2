# 슬라이드 출처·채점 감사 — 2026-09-12

현재 판단: 기존 두 슬라이드는 그대로 방어할 수 없다. MultiHiertt 추가 성능 실험은 보류한다.

## 출처 오류

- RowCol 검색 .5146은 `t_rowcol_values`, EM .2866은 `t_row_values`에서 나온다. 서로 다른 실행이다. 후자의 검색은 .7134이며, 전자의 EM은 .2735다. 전자는 과거 문맥 전달 결함이 있어 단순히 EM 숫자만 바꿔 발표해서도 안 된다.
- 본 방법의 과거 원본 EM은 710/991=.7164다. 슬라이드 .7225는 716/991에 해당하지만 출처를 확인하지 못했다.
- `고정 크기 1000byte 청킹 (LangChain 기본값)`은 `행 보존·헤더 반복 Markdown 청킹 1,000자 (자체 구현)`으로 정정해야 한다.
- `MT2NET Linearization`은 `MT2Net에서 착안한 계층 헤더 셀 문장`, `TableRAG`는 `Huawei에서 착안한 청킹`으로 표기한다. 전체 원본 시스템 재현이 아니다.
- 수정된 최신 RowCol은 `행·열 교집합 Markdown (leaf 헤더, HiTab 적응)`이다.

## 동일 기준의 자동 채점 감사

과거 6개 실행과 최신 3개 실행의 991건씩을 같은 채점기로 재채점하고 ID·정답·검색 판정 일치를 검사했다. 모두 저장된 정오 판정과 일치했다. 이것은 채점 코드 적용의 일관성 확인이며 사람의 의미 판정과 동등하다는 보증이 아니다. 과거 문맥 전달의 무결성을 새로 인증한 것도 아니다.

`audit.json`에 원본 파일 경로·해시 및 검색/답변 2×2 교차표를 저장했다.

## 방법별 차이의 진단

차이 = 검색 성공·답변 오답 비율 − 검색 실패·답변 정답 비율.
방법마다 검색 성공 집합과 전달 문맥이 다르므로 이 차이가 같아야 할 이유는 없다. 다만 그 설명만으로 실제 결함을 배제할 수는 없다.

최신 3개 표현이 모두 검색에 성공한 동일 403문항에서, 고정된 기존 예측을 재집계했다:

| 표현 | 검색 | 답변 정답 | EM |
|---|---:|---:|---:|
| S3c | 1.0000 | 327/403 | .8114 |
| RowCol 적응 | 1.0000 | 269/403 | .6675 |
| Huawei 문자 청킹 적응 | 1.0000 | 323/403 | .8015 |

질문 집합을 맞춰도 RowCol 차이가 남는다. 검색 성공률 차이만으로 설명되지 않으며 문맥 표현·헤더 정보·후보 수 등 전달 조건의 영향과 양립한다. 특정 요인의 인과효과를 입증한 실험은 아니다. 403건 결과는 사후 진단이며 991건 주지표를 대체하지 않는다.

## 사람 판정 절차 — 아직 미실시

`blind_review.jsonl`은 9개 실행의 질문·예측 쌍을 중복 제거한 4,287항목이다. 정답으로 자동 채점된 예측도 포함한다. 방법 이름과 자동 정오 판정을 숨겼고, 매핑은 `review_key.jsonl`에 분리했다. 이 파일들은 사람 채점 결과가 아니라 검토용 양식이다.

권장 공통 판정 기준:

1. 질문과 원표를 기준으로 답의 값·단위·방향을 확인한다. 명백한 단위 표기만 다른 답은 의미 정답 후보로 기록한다.
2. 여러 상충 후보 중 정답 하나를 포함했다는 이유만으로 정답 처리하지 않는다.
3. 반올림·백분율 변환·약칭·주석 차이는 근거와 적용 규칙을 명시한다. 모든 방법에 같은 기준을 적용한다.
4. 데이터 정답 자체의 문제와 모델 답변 문제를 구분한다. 해결되지 않은 것은 보류한다.
5. 가능하면 독립된 두 검토자가 판정하고 불일치를 조정한다. 기존 EM과 사람 판정 정확도를 별도로 보고한다.

완료 조건: 슬라이드 출처 수정, 비교군 재현 범위 명시, 사람 판정 기록 완료, 남는 RowCol 차이의 문맥 근거 검토. 현재 사람 판정과 원인 분해는 미완료이며 `.7225` 달성을 주장하지 않는다. test 답변을 본 후 규칙을 만든 감사는 사후 분석으로 표기하고 성능 개선의 독립 검증으로 제시하지 않는다.

## `orcK` 가 무엇인가

검색 top-K 안에 gold 셀이 **전부** 들어왔으면 **gold 만** 주입하고, 아니면 1위를 준다.
**재정렬기는 검색이 못 찾은 셀을 만들어낼 수 없다**는 제약을 지키므로 재정렬의 상한이다.

🚫 **`orc` 는 오라클이다. "우리가 .87 을 냈다"로 쓰면 안 된다.** 실제 재정렬기는
이만큼 못 한다. 성립하는 문장은 **"여기에 +.15 가 놓여 있다"** 뿐이다.

## 판정

**1. 재정렬이 이 저장소가 만진 어떤 레버보다 크다.**
`top10` → `orc10` 이 **+.1494** (149:25). 검색을 한 글자도 안 바꾸고, **이미 top10 안에
들어와 있는 셀 중 하나를 고르는 것만으로** 나온다. 같은 표의 p0 재학습 이득은
**+.0301** — **약 5배 차이**다.

**2. 검색은 이미 답을 갖고 있다.** `orc50` .8904 가 리더 천장 `gold` .9024 와 11건
차이다(p=.0064). 후보를 50 까지 늘리고 완벽히 고르면 **읽기 천장에 거의 닿는다.**

**3. 재정렬은 더 정확하면서 더 싸다.** `orc10` 108토큰 대 `top10` 631토큰. **6배 적다.**

**4. 페이지 제목은 읽기를 안 바꿨다.** `gold` 조건 p0 대 a0 가 1:2 (p=1.00). p0 개입이
**순수 검색 개입**임이 확인된다. 이 줄은 다른 arm 비교의 산술 통제로 재사용할 수 있다.

**5. distractor 비용의 직접 측정.** `EM|주입됨` 열을 세로로 읽으면, 정답 셀이
프롬프트에 있는 조건에서 셀 1개면 .9158~.9196, 10개면 **.7564** 다. **정답이 들어 있어도
옆에 9개가 더 있으면 −.16.**

## 무결성

- **결정성 검증**: gold 가 top10 안인 784건에서 `gold` 와 `orc10` 은 프롬프트가 글자
  단위로 같다. 예측도 **784/784 일치, 0 불일치**. 디코딩이 결정적이므로 이 레그의
  모든 짝지음이 유효하다.
- **검색 재현**: dry-run 의 `top1 gold hit 597/830 = 0.7193` 이
  `results/p0_confirm/` 의 R@1 과 소수점까지 같다. 이 스크립트의 검색 경로가
  `cell_rank_dump.py` 와 같은 값을 낸다.
- 자체 점검(`--dry-run`)에 `orc` 분기 assert 추가: gold 전부 주입 여부가
  `max(gold_ranks) < K` 와 동치여야 한다. 4,150 job 통과.

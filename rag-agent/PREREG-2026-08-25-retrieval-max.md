# 사전 등록 — 검색을 최대로 올리면 답변 EM은 얼마나 따라오나

작성 2026-08-25. **EM을 한 건도 보기 전에 커밋한다.**

## 왜 이 실험인가

2026-08-25에 셀 검색의 실패 유형을 갈랐다. **주소 충돌이 아니었다** — gold 셀의 주소가
코퍼스 58,759개 중 유일한데도 1등은 47%뿐이고 중앙 순위가 **2등**이다. 충돌하는 gold
셀은 830건 중 87건뿐이고, 전부 고쳐도 recall@10은 +2.2점이다.

실제 실패는 **형제 셀과 1~2등을 못 가르는 것**이다(`2013` 대 `2012`). 그래서 어휘
정확일치(BM25)와 미세조정이 둘 다 겨냥할 수 있는 문제다.

## 이미 측정한 것 (LLM 없음, `results/` 에 커밋됨)

`results/retriever_sweep.json`, `results/alpha_sweep_prefix.json`,
`results/query_prefix_test.json`, `results/cell_rank_curve.json`

| HiTab dev n=830, S3c, 512 | recall@1 | recall@30 | **OSC@512** |
|---|---|---|---|
| bm25 단독 | .370 | .787 | .727 |
| **dense (현재 논문 설정)** | .446 | .860 | **.789** |
| **hybrid α=.7** | **.516** | **.889** | **.837** |
| hybrid α=.6 | .527 | .880 | .837 |

**BM25 단독은 dense보다 나쁜데 섞으면 둘 다 이긴다** — dense가 동네를 찾고 BM25가
정확일치로 형제를 가른다는 진단과 맞는다.

**BGE 쿼리 접두어는 효과가 0이다** (dense OSC .789 → .784, hybrid .837 → .835).
`encoders.py`가 "맨몸 인코딩은 silent misuse"라고 적어둔 것이 이 과제에는 해당하지
않는다. **접두어는 쓰지 않는다. 이것도 측정된 0으로 기록한다.**

**검색의 절대 한계**: dense가 5,000개를 뽑아도 gold 셀의 **1.3%는 안 나온다.**
OSC=1.0은 이 인코더로 원리상 불가능하다.

## 전환 실패 전과 — 예측을 여기에 맞춘다

이 저장소에서 **OSC를 올린 개입 4건이 전부 EM으로 넘어가지 않았다**:
예산 512→1024 (+.06 OSC / ±.00 EM), `group` (+.02~.05 / 0), `capped` (오름 / 악화),
**hybrid (ΔOSC +5.5점 / ΔEM +1.0점)**.

**hybrid의 실측 전환율은 약 18%다.** 이번 ΔOSC가 +4.8점이므로 순진한 곱셈(+4.8 × .756)
이 주는 +3.6점이 아니라 **+1점 근처**를 예측해야 한다. 이유도 예측한다: 검색이 새로
건지는 질의는 원래 순위가 낮았던 것들이고, **읽기도 더 어려울 가능성이 높다.**

## 예측

### M1 (주) — hybrid의 EM 전환

**HiTab dev 512, S3c: hybrid α=.7 − dense = +.005 ~ +.030, McNemar p > .05.**

근거: 실측 전환율 18% × ΔOSC 4.8점 ≈ +0.9점. 구간 상단은 전환율이 2배로 좋을 경우.
**유의하지 않을 것으로 예측한다.**

### M2 — 미세조정 후 검색

**recall@1 +.08 ~ +.20, OSC@512 +.03 ~ +.08** (hybrid α=.7 기준선 대비).

근거: hard negative가 **같은 표의 형제 셀**이라 측정된 실패 유형을 정면으로 겨냥한다.
학습 3,667건은 작지만 과제가 좁다. recall@30은 천장(@100 = .930)에 가까워
**+.01 ~ +.04**로 더 작게 예측한다.

### M3 — 미세조정의 EM 전환

**+.01 ~ +.05, p > .05.** M1과 같은 논리다. 검색 이득의 대부분이 순위 1~2등 구간에서
나오는데, 그 질의들은 이미 OSC=1이라 EM에 새로 기여하지 않는다.

### M4 (안전 점검) — 우리 우위가 검색을 바꿔도 살아남나

**hybrid α=.7에서 S3c − MT2Net ≥ +.05 이고 p < .01.**

위험은 실재한다: 2026-08-20에 hybrid가 MultiHiertt에서 표 덤프 대비 우리 유의성을
날렸다(p=.0029 → .1524). **베이스라인이 우리보다 더 오르면 검색 수치를 얻고 논문을
잃는다.** 차이가 +.05 미만으로 좁혀지면 **논문 설정은 dense로 유지한다.**

### M5 (통제) — 같은 검색 설정 안에서만 비교한다

**같은 α의 두 런에서 `flat` arm 불일치 ≤ 5건, p 유의하지 않음.**

⚠️ `flat`은 검색 설정이 바뀌면 **당연히 달라진다.** dense 런과 hybrid 런 사이에서
0:0을 기대하지 않는다. arm 간 짝지음은 **같은 α 안에서만** 유효하다.

### M6 (통제) — 미세조정에 누출이 없다

train/dev/test는 질의도 표도 공유하지 않는다(2,519 / 540 / 538, 교집합 전부 0).
학습은 `populations/hitab_train_lookup_all.txt` (n=3,667)에서만 나온다.
`models/bge-cell-ft/train_meta.json`에 기록한다.

## 판정 규칙 — 결과를 보기 전에 정한다

| M1·M3 (EM 전환) | 결론 | 논문 |
|---|---|---|
| **+.05 이상, 유의** | 전환 실패 전과가 깨졌다. 검색 개선이 이 과제에서 값을 한다 | 새 설정을 주 설정으로. **예측 실패로 적는다** |
| **+.01 ~ +.05** | 예측대로. 검색은 오르고 EM은 조금 따라온다 | 검색 개선은 **부차 결과**로 싣고, 논문의 축은 색인 단위로 유지 |
| **≤ +.01 또는 음** | 전환 실패 5·6번째 사례 | **§검색 지표로 고르면 틀린다(기여 D)의 증거를 하나 더 얻는다** |

**M4가 깨지면(차이 < +.05) M1이 어떻게 나오든 논문 설정은 dense로 유지한다.**
검색 수치를 위해 논문의 대조를 팔지 않는다.
